`demo_sprite.cpp` renders a little night scene: the background is drawn once, afterwards only the sprites touch the
screen. Every sprite stores the background below its pixels and restores it when it moves, overlapping sprites respect
their z-order.

![Sprite demo](/vic/media/demo_sprite.gif)

## Background once

The background is drawn with a plain drawing context before the sprites are rendered. A gradient shader colors the
sky, anti aliasing smooths the moon and the hills:

```cpp
#include "dc.h"
#include "tc.h"
#include "sprite.h"
#include "shader/base.h"
#include "shader/gradient.h"

void render_background(vic::drv& head)
{
  vic::dc _dc(head);
  _dc.anti_aliasing_enable(true);
  _dc.present_lock();

  // sky: vertical gradient from deep blue to a warm horizon
  vic::shader::gradient_vertical<3> sky = { { 0,   0, vic::color::argb(0x10U, 0x10U, 0x40U) },
                                            { 0, 100, vic::color::argb(0x50U, 0x30U, 0x70U) },
                                            { 0, 159, vic::color::argb(0xE0U, 0x70U, 0x30U) } };
  _dc.shader_register(&sky);
  _dc.set_color(vic::color::white);   // the gradient takes the color of its points, only the pen alpha is used
  _dc.box({ 0, 0, 320, 160 });
  _dc.shader_remove(&sky);

  // moon: a bright disc, then a sky colored disc punched into it
  _dc.set_color(vic::color::argb(0xFFU, 0xF0U, 0xC0U));
  _dc.disc({ 262, 38 }, 16U);
  _dc.shader_register(&sky);
  _dc.disc({ 269, 33 }, 14U);
  _dc.shader_remove(&sky);

  // ground
  _dc.set_color(vic::color::argb(0x20U, 0x50U, 0x20U));
  _dc.box({ 0, 160, 320, 200 });

  _dc.present_lock(false);
}
```

## Sprites and z-order

```cpp
#include "sprite_sheets/bina.h"    // demo sheets, generated by demo/sprite_sheets/gen_sheets.py
#include "sprite_sheets/coin.h"
#include "sprite_sheets/ghost.h"

// the z-index defines what is in front: ghosts (30, 31) > ball (15) > bina (10) > coins (5)
static vic::sprite::sheet<32, 48>         bina  (head, &sprite_sheet_bina,  10);
static vic::sprite::canvas_sheet<320>     coin  (head, &sprite_sheet_coin,   5);
static vic::sprite::canvas_sheet<576>     ghost0(head, &sprite_sheet_ghost, 30);
static vic::sprite::canvas_sheet<576>     ghost1(head, &sprite_sheet_ghost, 31);
static vic::sprite::canvas<256, 1>        ball  (head, 15);
```

- `sheet<Frame_Width, Frame_Height>` renders frames straight out of a sprite sheet (`sheet_info_type`). It is the
  cheapest sprite, but it can't be rotated or recolored.
- `canvas_sheet<Pixel>` loads the sheet frame into a canvas, so it can be rotated and shaders apply. `Pixel` needs
  some headroom over `sprite_width * sprite_height` for rotated frames.
- `canvas<Pixel, Frames>` is a sprite you draw on with all drawing context functions.
- Bigger z-index is in front. Sprites with the same z-index are placed behind the existing ones.

## Canvas sprite

The beach ball is drawn once into a canvas with disc sectors, its origin is the ball center:

```cpp
ball.anti_aliasing_enable(true);                              // the canvas keeps its own pixels, so AA always works
ball.set_color(vic::color::argb(0xE0U, 0x30U, 0x30U));
ball.disc_sector({ 0, 0 }, 7U, 0U);
ball.disc_sector({ 0, 0 }, 7U, 2U);
ball.set_color(vic::color::argb(0xF0U, 0xF0U, 0xF0U));
ball.disc_sector({ 0, 0 }, 7U, 1U);
ball.disc_sector({ 0, 0 }, 7U, 3U);
ball.set_color(vic::color::argb(0x60U, 0x10U, 0x10U));
ball.circle({ 0, 0 }, 7U);
ball.set_color(vic::color::argb(0xFFU, 0xFFU, 0xFFU, 0xA0U));  // translucent highlight, alpha blended on render
ball.disc({ -3, -3 }, 1U);
```

## Animation and rotation

Every frame each sprite is rendered at its new position. `render()` restores the background of the old position and
draws the new one:

```cpp
std::int16_t bina_x = 20, ball_x = 100, ball_y = 60, ball_dx = 1, ball_angle = 0;   // moved by the demo logic

for (std::uint32_t t = 0U; ; ++t) {
  // bina walks: frame = row * 4 + column, row 2 walks right
  bina.render({ bina_x, 112 }, static_cast<std::uint16_t>(2U * 4U + (t / 6U) % 4U));

  // the coin spins through its 8 frames and rotates around the frame center
  coin.render({ 60, 130 }, static_cast<std::uint16_t>((t / 3U) % 8U), static_cast<std::int16_t>((t * 4U) % 360U));

  // the ball rolls: rotation around the canvas origin, then render
  ball_angle = static_cast<std::int16_t>((ball_angle + ball_dx * 8 + 360) % 360);
  ball.set_rotation(ball_angle, { 0, 0 });
  ball.render({ ball_x, ball_y });

  vic::io::delay(40U);
}
```

- `canvas_sheet::render(position, frame, angle)` rotates around the center of the sheet frame,
  `canvas::set_rotation(angle, center)` around a center in canvas coordinates. The angle is in degree, clockwise on
  screen. The pattern itself is not modified.
- Rendering an invalid frame (`0xFFFF`) hides a sprite and restores its background. The demo ends its one shot burst
  animations this way: `burst.render(pos, 0xFFFFU);`

## Collision detection

The ghosts are semi transparent and turn red while they overlap. A collision handler enables the pixel exact collision
detection of a sprite:

```cpp
struct ghost_state {
  vic::sprite::base* other_ghost;   // the ghost we are looking for
  bool               hit;           // collided in the last render
};

// called by render() once for every other sprite which shares a pixel with this one
void on_ghost_collision(vic::sprite::base& self, vic::sprite::base& other, void* arg)
{
  (void)self;
  ghost_state& state = *static_cast<ghost_state*>(arg);
  if (&other == state.other_ghost) {   // the ghosts touch bina and the ball too, only the other ghost counts
    state.hit = true;
  }
}

static ghost_state ghost_st[2] = { { &ghost1, false }, { &ghost0, false } };
ghost0.set_collision_handler(on_ghost_collision, &ghost_st[0]);
ghost1.set_collision_handler(on_ghost_collision, &ghost_st[1]);

// render a ghost red if it collided in its last render
vic::shader::tint red(vic::color::red, 200U);   // shader/base.h
if (ghost_st[0].hit) {
  ghost_st[0].hit = false;
  ghost0.shader_register(&red);
  ghost0.render(pos0, frame);
  ghost0.shader_remove(&red);
}
else {
  ghost0.render(pos0, frame);
}
```

- Only the rendered sprite reports: when A is rendered and overlaps B, the handler of A is called with `other = B`.
- The handler may change colors, frames or its own state, it must not destroy sprites or render the reporting sprite.
  That is why the demo only sets a flag and tints the ghost at its next render.
- Without a handler the detection is off and costs nothing. `get_collision()` is the polling alternative.

See [Sprites](/vic/reference/sprite/) for the reference.
