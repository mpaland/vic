Head for the four color e-paper controller JD79667 (up to 200 x 384, e.g. 2.66" 184 x 360, 2.9" 168 x 384 and
1.54" 200 x 200 panels), black / white / yellow / red. The head renders into a RAM framebuffer (2 bit per pixel,
bits 7:6 = left pixel). `present()` uploads it and starts a full refresh with the waveform from the MTP of the
panel, which takes 12 .. 25 s.

```cpp
#include "head/JD79667.h"
```

## Template parameters

```cpp
template<std::uint16_t Screen_Size_X = 200U, std::uint16_t Screen_Size_Y = 384U,
         drv::orientation_type Orientation = drv::orientation_0,
         std::uint16_t Refresh_Delay = 25000U>
class JD79667;
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `Screen_Size_X` | `std::uint16_t` | 200 | logical width; the physical panel is sources (max. 200, multiple of 4) x gates (max. 384) |
| `Screen_Size_Y` | `std::uint16_t` | 384 | logical height, must match the orientation |
| `Orientation` | `drv::orientation_type` | `orientation_0` | orientation, done in software; landscape is e.g. 384 x 200 with `orientation_90` or `270` |
| `Refresh_Delay` | `std::uint16_t` | 25000 | delay in ms used instead of the BUSY poll after a refresh when the I/O layer can't read the BUSY_N pin |

The physical panel must be at most 200 x 384 and its width a multiple of 4 (`static_assert`).

## Constructor


| Parameter | Type | Meaning |
|---|---|---|
| `device_handle` | `io::handle_type` | logical device handle of the SPI bus |

## Color format

| Drawing color | Pixel | Code |
|---|---|---|
| clearly red (R >= 128, G < 96, B < 96) | red | 11 |
| clearly yellow (R >= 128, G >= 128, B < 96) | yellow | 10 |
| other dark colors (luminance below 128) | black | 00 |
| light colors and `color::none` | white paper | 01 |

`pixel_get()` returns `color::black`, `color::white`, `color::yellow` or `color::red`.

## Interface

| Call | Option | Meaning |
|---|---|---|
| `io::write()` | 0 | command byte (D/C low) |
| `io::write()` | 1 | parameters and frame data (D/C high), the whole frame in one call |
| `io::read()` | 2 | one byte, bit 0 = 1 while the controller is busy |

The BUSY_N pin of the controller is active low: return the inverted pin level in bit 0. The head polls it every
10 ms after the reset, power on, refresh and power off. An I/O layer without BUSY read returns `false`, the head
then waits 200 ms after reset and power on / off and `Refresh_Delay` ms after a refresh. The hardware reset
(RST_N low) is part of `io::init()`.

## Orientation

All eight orientations, mapped in software into the framebuffer. The controller stays at scan up / shift right.

## Native hooks and read back

`pixel_set()`, `pixel_get()`, `cls()` and `present()`, all other primitives use the `drv` fallbacks on the RAM buffer.
`pixel_get()` reads the framebuffer.

:::caution
The drawing context calls `present()` after every primitive, and every `present()` of a changed framebuffer is a
full refresh of 12 .. 25 s. Always draw a screen inside `dc.present_lock()` / `dc.present_lock(false)`.
`present()` is skipped when nothing changed since the last refresh.
:::

## Head specific functions

| Function | Meaning |
|---|---|
| `framebuffer()` | pointer to the framebuffer (row organized, physical orientation, 2 bit per pixel) |

## Init sequence

The datasheet has no init sequence. `init()` sends the sequence that the GxEPD2, Waveshare and Adafruit drivers
share: `io::init()` (hardware reset), 10 ms, BUSY, `4Dh 78h`, panel setting `00h 0Fh 29h`, power setting
`01h 07h 00h`, `03h 10h 54h 44h`, booster soft start `06h 05h 00h 3Fh 0Ah 25h 12h 1Ah`, VCOM and data interval
`50h 37h` (white border), `60h 02h 02h`, resolution `61h`, `E7h 1Ch`, power saving `E3h 22h`, `B4h D0h`, `B5h 03h`,
`E9h 01h`, PLL `30h 08h`, power on `04h` and BUSY, clear to white. The registers 03h, 4Dh, 60h, B4h, B5h, E7h and
E9h are not described in the datasheet. The panel is not refreshed by `init()`, call `present()` after drawing.
`present()` writes the frame with 10h, starts the refresh with `12h 00h` and waits for BUSY. `shutdown()` sends
power off `02h 00h`, waits for BUSY and enters deep sleep with `07h A5h`; a hardware reset (`io::init()`) wakes the
controller up.

:::note
The head is checked against the datasheet, the reference drivers and with the I/O trace, it has not been run on a
panel yet.
:::

## Example

From `demo/heads/JD79667.cpp` (200 x 384 panel in landscape):

```cpp
#include "head/JD79667.h"
#include "dc.h"
#include "tc.h"
#include "font/LCD_6x8.h"

static vic::head::JD79667<384, 200, vic::drv::orientation_90> epd(reinterpret_cast<vic::io::handle_type>(0));

int main()
{
  epd.init();

  // black frame, three discs and text on white paper, one refresh at the end
  vic::dc d(epd);
  d.present_lock();
  d.cls();                                  // white
  d.set_color(vic::color::black);
  d.rectangle({ 0, 0, 384, 200 });
  d.rectangle({ 4, 4, 380, 196 });
  d.disc({ 70, 80 }, 40U);
  d.set_color(vic::color::red);
  d.disc({ 190, 80 }, 40U);
  d.set_color(vic::color::yellow);
  d.disc({ 310, 80 }, 40U);
  d.set_color(vic::color::black);
  vic::tc t(d);
  vic::font::LCD_6x8 lcd_6x8;
  t.set_font(lcd_6x8);
  t.set_pos({ 130, 160 });
  t.out(reinterpret_cast<const std::uint8_t*>("vic four color e-paper"));
  d.present_lock(false);                    // upload and refresh

  epd.shutdown();                           // power off and deep sleep
  return 0;
}
```

## Controller notes

[JD79667.md](https://github.com/mpaland/vic/blob/master/src/head/doc/JD79667.md): 200 sources x 384 gates, 2 bit
per pixel frame memory (19200 bytes), 4-wire SPI or 3-wire 9 bit SPI, BUSY_N output low while the controller works.
The waveform LUT and the default register settings come from the MTP of the panel. Commands: panel setting 00h,
power setting 01h, power off 02h, power on 04h, booster 06h, deep sleep 07h, data 10h, refresh 12h, PLL 30h,
border and data polarity 50h, resolution 61h, partial window 83h. The summary has the crosscheck of the init
sequence against the datasheet and a comparison of the reference drivers.
