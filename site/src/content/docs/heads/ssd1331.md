Head for the SSD1331 96 x 64 RGB OLED controller with 65k colors. The head writes directly into the GDDRAM (no
framebuffer): pixels are streamed through the column / row address window with native auto increment, the
orientation is done with the remap bits. The graphic acceleration commands (GAC) are used for clear, filled boxes
and move (copy).

```cpp
#include "head/SSD1331.h"
```

## Template parameters

```cpp
template<std::uint16_t Screen_Size_X = 96U, std::uint16_t Screen_Size_Y = 64U,
         drv::orientation_type Orientation = drv::orientation_0,
         SSD1331_interface_type Interface_Mode = SSD1331_SPI,
         bool RGB_to_BGR = false,
         bool Use_GAC = true,
         std::uint8_t GAC_Delay = 0U>
class SSD1331;
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `Screen_Size_X` | `std::uint16_t` | 96 | logical width, 96 for `orientation_0` / `180`, 64 for `90` / `270` |
| `Screen_Size_Y` | `std::uint16_t` | 64 | logical height |
| `Orientation` | `drv::orientation_type` | `orientation_0` | hardware orientation (remap bits) |
| `Interface_Mode` | `SSD1331_interface_type` | `SSD1331_SPI` | `SSD1331_SPI` (4-wire, write only), `SSD1331_PAR8` (8 bit 6800 / 8080), `SSD1331_PAR16` (16 bit, one pixel per word); the parallel buses can read back |
| `RGB_to_BGR` | `bool` | false | swap the R and B segments (remap bit A[2]), panel dependent |
| `Use_GAC` | `bool` | true | use the graphic acceleration commands for `cls()`, `box()` and `move()` |
| `GAC_Delay` | `std::uint8_t` | 0 | delay in ms after every GAC command, 0 = none |

## Color format and interface

RGB565 big endian (65k format 1, `color::color_to_RGB565()`), red in the MSB. If red and blue are swapped on a
module, set `RGB_to_BGR`.

| Call | Option | Meaning |
|---|---|---|
| `io::write()` | 0 | command sequence (D/C# low), including the GAC commands |
| `io::write()` | 1 | pixel data (D/C# high), in blocks of 32 pixels |
| `io::read()` | 1 | two bytes of one pixel on the parallel buses, the I/O layer does the dummy read |

The head emits 8 bit bytes for all interfaces, a 16 bit bus I/O layer packs two data bytes into one word (first byte
= D15..D8). SPI mode 3, about 6 MHz in the demo.

## Orientation

All eight orientations with the remap register A0h: A[0] vertical address increment for the rotated orientations,
A[1] column remap (X mirror), A[4] COM scan remap (Y mirror); 65k format and COM split are always set.
`orientation_0` is the datasheet default (no remap), the common 0.96" modules are upright with `orientation_180`
(Adafruit remap 72h, 76h with color swap is `orientation_180` with `RGB_to_BGR`).

## Native hooks and read back

| Hook | Implementation |
|---|---|
| `pixel_set()` | sets the window only if the tracked write pointer is not already at the pixel |
| `line_horz()` | one window and a pixel stream |
| `line_vert()` | a one column wide window |
| `box()` | GAC draw rectangle (22h) with fill, without GAC window and stream |
| `move()` | GAC copy (23h), clipped to the screen; without GAC the `drv` fallback, which needs read back |
| `blit()` | window over the clipped block, the pixels are streamed |
| `cls()` | GAC clear window (25h) for black, filled rectangle for other colors; without GAC one stream |

`pixel_get()` returns `color::none` on SPI (no read back on the serial interface), on the parallel buses it reads
the pixel. With `color::none` alpha blending and anti aliasing use the background color of the drawing context; put
the [`framebuffer`](/vic/heads/framebuffer/) head in front if the real pixels are needed, see
[Write only displays](/vic/design/write-only-displays/).

:::caution
The controller executes a GAC command asynchronously and has no busy flag, the datasheet gives no execution time.
If artifacts appear on fast buses, set `GAC_Delay` or disable the GAC.
:::

## Head specific functions

| Function | Meaning |
|---|---|
| `display_enable(bool)` | AFh / AEh (sleep mode, RAM retained) |
| `display_brightness(level)` | master current 87h, level / 16 |
| `display_contrast(level)` | scales the contrasts of the three colors, the color balance 91h / 50h / 7Dh is kept |
| `display_inverse(bool)` | A7h / A4h, the RAM content is not changed |

## Init sequence

The Adafruit_SSD1331 values: unlock, display off, remap from the orientation, start line and offset 0, normal
display, MUX, external VCC (ADh 8Eh), power save off, phase period, clock, second precharge speeds, precharge level,
VCOMH, master current, the three contrasts, fill mode (on with GAC), scroll off, display on, then clear.
`shutdown()` switches the display off; VCC may be removed afterwards.

## Example

From `demo/heads/SSD1331.cpp` (0.96" SPI module):

```cpp
#include "head/SSD1331.h"
#include "scene.h"          // demo_scene(): frame, line, circle, disc and text

static vic::head::SSD1331<96, 64, vic::drv::orientation_180> oled(reinterpret_cast<vic::io::handle_type>(0));

int main()
{
  oled.init();
  demo_scene(oled);
  // the graphic accelerator: move the scene 10 pixels to the right (copy command)
  vic::dc d(oled);
  d.move({ 0, 0, 86, 64 }, { 10, 0 });
  oled.display_brightness(255U);
  return 0;
}
```

`demo/heads/framebuffer.cpp` puts a [`framebuffer`](/vic/heads/framebuffer/) head in front of this display for
anti aliasing.

## Controller notes

[SSD1331.md](https://github.com/mpaland/vic/blob/master/src/head/doc/SSD1331.md): 96 x 64 x 16 bit GDDRAM, 8 / 9 / 16
bit 6800 / 8080 or write only SPI (BS[3:0]). Window 15h (columns) / 75h (rows), data are written without a write RAM
command. Contrast per color 81h..83h, master current 87h. Remap A0h: A[0] vertical increment, A[1] column remap,
A[2] segment order (BGR), A[3] COM left / right swap, A[4] COM scan remap, A[5] COM split, A[7:6] color format. The
known 96 x 64 modules use COM split. Acceleration: draw line 21h, draw rectangle 22h (outline and fill color, fill
mode 26h), copy 23h, dim window 24h, clear window 25h, scrolling 27h / 2Eh / 2Fh.
