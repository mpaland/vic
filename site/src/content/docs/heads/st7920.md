Head for the ST7920 controller of the 128 x 64 graphic LCD modules (12864B) in graphic mode. The GDRAM is written in
16 bit words; the 64 rows of a 128 x 64 panel are two halves of 32 rows side by side in the RAM. The head renders into
a row organized framebuffer (bit 7 = left pixel) and sends it with `present()`.

```cpp
#include "head/ST7920.h"
```

## Template parameters and constructor

```cpp
template<std::uint16_t Screen_Size_X = 128U, std::uint16_t Screen_Size_Y = 64U,
         drv::orientation_type Orientation = drv::orientation_0>
class ST7920;

ST7920(io::handle_type device_handle);
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `Screen_Size_X` | `std::uint16_t` | 128 | logical width, 128 for `orientation_0` / `180`, 64 for `90` / `270` |
| `Screen_Size_Y` | `std::uint16_t` | 64 | logical height |
| `Orientation` | `drv::orientation_type` | `orientation_0` | orientation, done in software |
| `device_handle` | `io::handle_type` | | logical device handle of the bus |

The physical width must be a multiple of 16 and the two halves of a row must fit into 16 GDRAM words
(`static_assert`).

## Color format and interface

1 bit per pixel, any color which is not black sets the pixel (`color::color_to_L1()`).

| Call | Option | Meaning |
|---|---|---|
| `io::write()` | 0 | instruction (RS = 0) |
| `io::write()` | 1 | data (RS = 1) |

On the serial interface (PSB low) the I/O layer sends every byte as the sync byte F8h / FAh followed by the high and
the low nibble in the upper four bits of two bytes. Every byte needs 72 µs, the I/O layer has to pace the transfers
or poll the busy flag; the head only waits after power on (50 ms), the first function set (1 ms) and the clear
(2 ms). The head never reads.

## Orientation

All eight orientations, mapped in software into the framebuffer. The 128 x 64 modules are upright with
`orientation_0`.

## Native hooks and read back

`pixel_set()`, `pixel_get()`, `cls()` and `present()`, all other primitives use the `drv` fallbacks on the RAM buffer.
`pixel_get()` reads the framebuffer. `present()` writes 32 vertical addresses with `80h + y, 80h`, 16 bytes of row y
and 16 bytes of row y + 32 (1024 bytes for 128 x 64): collect a frame with `dc.present_lock()`.

## Head specific functions

| Function | Meaning |
|---|---|
| `framebuffer()` | pointer to the row organized framebuffer (physical orientation) |
| `display_enable(bool)` | toggles the graphic display bit (36h / 34h), the GDRAM is retained |

## Init sequence

The datasheet init flow (also used by u8g2): 50 ms, function set 30h twice, display on 0Ch, clear 01h (2 ms), entry
mode 06h, extended instruction set 34h, graphic display on 36h, then clear and present. `shutdown()` leaves the
graphic mode (34h, 30h) and switches the display off (08h).

## Example

From `demo/heads/ST7920.cpp` (128 x 64 module on the serial interface):

```cpp
#include "head/ST7920.h"
#include "scene.h"          // demo_scene(): frame, line, circle, disc and text

static vic::head::ST7920<128, 64> lcd(reinterpret_cast<vic::io::handle_type>(0));

int main()
{
  lcd.init();
  demo_scene(lcd);
  return 0;
}
```

## Controller notes

[ST7920.md](https://github.com/mpaland/vic/blob/master/src/head/doc/ST7920.md): 32 common x 64 segment driver with
segment extenders, DDRAM for text with a Chinese font ROM, CGRAM and a 64 x 256 bit GDRAM for graphics. 8 / 4 bit
parallel (PSB = 1) or write only clock synchronized serial (PSB = 0: CS, SID, SCLK). 72 µs per instruction, clear
1.6 ms. Basic instructions (RE = 0): clear, home, entry mode, display control, function set 20h with DL / RE / G.
Extended instructions (RE = 1): GDRAM address 80h + vertical address, then 80h + horizontal word. RE must not change
together with DL or G, which is why the head enters and leaves the graphic mode in two steps. There are no segment or
common direction bits, every orientation is done in software.
