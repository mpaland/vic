Head for the PCD8544, the controller of the Nokia 5110 / 3310 displays. The RAM is organized in 6 banks of 8
vertical pixels (bit 0 = top row). The head renders into a 504 byte RAM framebuffer and sends it with `present()` in
horizontal addressing mode as one block. The controller can't be read back.

```cpp
#include "head/PCD8544.h"
```

## Template parameters

```cpp
template<std::uint16_t Screen_Size_X = 84U, std::uint16_t Screen_Size_Y = 48U,
         drv::orientation_type Orientation = drv::orientation_0,
         std::uint8_t Vop  = 0x38U,
         std::uint8_t Bias = 0x04U>
class PCD8544;
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `Screen_Size_X` | `std::uint16_t` | 84 | logical width, 84 for `orientation_0` / `180`, 48 for `90` / `270` |
| `Screen_Size_Y` | `std::uint16_t` | 48 | logical height |
| `Orientation` | `drv::orientation_type` | `orientation_0` | orientation, done in software |
| `Vop` | `std::uint8_t` | 38h | operation voltage (contrast) 0..127, VLCD = 3.06 V + Vop x 0.06 V |
| `Bias` | `std::uint8_t` | 4 | bias system 0..7, 4 as in Adafruit_PCD8544 (the datasheet table says 3 for 1:48) |

## Constructor

```cpp
PCD8544(io::handle_type device_handle);
```

| Parameter | Type | Meaning |
|---|---|---|
| `device_handle` | `io::handle_type` | logical device handle of the SPI bus |

## Color format and interface

1 bit per pixel, any color which is not black sets the pixel (`color::color_to_L1()`).

| Call | Option | Meaning |
|---|---|---|
| `io::write()` | 0 | command bytes (D/C low) |
| `io::write()` | 1 | display data, `present()` sends the 504 bytes in one call |

SPI mode 0, max. 4 MHz. The head never reads; driving RES is left to `io::init()` / the board.

## Orientation

All eight orientations, mapped in software into the physical 84 x 48 framebuffer. The `m` orientations mirror the
panel top / bottom after the rotation. The Nokia 5110 modules are upright with `orientation_0`.

## Native hooks and read back

`pixel_set()`, `pixel_get()`, `cls()` and `present()`; all other primitives use the `drv` fallbacks on the RAM
buffer. `pixel_get()` reads the framebuffer, so it always works. `present()` sends the whole buffer: collect the
primitives of a frame with `dc.present_lock()`.

## Head specific functions

| Function | Meaning |
|---|---|
| `framebuffer()` | pointer to the bank organized framebuffer (physical orientation) |
| `display_enable(bool)` | display control normal / blank, the RAM is retained |
| `display_contrast(level)` | sets Vop = level / 2 |
| `display_inverse(bool)` | inverse video |

:::caution
`display_contrast()` levels above about 180 exceed the 8.5 V limit of the internal generator, levels 0 / 1 give
Vop = 0, which switches the charge pump off. Tune `Vop` and `Bias` together.
:::

## Init sequence

`io::init()`, then the Adafruit_PCD8544 sequence: 21h (extended instruction set), 80h + Vop, 04h (temperature
coefficient 0), 10h + Bias, 20h (basic instruction set), 0Ch (normal display), clear and present. `shutdown()` sends
08h (blank) and 24h (power down).

## Example

From `demo/heads/PCD8544.cpp`:

```cpp
#include "head/PCD8544.h"
#include "scene.h"          // demo_scene(): frame, line, circle, disc and text

static vic::head::PCD8544<84, 48> lcd(reinterpret_cast<vic::io::handle_type>(0));

int main()
{
  lcd.init();
  demo_scene(lcd);          // drawn with present_lock(), one transfer
  lcd.display_contrast(0x70U);
  return 0;
}
```

## Controller notes

[PCD8544.md](https://github.com/mpaland/vic/blob/master/src/head/doc/PCD8544.md): 84 x 48 pixel, 504 byte write only
display RAM in 6 banks, serial interface only (SCE, D/C, SDIN, SCLK, MSB first, up to 4 Mbit/s). The function set
20h carries PD (power down), V (vertical addressing) and H (extended instruction set). Basic set (H = 0): display
control 08h / 0Ch / 09h / 0Dh (blank, normal, all on, inverse), Y address 40h + bank, X address 80h + column.
Extended set (H = 1): temperature coefficient 04h, bias 10h, Vop 80h. There are no mirror, rotation or start line
bits, every orientation is done in software. After RES the chip is in power down with Vop = 0, the RAM is not cleared.
