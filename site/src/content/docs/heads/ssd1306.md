Head for the monochrome OLED controllers SSD1306, SSD1309 and SH1106 (128 x 64 and 128 x 32 modules). The controller
RAM is organized in pages of 8 vertical pixels. With the (default) framebuffer the pixels are rendered in RAM and the
whole buffer is sent with `present()`, which is the fastest option on a serial bus.

```cpp
#include "head/SSD1306.h"
```

## Template parameters

```cpp
template<std::uint16_t Screen_Size_X = 128U, std::uint16_t Screen_Size_Y = 64U,
         drv::orientation_type Orientation = drv::orientation_0,
         SSD1306_interface_type Interface_Mode = SSD1306_I2C,
         bool Framebuffer = true,
         bool Charge_Pump = true,
         SSD1306_controller_type Controller = SSD1306_CTRL_SSD1306,
         std::uint8_t Column_Offset = (Controller == SSD1306_CTRL_SH1106) ? 2U : 0U>
class SSD1306;
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `Screen_Size_X` | `std::uint16_t` | 128 | screen width in pixel |
| `Screen_Size_Y` | `std::uint16_t` | 64 | screen height in pixel, 64 or 32 typical, must be a multiple of 8 |
| `Orientation` | `drv::orientation_type` | `orientation_0` | `orientation_0`, `0m`, `180` or `180m` |
| `Interface_Mode` | `SSD1306_interface_type` | `SSD1306_I2C` | `SSD1306_SPI3`, `SSD1306_SPI4`, `SSD1306_I2C`, `SSD1306_MEM` (8 bit parallel) |
| `Framebuffer` | `bool` | true | render into a RAM framebuffer which is sent with `present()` (recommended) |
| `Charge_Pump` | `bool` | true | enable the internal charge pump (SSD1306 8Dh 14h, SH1106 ADh 8Bh), false for an external VCC; the SSD1309 has none |
| `Controller` | `SSD1306_controller_type` | `SSD1306_CTRL_SSD1306` | `SSD1306_CTRL_SSD1306`, `SSD1306_CTRL_SSD1309` or `SSD1306_CTRL_SH1106` |
| `Column_Offset` | `std::uint8_t` | 2 for the SH1106, else 0 | first RAM column of the panel: 2 for 128 pixel SH1106 panels, 32 for 64 x 48 SSD1306 panels |

## Constructor

```cpp
SSD1306(io::handle_type device_handle);
```

| Parameter | Type | Meaning |
|---|---|---|
| `device_handle` | `io::handle_type` | logical device handle, e.g. the I²C address 3Ch |

## Color format

1 bit per pixel, any color which is not black switches the pixel on (`color::color_to_L1()`), also for the
background color of `cls()`.

## Interface

| Call | Option | Meaning |
|---|---|---|
| `io::write()` | 0 | command sequence |
| `io::write()` | 1 | data sequence (GDDRAM bytes) |
| `io::read()` | 1 | one GDDRAM byte, only used without framebuffer |

The head emits plain 8 bit bytes for all interfaces. In I²C mode the control byte (00h commands, 40h data) is the
first byte of every block, so one `io::write()` is one I²C transfer. In 3-wire SPI mode the I/O layer builds the
9 bit frames from the option and the byte. Command and SH1106 page sequences are sent in blocks of up to 32 bytes; the
framebuffer of the SSD1306 / SSD1309 goes out in one `io::write()` (I²C: control byte and data in one block).

## Orientation

`orientation_0`, `orientation_0m`, `orientation_180`, `orientation_180m`, set with the segment remap (A0h / A1h) and
the COM scan direction (C0h / C8h). 90 and 270 degree would need a rotated framebuffer and are not supported. The
reference drivers (Adafruit_SSD1306, u8g2) use A1h / C8h as their rotation 0, which is `orientation_180` here; most
modules are upright with it.

## Native hooks and read back

`pixel_set()`, `pixel_get()`, `cls()` and `present()`; the other primitives use the `drv` fallbacks on the RAM
buffer. With the framebuffer `pixel_get()` reads the RAM copy, so alpha blending and anti aliasing work against the
real pixels (on / off). `present()` sends the whole buffer: collect a frame with `dc.present_lock()`.

:::caution
Without framebuffer (`Framebuffer = false`) every pixel is a read-modify-write of one page byte on the display. The
GDDRAM can only be read on the parallel bus (`SSD1306_MEM`), the I/O layer has to do the dummy read. On SPI and I²C
use the framebuffer.
:::

## Head specific functions

| Function | Meaning |
|---|---|
| `framebuffer()` | pointer to the page organized framebuffer, `Screen_Size_Y / 8 * Screen_Size_X` bytes |
| `display_enable(bool)` | AFh / AEh |
| `display_contrast(level)` | 81h level |

## Init sequence

`AEh, A8h N-1, D3h 00h, 40h, A0h/A1h, C0h/C8h, DAh 12h (02h for 32 lines), 81h 7Fh, A4h, A6h, D5h 80h`, the charge
pump (`8Dh 14h` on the SSD1306, `ADh 8Bh` / `ADh 8Ah` on the SH1106), `D9h 22h, DBh 30h`, horizontal addressing
`20h 00h` (not on the SH1106), `AFh`, then clear and present. `shutdown()` switches the display off.

## Example

From `demo/heads/SSD1306.cpp` (0.96" SSD1306 and 1.3" SH1106 I²C modules):

```cpp
#include "head/SSD1306.h"
#include "scene.h"          // demo_scene(): frame, line, circle, disc and text

static vic::head::SSD1306<128, 64, vic::drv::orientation_180> oled(reinterpret_cast<vic::io::handle_type>(0x3C));
static vic::head::SSD1306<128, 64, vic::drv::orientation_180, vic::head::SSD1306_I2C, true, true,
                          vic::head::SSD1306_CTRL_SH1106> oled_sh1106(reinterpret_cast<vic::io::handle_type>(0x3C));

int main()
{
  oled.init();
  demo_scene(oled);
  oled.display_contrast(0x40U);

  oled_sh1106.init();       // page addressing, column offset 2
  demo_scene(oled_sh1106);
  return 0;
}
```

## Controller notes

[SSD1306.md](https://github.com/mpaland/vic/blob/master/src/head/doc/SSD1306.md): 128 x 64 bit GDDRAM in 8 pages of
8 rows, interfaces selected with BS[2:0] (4-wire SPI, 3-wire SPI, I²C, 6800, 8080). Addressing modes with 20h, the
column / page window 21h / 22h. Hardware configuration: start line 40h, segment remap A0h / A1h, MUX A8h, COM scan
C0h / C8h, display offset D3h, COM pins DAh. Timing: clock D5h, precharge D9h, VCOMH DBh, charge pump 8Dh. Only two
mirror bits, no 90 degree rotation. The SSD1309 is an SSD1306 with external VCC only (no 8Dh).

[SH1106.md](https://github.com/mpaland/vic/blob/master/src/head/doc/SH1106.md): the controller of most 1.3" modules,
132 x 64 RAM. It is command compatible with the SSD1306 except: no addressing modes and windows (20h / 21h / 22h),
only page addressing (`B0h | page`, `00h | low nibble`, `10h | high nibble`); 128 pixel panels sit at RAM columns
2..129; the charge pump is `ADh 8Bh` / `ADh 8Ah`. SSD1306 code on an SH1106 shows the image shifted by two columns,
so the head addresses and sends every page separately with the column offset.
