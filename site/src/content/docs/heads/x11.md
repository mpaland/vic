The `x11` head emulates a graphic display in an X11 window on Linux (and any other X11 system, Wayland desktops run
it with XWayland). It is the Linux counterpart of the [`windows`](/vic/heads/windows/) head: develop the application
on the PC and run the vic demos. The only dependency is Xlib, link with `-lX11` (CMake: `X11::X11`). The head needs
only `io::delay()` from the I/O layer.

```cpp
#include "head/X11.h"
```

## Template parameters and constructor

```cpp
template<std::uint16_t Screen_Size_X, std::uint16_t Screen_Size_Y,
         std::uint16_t Viewport_Size_X = Screen_Size_X, std::uint16_t Viewport_Size_Y = Screen_Size_Y>
class x11;

x11(std::uint16_t viewport_x = 0U, std::uint16_t viewport_y = 0U,
    std::int16_t  window_x   = 0,  std::int16_t  window_y   = 0,
    std::uint8_t  zoom_x     = 1U, std::uint8_t  zoom_y     = 1U,
    const char*   caption    = "vic screen");
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `Screen_Size_X` | `std::uint16_t` | | screen (buffer) width |
| `Screen_Size_Y` | `std::uint16_t` | | screen (buffer) height |
| `Viewport_Size_X` | `std::uint16_t` | `Screen_Size_X` | viewport (window) width |
| `Viewport_Size_Y` | `std::uint16_t` | `Screen_Size_Y` | viewport (window) height |
| `viewport_x` | `std::uint16_t` | 0 | viewport x position (left) on the screen |
| `viewport_y` | `std::uint16_t` | 0 | viewport y position (top) on the screen |
| `window_x` | `std::int16_t` | 0 | window x position on the desktop |
| `window_y` | `std::int16_t` | 0 | window y position on the desktop |
| `zoom_x` | `std::uint8_t` | 1 | x zoom factor |
| `zoom_y` | `std::uint8_t` | 1 | y zoom factor |
| `caption` | `const char*` | `"vic screen"` | window caption, must be valid until `init()` is called |

The head owns the window and the frame buffer, it can't be copied.

## How it works

- `init()` opens the display connection, creates a fixed size window (viewport size times zoom) at the given
  position, waits until it is visible and wraps the frame buffer into an `XImage`. Without a display (`DISPLAY` not
  set) or without a 24 bit true color visual it prints an error and the head stays inactive.
- The pixels are kept in a zoomed 32 bit 0RGB frame buffer (`color::color_to_RGB888()`), `pixel_set()` writes
  `zoom_x * zoom_y` buffer pixels. `pixel_get()` reads the frame buffer, so alpha blending and anti aliasing work.
- `present()` services the window events and copies the viewport part of the frame buffer to the window with
  `XPutImage()`. `viewport_set()` scrolls the window over a larger screen. Closing the window ends the program
  (`std::exit(0)`).
- `shutdown()` destroys the image, the window and the connection.
- No orientation, the native hooks are the `drv` fallbacks.

## The demo main.cpp

`demo/linux/main.cpp` provides the head, the I/O layer and `main()` for the graphic demos (`demo/demo_*.cpp`):

```cpp
#include <time.h>
#include "head/X11.h"

// create a single head: 320 x 200 pixel window with zoom factor 2
vic::drv& get_singlehead()
{
  static vic::head::x11<320, 200> _head( 0, 0, 0, 0, 2U, 2U );
  return _head;
}

// the only io function the emulation needs
void vic::io::delay(std::uint32_t time_to_delay)
{
  struct timespec ts;
  ts.tv_sec  = static_cast<time_t>(time_to_delay / 1000U);
  ts.tv_nsec = static_cast<long>(time_to_delay % 1000U) * 1000000L;
  ::nanosleep(&ts, nullptr);
}

extern void demo(void);

int main()
{
  demo();
  vic::io::delay(100000U);
  return 0;
}
```

The demos need the Xlib headers (`sudo apt install libx11-dev`) and are built with `-DVIC_BUILD_DEMOS=ON`, every demo
is a target `vic_<demo>` linked with `linux/main.cpp` and `X11::X11`, see
[Installation](/vic/getting-started/installation/).
