Head for the ILI9325 TFT controller with a 240 x 320 x 18 bit GRAM. The head writes directly into the GRAM (no
framebuffer); the GRAM window and the address counter direction (entry mode) are set up so that every orientation is
rendered with native auto increment.

```cpp
#include "head/ILI9325.h"
```

## Template parameters

```cpp
template<std::uint16_t Screen_Size_X = 240U, std::uint16_t Screen_Size_Y = 320U,
         drv::orientation_type Orientation = drv::orientation_0,
         std::uint8_t Interface_Mode = 0U,
         bool Color_256k = false,
         bool RGB_to_BGR = false>
class ILI9325;
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `Screen_Size_X` | `std::uint16_t` | 240 | logical screen width, 240 for `orientation_0` / `180` (and mirrored), 320 for `90` / `270` |
| `Screen_Size_Y` | `std::uint16_t` | 320 | logical screen height |
| `Orientation` | `drv::orientation_type` | `orientation_0` | hardware orientation |
| `Interface_Mode` | `std::uint8_t` | 0 | 0: device (SPI) via `io::write()`, 8 / 9 / 16 / 18: memory mapped bus of that width |
| `Color_256k` | `bool` | false | false: 64k colors (RGB565), true: 256k colors (RGB666). The 9 and 18 bit buses are always 256k. Don't use true with SPI, the SPI 18 bit format is not supported |
| `RGB_to_BGR` | `bool` | false | swap R and B (entry mode BGR bit), some displays need that |

## Constructor

```cpp
ILI9325(io::handle_type device_handle, void* mem_reg_addr, void* mem_data_addr, bool spi_id_bit);
```

| Parameter | Type | Meaning |
|---|---|---|
| `device_handle` | `io::handle_type` | device handle for the device (SPI) interface |
| `mem_reg_addr` | `void*` | memory address of the index register (memory interfaces) |
| `mem_data_addr` | `void*` | memory address of the data register (memory interfaces) |
| `spi_id_bit` | `bool` | level of the IM0/ID hardware pin (SPI device ID); the SPI start byte is built by the I/O layer |

## Color format

RGB565 (`color::color_to_RGB565()`) or RGB666 (`color::color_to_RGB666()`) with `Color_256k` or on the 9 / 18 bit
buses. On the 16 bit bus 18 bit pixels are transferred as 2 + 16 bits, on the 8 bit bus as 2 or 3 bytes.

## Interface

| Interface_Mode | Access | Meaning |
|---|---|---|
| 0 | `io::write()` option 0 | index register, two bytes `00h idx` |
| 0 | `io::write()` option 1 | register data (2 bytes) or pixel data (2 or 3 bytes) |
| 0 | `io::read()` option 1 | one GRAM pixel as two bytes (RGB565), the I/O layer handles the dummy bytes |
| 8 | `io::mem::write<std::uint8_t>()` | index and data as bytes on DB17..DB10 |
| 9 | `io::mem::write<std::uint16_t>()` | registers as bytes on DB17..DB10, pixels as 9 + 9 bits |
| 16 | `io::mem::write<std::uint16_t>()` | 16 bit words |
| 18 | `io::mem::write<std::uint32_t>()` | 32 bit access, 18 bit pixels |

In the memory modes `io::init()` only sets up the bus and the reset, all register traffic goes through
`io::mem::write()` / `io::mem::read()` on the two addresses.

## Orientation

All eight orientations. The GRAM is always 240 columns x 320 lines, the head maps the logical coordinates to GRAM
addresses and sets the AM and I/D bits of the entry mode register (R03h) so that a logical row major stream is
written with auto increment:

| Orientation | Logical size | R03h AM, I/D |
|---|---|---|
| `orientation_0` | 240 x 320 | 0, 11 |
| `orientation_0m` | 240 x 320 | 0, 01 |
| `orientation_180` | 240 x 320 | 0, 00 |
| `orientation_180m` | 240 x 320 | 0, 10 |
| `orientation_90` | 320 x 240 | 1, 10 |
| `orientation_90m` | 320 x 240 | 1, 00 |
| `orientation_270` | 320 x 240 | 1, 01 |
| `orientation_270m` | 320 x 240 | 1, 11 |

## Native hooks and read back

| Hook | Implementation |
|---|---|
| `pixel_set()` | sets R20h / R21h only if the address counter is not already at the pixel (tracked along logical x) |
| `line_horz()` | one address setup and a pixel stream |
| `blit()` | GRAM window set to the clipped block, the pixels are streamed, then the full window is restored |
| `cls()` | one stream over the whole GRAM |
| `line_vert()`, `box()`, `move()` | `drv` fallbacks |
| `present()` | nothing, the data is written directly |

`pixel_get()` reads one pixel: RGB565 on the 8 / 16 bit buses and SPI, 18 bit on the 9 / 18 bit buses. In SPI mode
it returns `color::none` if the I/O layer can't read, see [Write only displays](/vic/design/write-only-displays/).

## Head specific functions

| Function | Meaning |
|---|---|
| `display_enable(bool)` | R07h 0133h / 0000h, the GRAM is retained |

## Init sequence

`init()` runs the vendor power on sequence with 200 / 50 / 80 / 20 ms waits, sets the entry mode from the orientation,
frame rate 80 Hz, gamma, the full GRAM window, gate scan, disables the partial images and clears the screen.
`shutdown()` runs the display off sequence and enters the sleep mode, `init()` wakes the controller up again.

## Example

From `demo/heads/ILI9325.cpp` (2.8" module on an 8 bit parallel bus):

```cpp
#include "head/ILI9325.h"
#include "scene.h"          // demo_scene(): frame, line, circle, disc and text

// the two "registers" of the 8 bit bus, on a real target these are the external bus addresses
static std::uint8_t reg_index = 0U;
static std::uint8_t reg_data  = 0U;

static vic::head::ILI9325<240, 320, vic::drv::orientation_0, 8U> tft(reinterpret_cast<vic::io::handle_type>(0), &reg_index, &reg_data, false);

int main()
{
  tft.init();
  demo_scene(tft);
  return 0;
}
```

The SPI variant (`Interface_Mode` 0) uses `io::write()` option 0 = index, 1 = data.

## Controller notes

[ILI9325.md](https://github.com/mpaland/vic/blob/master/src/head/doc/ILI9325.md): 240 RGB x 320 panel, 18 bit GRAM,
16 bit index register and 16 bit registers. Interfaces are selected with IM[3:0] (i80 8 / 9 / 16 / 18 bit, SPI, plus
RGB and VSYNC). The GRAM is accessed through R20h / R21h (address counter), R22h (GRAM data) and the window
R50h..R53h; the address counter wraps inside the window in the direction of R03h AM / I/D. The controller has no
rotation of its own, SS = 1 and GS = 1 (common module wiring) are the base of `orientation_0`. Power on is a
sequence of power control registers R10h..R13h, R29h with waits, display on is R07h in steps up to 0133h; sleep is
SLP in R10h.
