Head for the standard alphanumeric LCD controller (16 x 2, 20 x 4, ...). It is an alpha numeric head
(`is_graphic()` returns `false`) and implements the text functions of `drv`, you write to it with a text context
`vic::tc`. The Sitronix ST7066 (ST7066U), Samsung KS0066U, Epson SED1278 and Sunplus SPLC780 are pin and instruction
compatible and work unchanged.

```cpp
#include "head/HD44780.h"
```

## Template parameters

```cpp
template<std::uint16_t Columns = 16U, std::uint16_t Lines = 2U,
         HD44780_bus_type  Bus  = HD44780_BUS8,
         HD44780_wait_type Wait = HD44780_WAIT_DELAY,
         HD44780_rom_type  Rom  = HD44780_ROM_A00,
         bool Font_5x10 = false,
         std::uint16_t Exec_Us = 43U>
class HD44780;
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `Columns` | `std::uint16_t` | 16 | visible characters per line, max 40 |
| `Lines` | `std::uint16_t` | 2 | 1, 2 or 4 lines (4 line modules are 2 line controllers, line 3 / 4 continue line 1 / 2); `Lines * Columns <= 80` |
| `Bus` | `HD44780_bus_type` | `HD44780_BUS8` | `HD44780_BUS8` (DB7..DB0) or `HD44780_BUS4` (DB7..DB4, two transfers per byte, done by the I/O layer) |
| `Wait` | `HD44780_wait_type` | `HD44780_WAIT_DELAY` | wait strategy after every byte, see below |
| `Rom` | `HD44780_rom_type` | `HD44780_ROM_A00` | character ROM for the UNICODE to character code mapping |
| `Font_5x10` | `bool` | false | 5 x 10 dot font instead of 5 x 8, only with one line |
| `Exec_Us` | `std::uint16_t` | 43 | execution time of a byte in µs, passed to the I/O layer (HD44780 37, ST7066 43, scale by 270 kHz / fOSC for other clocks) |

The limits are checked with `static_assert`.

| `Wait` | Behaviour |
|---|---|
| `HD44780_WAIT_DELAY` | the head calls `io::delay(1)` after every byte (2 ms after clear / home), works with every I/O layer but is slow |
| `HD44780_WAIT_BUSY` | the head polls the busy flag with `io::read()` (up to 1000 polls), falls back to the delay if the I/O layer can't read |
| `HD44780_WAIT_IO` | the I/O layer blocks until the controller accepts the next byte (`Exec_Us` from the option bits or its own busy poll), the head only delays after clear / home |

| `Rom` | Character set |
|---|---|
| `HD44780_ROM_A00` | Japanese standard font: ASCII, half width Katakana at A1h..DFh, some symbols (`ä ö ü ß ° ¥ ÷` and arrows are mapped) |
| `HD44780_ROM_A02` | European standard font: A0h..FFh follow ISO 8859-1 |
| `HD44780_ROM_0B` | ST7066 European font (ROM code 0B): code page 437 Latin letters at 80h..9Ah, symbols, Greek |

Characters 00h..07h are the user defined CGRAM characters, unknown characters are shown as `?`.

## Constructor

```cpp
HD44780(io::handle_type device_handle);
```

| Parameter | Type | Meaning |
|---|---|---|
| `device_handle` | `io::handle_type` | logical device handle of the display interface |

## Interface

Every byte is one `io::write()` call. The low byte of the option selects the register, bits 8..23 carry `Exec_Us`:

| Option bits | Value | Meaning |
|---|---|---|
| 0..7 | 0 | instruction (RS = 0) |
| 0..7 | 1 | data (RS = 1) |
| 0..7 | 2 | instruction, high nibble only: the single nibble transfers of the 4 bit init sequence; an 8 bit I/O layer treats it like 0 |
| 8..23 | `Exec_Us` | execution time in µs, an I/O layer for `HD44780_WAIT_IO` waits `(option >> 8) & 0xFFFF` µs after the transfer, others ignore it |

The I/O layer drives E, R/W and RS and splits the bytes into two nibbles in 4 bit mode, or talks to an I²C port
expander (PCF8574 backpacks). `io::read()` with option 0 returns the busy flag (bit 7) and the address counter, in 4
bit mode the I/O layer assembles the two nibbles.

## Text functions

`cls()` (clear instruction), `text_out()`, `text_set_pos()`, `text_clear_eol()`, `text_clear_sol()`,
`text_clear_line()`. The head tracks the logical cursor (which may be outside the screen) and the address counter
of the controller, the DDRAM address is only sent when the controller is not already at the cursor; characters
outside the screen are skipped. Lines 1 and 2 start at DDRAM 00h and 40h, lines 3 and 4 continue them at
`+ Columns`. Control characters 08h..1Fh are ignored. No orientation, no viewport, no graphics.

## Head specific functions

| Function | Meaning |
|---|---|
| `display_enable(bool)` | display on / off, the DDRAM is retained |
| `cursor_set(bool show, bool blink = false)` | underline cursor and blinking character at the cursor position |
| `char_define(index, pattern)` | define user character 0..7 in the CGRAM: 8 rows of 5 bits (bit 4 is the left dot), row 7 is the cursor line |
| `display_shift(bool right)` | shift the whole display by one character without changing the DDRAM, the logical positions don't follow |
| `display_home()` | undo the display shift, cursor to (0, 0) |

## Init sequence

Initialization by instruction, independent of the internal reset: `io::init()`, 50 ms, three times function set
8 bit (`30h`, single nibbles on the 4 bit bus) with 5 / 1 / 1 ms, on the 4 bit bus one more nibble `20h`, then
function set (bus, lines, font), display off, clear, entry mode increment, display on. `shutdown()` switches the
display off, the DDRAM content is retained.

## Example

From `demo/heads/HD44780.cpp` (16 x 2 module on a 4 bit bus):

```cpp
#include "head/HD44780.h"
#include "tc.h"

static vic::head::HD44780<16, 2, vic::head::HD44780_BUS4, vic::head::HD44780_WAIT_DELAY> lcd(reinterpret_cast<vic::io::handle_type>(0));
// 20 x 4 module on an 8 bit bus with busy flag polling:
//   vic::head::HD44780<20, 4, vic::head::HD44780_BUS8, vic::head::HD44780_WAIT_BUSY> lcd_20x4;

int main()
{
  lcd.init();

  // a user defined character (code 0)
  static const std::uint8_t heart[8] = { 0x00U, 0x0AU, 0x1FU, 0x1FU, 0x0EU, 0x04U, 0x00U, 0x00U };
  lcd.char_define(0U, heart);

  vic::tc t(lcd);
  t.cls();
  t.out({ 0, 0 }, reinterpret_cast<const std::uint8_t*>("vic head demo"));
  t.out({ 0, 1 }, reinterpret_cast<const std::uint8_t*>("Hello World"));
  t.set_pos({ 12, 1 });
  t.out(static_cast<std::uint16_t>(0U));    // the heart
  lcd.cursor_set(true, true);
  return 0;
}
```

## Controller notes

[HD44780.md](https://github.com/mpaland/vic/blob/master/src/head/doc/HD44780.md): 80 byte DDRAM (more than the
visible characters), CGROM with 208 characters of 5 x 8 and 32 of 5 x 10 dots (ROM A00 or A02), 64 byte CGRAM for 8
user characters. Instructions: clear 01h and home 02h (1.52 ms), entry mode 04h, display control 08h (D, C, B),
shift 10h, function set 20h (DL, N, F), CGRAM address 40h, DDRAM address 80h; 37 µs per instruction at 270 kHz. The
busy flag is bit 7 of the instruction read. Function set (bus width, lines, font) can't be changed after the init.

[ST7066.md](https://github.com/mpaland/vic/blob/master/src/head/doc/ST7066.md): same instruction set, but 43 µs per
data write / read, which is why `Exec_Us` defaults to 43. ROM code 0A is the Japanese font (`HD44780_ROM_A00`), ROM
code 0B is a European font of its own (`HD44780_ROM_0B`), not the ISO 8859-1 layout of the HD44780 A02 ROM. There is
no orientation control, the order of segments and commons is fixed by the module wiring.
