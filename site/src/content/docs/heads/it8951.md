Head for the ITE IT8951 e-paper timing controller (Waveshare 6" 800 x 600, 6" HD 1448 x 1072, 9.7" 1200 x 825,
7.8" / 10.3" 1872 x 1404 HATs, M5Paper 960 x 540), 16 gray levels. The controller keeps the image in its own SDRAM,
so the head has **no framebuffer**: pixels, lines, boxes and pixel blocks are loaded directly into the image
buffer of the controller and the head only tracks the changed area. `present()` refreshes that area, with the
default GC16 waveform in about 450 ms.

```cpp
#include "head/IT8951.h"
```

## Template parameters

```cpp
template<std::uint16_t Screen_Size_X = 800U, std::uint16_t Screen_Size_Y = 600U,
         drv::orientation_type Orientation = drv::orientation_0,
         std::uint8_t Mode = 2U,
         std::uint16_t VCOM = 0U,
         std::uint8_t Filter = 0U>
class IT8951;
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `Screen_Size_X` | `std::uint16_t` | 800 | logical width, max. 2047 |
| `Screen_Size_Y` | `std::uint16_t` | 600 | logical height, max. 2047, must match the orientation |
| `Orientation` | `drv::orientation_type` | `orientation_0` | orientation, done in software; portrait is e.g. 600 x 800 with `orientation_90` or `270` |
| `Mode` | `std::uint8_t` | 2 (GC16) | waveform mode of `present()`, see the table below |
| `VCOM` | `std::uint16_t` | 0 | VCOM of the panel as magnitude in mV (2000 = -2.00 V, printed on the panel cable); 0 keeps the value of the controller |
| `Filter` | `std::uint8_t` | 0 | color filter array of the panel: 0 for a gray level panel, 1 .. 12 for a color filter panel, see [color filter panels](#color-filter-panels) |

## Color format

16 gray levels, `color::color_to_L4()`: 0 is black, 15 is white. `color::none` is white paper.

## Color filter panels

Color panels with a color filter array (E Ink Kaleido, 4096 colors) are gray level panels for the controller:
every pixel lies under a red, green or blue filter. With `Filter` 1 .. 12 the head loads for each pixel the upper
4 bits of the color channel of its filter, so 16 levels per channel. A gray has the same level under every filter.

```cpp
// 13.3" 1600 x 1200 color filter panel, GC16, VCOM -2.10 V, filter layout 1
static vic::head::IT8951<1600, 1200, vic::drv::orientation_0, 2, 2100, 1> epd(device);
```

`Filter` selects the layout, given as the filters of the first three pixels of the physical rows 0, 1 and 2. The
pattern repeats after 3 pixels and 3 rows and belongs to the panel, not to the orientation.

| Filter | Row 0 | Row 1 | Row 2 | | Filter | Row 0 | Row 1 | Row 2 |
|---|---|---|---|---|---|---|---|---|
| 1 | R G B | G B R | B R G | | 7 | B G R | G R B | R B G |
| 2 | G B R | B R G | R G B | | 8 | G R B | R B G | B G R |
| 3 | B R G | R G B | G B R | | 9 | R B G | B G R | G R B |
| 4 | R G B | B R G | G B R | | 10 | B G R | R B G | G R B |
| 5 | G B R | R G B | B R G | | 11 | G R B | B G R | R B G |
| 6 | B R G | G B R | R G B | | 12 | R B G | G R B | B G R |

The layout is in the specification of the panel. Without it: a red `cls()` gives a red screen with the right
value, another pure color with the wrong phase or channel order and a gray screen with the wrong direction of the
diagonals (1 .. 3 against 4 .. 6); a green `cls()` then tells 1 .. 6 from 7 .. 12.

`pixel_get()` returns the level of the pixel as gray, which is the level of its own color channel. A single pixel
shows only one channel, so thin colored lines and small colored text lose color; areas and bold shapes work best.
Other filter arrangements, low pass filtering and dithering of images are not part of the head.

## Waveform modes

| Constant | Mode | Time | Use |
|---|---|---|---|
| `MODE_INIT` | 0 | 2 s | full clear to white |
| `MODE_DU` | 1 | 260 ms | black / white only, no flash |
| `MODE_GC16` | 2 | 450 ms | 16 gray levels, best quality |
| `MODE_GL16` | 3 | 450 ms | 16 gray levels, less flash for text on white |
| `MODE_GLR16` | 4 | 450 ms | as GL16 with ghost reduction |
| `MODE_GLD16` | 5 | 450 ms | as GL16 with dithering |
| `MODE_A2` | 6 | 120 ms | black / white only, fast animation |
| `MODE_DU4` | 7 | 290 ms | 4 gray levels |

The numbers depend on the waveform of the panel firmware: on the 6" "M641" firmware A2 is mode 4. INIT and GC16 are
0 and 2 on all known panels.

## Interface

SPI mode 0, max. 24 MHz (12 MHz recommended). Every `io::write()` is one packet, i.e. one CS low period; the head
puts the 16 bit preamble in front of the big endian words.

| Call | Option | Meaning |
|---|---|---|
| `io::write()` | 0 | command packet (`60h 00h` + command word) |
| `io::write()` | 1 | data packet (`00h 00h` + argument, register value or up to 128 pixel words) |
| `io::read()` | 1 | data words: the I/O layer sends the read preamble `10h 00h`, drops the dummy word and reads the big endian words in the same CS low period |
| `io::read()` | 2 | one byte, bit 0 = 1 while the controller is busy (HRDY pin low: return the inverted level) |

The head polls the busy flag before every packet. An I/O layer without HRDY read returns `false`, the head then
sends without waiting: use a slow SPI clock (1 .. 2 MHz) in this case. An I/O layer which can't read data words
still draws and refreshes: there is no device info, `pixel_get()` returns `color::none` and `present()` waits a
fixed time (500 ms, 2 s after `init()`). The hardware reset (RESET_N low for at least 20 ms) is part of `io::init()`.

## Orientation

All eight orientations, mapped in software. The rotation of the controller is not used.

## Native hooks and read back

| Hook | Implementation |
|---|---|
| `pixel_set()` | a load of 1 x 1 pixel: 8 packets |
| `line_horz()`, `line_vert()`, `box()` | one load of the (clipped) area with a constant color |
| `blit()` | one load of the block |
| `cls()` | one load of the whole screen |
| `present()` | display command for the changed area, then waits for the display engine |
| `pixel_get()` | memory read of one word from the image buffer; needs the device info and `io::read()` option 1 |

:::caution
A single pixel is a complete load sequence, so everything which is rendered pixel by pixel (text, circles, anti
aliased shapes) is slow on this controller. Lines, boxes and pixel blocks are one load each.
The drawing context calls `present()` after every primitive, and every `present()` of a changed area is a refresh
of the panel. Always draw a screen inside `dc.present_lock()` / `dc.present_lock(false)`.
:::

## Head specific functions

| Function | Meaning |
|---|---|
| `refresh_mode(mode)` | selects the waveform mode of `present()`, e.g. `MODE_DU` for fast black / white updates |
| `refresh(mode)` | displays the whole screen from the image buffer, e.g. `MODE_GC16` or `MODE_INIT` against ghosting |
| `device_info()` | panel width and height, image buffer address, firmware and LUT version read by `init()`; `valid` is false if the I/O layer can't read |

## Init sequence

`init()` follows the reference drivers (Waveshare, ITE example): `io::init()` (hardware reset), HRDY, system run
`0001h`, device info `0302h` (20 words), packed command parameters `0011h 0004h 0001h`, load address register =
image buffer address, VCOM get / set if `VCOM` is not 0, a load of a white screen and a display of the screen with
the INIT waveform (about 2 s). `shutdown()` sends sleep `0003h`, `init()` wakes the controller up.

:::note
The head is checked against the datasheet, the ITE programming guide, the reference drivers and with the I/O
trace, it has not been run on a panel yet. The pixel read back is derived from the documents only, no reference
driver uses it.
:::

## Example

From `demo/heads/IT8951.cpp` (6" 800 x 600 panel):

```cpp
#include "head/IT8951.h"
#include "dc.h"
#include "tc.h"
#include "font/LCD_6x8.h"

static vic::head::IT8951<800, 600> epd(reinterpret_cast<vic::io::handle_type>(0));

int main()
{
  epd.init();                               // clears the panel to white (INIT waveform, about 2 s)

  // frame, a gray scale of 16 boxes and text, one GC16 refresh of the changed area at the end
  vic::dc d(epd);
  d.present_lock();
  d.set_color(vic::color::black);
  d.rectangle({ 100, 100, 700, 500 });
  for (std::int16_t i = 0; i < 16; ++i) {
    const std::uint8_t g = static_cast<std::uint8_t>(i * 17);
    d.set_color(vic::color::argb(g, g, g));
    d.box({ static_cast<std::int16_t>(144 + i * 32), 200, static_cast<std::int16_t>(176 + i * 32), 300 });
  }
  d.set_color(vic::color::black);
  vic::tc t(d);
  vic::font::LCD_6x8 lcd_6x8;
  t.set_font(lcd_6x8);
  t.set_pos({ 340, 340 });
  t.out(reinterpret_cast<const std::uint8_t*>("vic 16 gray levels"));
  d.present_lock(false);                    // refresh the changed area

  epd.shutdown();                           // sleep
  return 0;
}
```

## Controller notes

[IT8951.md](https://github.com/mpaland/vic/blob/master/src/head/doc/IT8951.md): e-paper timing controller with
built-in SDRAM (1 byte per pixel image buffer), panels up to 2048 x 2048, hosts SPI / I80 / M68 / I2C / USB. On SPI
every packet starts with a preamble word (6000h command, 0000h write data, 1000h read data with one dummy word),
HRDY signals that the controller accepts the next packet. Commands: run 0001h, standby 0002h, sleep 0003h,
register read / write 0010h / 0011h, memory burst 0012h .. 0015h, load image area 0021h, load end 0022h, display
area 0034h, VCOM 0039h, device info 0302h. The summary has the pixel packing, the display modes, the crosscheck
against the documents and reference drivers and the points which are still to be verified on hardware.
