Head for the e-paper controllers SSD1680 and SSD1681 (2.13" 122 x 250, 2.9" 128 x 296, 1.54" 200 x 200 panels),
black / white or black / white / red. The head renders into a RAM framebuffer (1 bit per pixel, 1 = white, bit 7 =
left pixel). `present()` uploads it and starts a full refresh with the waveform from the OTP, which takes 1 .. 4 s.

```cpp
#include "head/SSD1680.h"
```

## Template parameters

```cpp
template<std::uint16_t Screen_Size_X = 122U, std::uint16_t Screen_Size_Y = 250U,
         drv::orientation_type Orientation = drv::orientation_0,
         bool Tri_Color = false,
         bool Source_S8 = (physical width <= 160),
         std::uint16_t Refresh_Delay = 3000U>
class SSD1680;
```

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `Screen_Size_X` | `std::uint16_t` | 122 | logical width; the physical panel is sources (122, 128, 200) x gates (250, 296, 200) |
| `Screen_Size_Y` | `std::uint16_t` | 250 | logical height, must match the orientation |
| `Orientation` | `drv::orientation_type` | `orientation_0` | orientation, done in software; the usual landscape use of the 2.13" panel is 250 x 122 with `orientation_90` or `270` |
| `Tri_Color` | `bool` | false | black / white / red panel, second RAM plane |
| `Source_S8` | `bool` | true if the physical width is 160 or less | display update control 1: use sources S8..S167 (true for the 122 / 128 wide panels, false for 176 / 200 wide); toggle it if the image is shifted by 8 pixels |
| `Refresh_Delay` | `std::uint16_t` | 3000 | delay in ms used instead of the BUSY poll when the I/O layer can't read the BUSY pin |

The physical panel must be at most 200 x 296 (`static_assert`, the union of both chips).

## Constructor

```cpp
SSD1680(io::handle_type device_handle);
```

| Parameter | Type | Meaning |
|---|---|---|
| `device_handle` | `io::handle_type` | logical device handle of the SPI bus |

## Color format

Dark colors (luminance below 128) are ink, light colors and `color::none` are paper (white). On tri color panels
clearly red colors (R >= 128, G < 96, B < 96) go to the red plane. `pixel_get()` returns `color::black`,
`color::white` or `color::red`.

## Interface

| Call | Option | Meaning |
|---|---|---|
| `io::write()` | 0 | command byte (D/C low) |
| `io::write()` | 1 | parameters and RAM data (D/C high), a whole plane in one call |
| `io::read()` | 2 | one byte, bit 0 = level of the BUSY pin |

The head polls BUSY every 10 ms after the software reset and after the refresh. An I/O layer without BUSY read
returns `false`, the head then waits `Refresh_Delay` ms. The hardware reset (RES# low >= 10 µs) is part of
`io::init()`.

## Orientation

All eight orientations, mapped in software into the framebuffer. The controller stays at data entry mode 03h (X and Y
increment).

## Native hooks and read back

`pixel_set()`, `pixel_get()`, `cls()` and `present()`, all other primitives use the `drv` fallbacks on the RAM buffer.
`pixel_get()` reads the framebuffer.

:::caution
The drawing context calls `present()` after every primitive, and every `present()` of a changed framebuffer is a
full refresh of several seconds. Always draw a screen inside `dc.present_lock()` / `dc.present_lock(false)`.
`present()` is skipped when nothing changed since the last refresh.
:::

## Head specific functions

| Function | Meaning |
|---|---|
| `framebuffer()` | pointer to the black / white framebuffer (row organized, physical orientation, 1 = white) |

## Init sequence

`init()` follows the datasheet operation flow with the Adafruit_EPD parameters: `io::init()` (hardware reset), 10 ms,
software reset 12h and BUSY, driver output 01h (gates - 1), data entry 11h 03h, RAM X range 44h, RAM Y range 45h,
border waveform 3Ch 05h, display update control 21h (`Source_S8`), internal temperature sensor 18h 80h, clear to
white. The panel is not refreshed by `init()`, call `present()` after drawing. `present()` sets the RAM counters,
writes 24h (and 26h on tri color panels), then 22h F7h (load temperature, LUT, display) and 20h (master activation),
and waits for BUSY. `shutdown()` enters deep sleep mode 1 (RAM retained), a hardware reset (`io::init()`) wakes the
controller up.

## Example

From `demo/heads/SSD1680.cpp` (2.13" 250 x 122 black / white module in landscape):

```cpp
#include "head/SSD1680.h"
#include "dc.h"
#include "tc.h"
#include "font/LCD_6x8.h"

static vic::head::SSD1680<250, 122, vic::drv::orientation_90> epd(reinterpret_cast<vic::io::handle_type>(0));

int main()
{
  epd.init();

  // black frame and text on white paper, one refresh at the end
  vic::dc d(epd);
  d.present_lock();
  d.cls();                                  // white
  d.set_color(vic::color::black);
  d.rectangle({ 0, 0, 250, 122 });
  d.rectangle({ 4, 4, 246, 118 });
  d.disc({ 60, 61 }, 40U);
  vic::tc t(d);
  vic::font::LCD_6x8 lcd_6x8;
  t.set_font(lcd_6x8);
  t.set_pos({ 120, 50 });
  t.out(reinterpret_cast<const std::uint8_t*>("vic e-paper"));
  d.present_lock(false);                    // upload and refresh

  epd.shutdown();                           // deep sleep
  return 0;
}
```

## Controller notes

[SSD1680.md](https://github.com/mpaland/vic/blob/master/src/head/doc/SSD1680.md): 176 sources x 296 gates, two RAM
planes (24h black / white with 1 = white, 26h red). 4-wire SPI or 3-wire 9 bit SPI, up to 20 MHz write and 2.5 MHz
read, BUSY output high while the controller works. Waveforms come from the OTP (36 temperature ranges, selected by
the internal sensor 18h 80h) or are written by the MCU (32h); display mode 1 is the full update, mode 2 a partial
update with a mode 2 waveform. Commands: driver output 01h, data entry 11h, RAM ranges 44h / 45h, RAM counters 4Eh /
4Fh, update control 21h / 22h, master activation 20h, border 3Ch, deep sleep 10h. The controller has no rotation, the
X unit is a byte of 8 sources.

[SSD1681.md](https://github.com/mpaland/vic/blob/master/src/head/doc/SSD1681.md): the same command set for 200 x 200
panels with 5000 bytes per plane. Use `vic::head::SSD1680<200, 200, drv::orientation_0, Tri_Color>`, `Source_S8`
defaults to false for the 200 pixel width.
