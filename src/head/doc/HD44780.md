# HD44780 programming summary

Source: Hitachi, *HD44780U (LCD-II) Dot Matrix Liquid Crystal Display Controller/Driver* (`HD44780.pdf`).
The HD44780 is the standard controller of the alphanumeric LCD modules (8x1 .. 40x2, 16x4, 20x4) and the
compatible controllers (KS0066, ST7066, SPLC780 ...) follow its instruction set. This is the programming view
of the datasheet: registers, RAM layout, instruction set, interfaces and sequences. The last section
describes how the vic head `src/head/HD44780.h` uses the controller.

## 1 Overview

| Item | Value |
|---|---|
| Drivers | 16 common x 40 segment outputs: 8 characters of 5 x 8 dots in 2 lines (or 5 x 10 in 1 line) per chip, extended with HD44100 / HD66100 segment drivers to 40 characters per line |
| DDRAM | 80 x 8 bit character codes, more than the visible characters, the rest is usable as RAM |
| CGROM | 208 characters of 5 x 8 dots and 32 of 5 x 10 dots, ROM A00 (Japanese) or A02 (European) |
| CGRAM | 64 byte: 8 user characters of 5 x 8 dots or 4 of 5 x 10 dots |
| Supplies | VCC 2.7 .. 5.5 V, LCD drive voltage VCC - V5 up to 11 V (contrast at V0) |
| Oscillator | RC with external resistor or external clock, fOSC 190 .. 350 kHz, typ. 270 kHz |
| Frame rate | 1 frame = 400 (1/8, 1/11 duty) or 200 (1/16 duty) clocks x lines: 84.3 Hz at 270 kHz for 1/8 and 1/16 duty, 61.4 Hz for 1/11 duty |
| Duty | 1/8 (1 line 5 x 8), 1/11 (1 line 5 x 10), 1/16 (2 lines 5 x 8) |

## 2 MPU interface

Control pins: `RS` (0 = instruction register IR, 1 = data register DR), `R/W` (0 = write, 1 = read), `E` (enable,
data is latched on the falling edge), `DB7..DB0`.

| RS | R/W | Operation |
|---|---|---|
| 0 | 0 | Write instruction |
| 0 | 1 | Read busy flag (DB7) and address counter (DB6..DB0) |
| 1 | 0 | Write data to DDRAM or CGRAM |
| 1 | 1 | Read data from DDRAM or CGRAM |

- 8 bit bus: one E cycle per byte on DB7..DB0.
- 4 bit bus (function set DL = 0): only DB7..DB4 are used, every byte is two E cycles, high nibble first.
  DB3..DB0 are left open. The busy flag read is also two cycles (BF + AC6..AC4, then AC3..AC0).
- Busy flag: while an instruction executes BF = 1 and no instruction except the busy flag read is accepted.
  Either poll BF before every byte or wait the maximum execution time (37 us for most instructions,
  1.52 ms for clear and home at 270 kHz, scale by 270 / fOSC for other clocks). Reading the address counter
  right after a data access gives the old value for tADD = 1.5 / fOSC (4 us) after BF goes low.
- Data read: the first read after a set address instruction returns invalid data (the DR is filled one access
  behind), the next reads return the data at the address counter, which increments / decrements after
  every data read and write according to the entry mode.

Bus timing (write cycle):

| VCC | E cycle | E high | Setup RS / R/W before E | Data setup before E falls | Hold |
|---|---|---|---|---|---|
| 2.7 .. 4.5 V | >= 1000 ns | >= 450 ns | >= 60 ns | >= 195 ns | 10 ns |
| 4.5 .. 5.5 V | >= 500 ns | >= 230 ns | >= 40 ns | >= 80 ns | 10 ns |

## 3 DDRAM address map

The address counter (AC) holds the DDRAM or CGRAM address and is set by the address instructions; after a
data write or read it moves by +1 (I/D = 1) or -1 (I/D = 0). The cursor and blinking appear at the AC position.

| Mode (function set N) | Line | DDRAM addresses | Display position 1 .. 40 |
|---|---|---|---|
| 1 line (N = 0) | 1 | 00h .. 4Fh (80 characters) | 00h .. 27h visible on a 40 character module |
| 2 lines (N = 1) | 1 | 00h .. 27h | 00h + column |
| 2 lines (N = 1) | 2 | 40h .. 67h | 40h + column |

The two lines are not consecutive: after 27h the AC continues with 28h, which is not displayed, the cursor
reaches the second line only after the 40th character. A module with fewer visible columns shows the
first columns of each line, the AC runs on into the invisible area.

Display shift (entry mode S = 1 or the shift instruction) moves the window over the DDRAM: shift left shows
01h at position 1 (and 41h on line 2), shift right shows 27h / 67h at position 1. Both lines shift together,
line 2 never shifts into line 1.

4 line modules (16x4, 20x4) are 2 line controllers whose lines 3 and 4 continue lines 1 and 2 in the DDRAM:
line 3 starts at 00h + columns (14h for 20 columns), line 4 at 40h + columns (54h). Many 16x1 modules are
wired as 8x2 (positions 9 .. 16 at 40h) and must be configured as 2 line, 8 column displays.

## 4 CGROM and CGRAM

Character codes 20h .. 7Fh are ASCII in both ROMs with two exceptions in the A00 ROM: 5Ch is the yen sign and
7Eh / 7Fh are arrows. ROM A00 has half width Katakana at A1h .. DFh and symbols (ä, ß, ö, ü, °, Σ, Ω, ÷ ...) at
E0h .. FFh; ROM A02 has ISO 8859-1 like characters at A0h .. FFh and symbols at 10h .. 1Fh and 80h .. 9Fh.

Codes 00h .. 07h (bit 3 is ignored, so 08h .. 0Fh are the same) display the 8 user characters of the CGRAM:

| CGRAM address bits | Meaning |
|---|---|
| 5 .. 3 | character code 0 .. 7 |
| 2 .. 0 | pattern row 0 (top) .. 7 (bottom, the cursor line, keep it 0) |
| data bits 4 .. 0 | dots of the row, bit 4 is the left dot, 1 = on |

For the 5 x 10 font the 4 characters use codes 0, 2, 4, 6 with 16 rows each (rows 0 .. 10 displayed, row 10
is the cursor line). Write the CGRAM with set CGRAM address (40h | address) followed by the data bytes, the
AC increments per byte; set the DDRAM address afterwards to continue writing text.

## 5 Instruction set

All codes are written with RS = 0 (except the data instructions). Execution times are the maximum at
fOSC = 270 kHz.

| Instruction | RS | R/W | Code (DB7 .. DB0) | Time | Function |
|---|---|---|---|---|---|
| Clear display | 0 | 0 | `0000 0001` | 1.52 ms | DDRAM = 20h, AC = 0, shift reset, I/D = 1 |
| Return home | 0 | 0 | `0000 001x` | 1.52 ms | AC = 0, shift reset, DDRAM unchanged |
| Entry mode set | 0 | 0 | `0000 01 I/D S` | 37 us | I/D = 1 increment, S = 1 shift the display on every data write |
| Display on/off | 0 | 0 | `0000 1 D C B` | 37 us | D display, C cursor (underline), B blink the character at the cursor |
| Cursor / display shift | 0 | 0 | `0001 S/C R/L xx` | 37 us | S/C = 0 move the cursor (AC +/- 1), 1 shift the display; R/L = 1 right |
| Function set | 0 | 0 | `001 DL N F xx` | 37 us | DL = 1 8 bit bus, N = 1 two lines, F = 1 5 x 10 font; only once, before anything else |
| Set CGRAM address | 0 | 0 | `01 AAAAAA` | 37 us | AC = CGRAM address |
| Set DDRAM address | 0 | 0 | `1 AAAAAAA` | 37 us | AC = DDRAM address |
| Read busy flag / address | 0 | 1 | `BF AAAAAAA` | 0 | BF = 1 busy |
| Write data | 1 | 0 | data | 37 us | to DDRAM or CGRAM (the last address instruction decides), AC +/- 1 |
| Read data | 1 | 1 | data | 37 us | from DDRAM or CGRAM, AC +/- 1, no display shift |

Blink period: 409.6 ms at 250 kHz (379 ms at 270 kHz). The cursor is the 8th (11th) row of the character.

## 6 Reset and initialisation

Internal reset (power on, only if VCC rises within the specified limits): clear, function set 8 bit / 1 line /
5 x 8, display off, entry mode increment without shift; BF = 1 for 10 ms after VCC reaches 4.5 V.

Initialisation by instruction (figures 23 / 24), to be used when the power on conditions are not guaranteed:

| Step | 8 bit bus | 4 bit bus (DB7..DB4 only) | Wait after |
|---|---|---|---|
| Power on | | | > 40 ms (VCC >= 2.7 V) or > 15 ms (VCC >= 4.5 V) |
| 1 | 30h | 3h (one nibble) | > 4.1 ms, BF can't be checked |
| 2 | 30h | 3h | > 100 us, BF can't be checked |
| 3 | 30h | 3h | BF can't be checked |
| 4 | - | 2h (one nibble, sets 4 bit) | |
| 5 | function set 3xh | 2xh (two nibbles from here on) | BF can be checked from here on |
| 6 | display off 08h | | |
| 7 | clear 01h | | 1.52 ms |
| 8 | entry mode 06h | | |

The number of lines and the font can't be changed after step 5 (only together with a bus width change).

## 7 The vic head `src/head/HD44780.h`

```cpp
vic::head::HD44780<Columns = 16, Lines = 2,            // 1, 2 or 4 lines, max 40 columns, max 80 characters
                   Bus  = HD44780_BUS8,                // HD44780_BUS8, HD44780_BUS4
                   Wait = HD44780_WAIT_DELAY,          // HD44780_WAIT_DELAY, HD44780_WAIT_BUSY, HD44780_WAIT_IO
                   Rom  = HD44780_ROM_A00,             // HD44780_ROM_A00, HD44780_ROM_A02
                   Font_5x10 = false,                  // 1 line only
                   Exec_Us = 43>                       // execution time per byte in us: HD44780 37, ST7066 43
HD44780(io::handle_type device);
```

- io layer: every byte is one `io::write()`, the low byte of the option is the register: 0 = instruction (RS = 0),
  1 = data (RS = 1), 2 = instruction high nibble only (the four single nibble transfers of the 4 bit init; an 8 bit
  io layer treats it like 0). Bits 8 .. 23 of the option carry the execution time of the byte in us (`Exec_Us`), an
  io layer with `WAIT_IO` waits `(option >> 8) & 0xFFFF` us after the transfer, other io layers ignore the bits.
  The io layer drives E / R/W / RS, splits the nibbles in 4 bit mode or talks to an I2C expander (PCF8574 backpacks).
  `io::read()` with option 0 returns BF | AC (two nibbles assembled by the io layer in 4 bit mode).
- Waiting: `WAIT_DELAY` calls `io::delay(1)` after every byte (2 ms after clear / home), safe but slow (a
  20 x 4 screen takes 80 ms); `WAIT_BUSY` polls BF with `io::read()` (up to 1000 polls, falls back to the delay
  if the io layer can't read); `WAIT_IO` leaves the short waits to the io layer (the `Exec_Us` microseconds from the
  option bits or its own busy poll), only clear / home are delayed by the head. The init waits (50 / 5 / 1 / 1 ms)
  always use `io::delay()`. `Exec_Us` defaults to 43, the ST7066 value, which is also safe for the HD44780 (37 us).
- init: `30 30 30 [20] <function set> 08 01 06 0C`, cursor (0, 0). `shutdown()` = display off.
- Text: the head tracks the logical cursor (may be outside the screen) and the address counter; `text_out()`
  sets the DDRAM address only when the controller is not already at the cursor, characters outside the screen
  are skipped. Strings go through `drv::text_out()` (UTF-8 decoded, one data byte per character). The
  `text_clear_*()` functions write spaces and restore the cursor address. `cls()` is the clear instruction.
- Character mapping: 00h .. 07h (CGRAM) and 20h .. 7Fh unchanged; ROM A02 passes U+00A0 .. U+00FF through;
  ROM A00 maps half width Katakana U+FF61 .. U+FF9F to A1h .. DFh and ä ö ü ß ° ¥ · ÷ and the arrows to
  their codes; everything else becomes `?`.
- Display API: `display_enable()` (D bit), `cursor_set(show, blink)`, `char_define(index, pattern[8])`,
  `display_shift(right)`, `display_home()`. The logical positions don't follow a display shift until
  `display_home()` or `cls()`. No backlight control (not part of the controller).
- Limitations: no DDRAM read back, no 16x1 split addressing (configure such modules as 8 x 2), no 5 x 10
  CGRAM characters, no entry mode shift.

## 8 Compatible controllers: ST7066 crosscheck

Source: Sitronix, *ST7066 Dot Matrix LCD Controller/Driver*, V1.0 1999/12/09 (`ST7066.pdf`). The ST7066 states pin
function compatibility with the HD44780, KS0066U and SED1278; the SPLC780 and the ST7066U follow the same
programming model. The head `HD44780.h` works unchanged with these controllers. Checked item by item:

| Item | HD44780 | ST7066 | Head |
|---|---|---|---|
| Instruction codes | clear 01h, home 02h, entry 04h, display 08h, shift 10h, function 20h, CGRAM 40h, DDRAM 80h | identical, same bit positions (I/D S, D C B, S/C R/L, DL N F) | same codes |
| Execution time, instructions | 37 us | 37 us | 1 ms delay / busy poll / io layer |
| Execution time, data write and read | 37 us | **43 us** | `WAIT_DELAY` and `WAIT_BUSY` are safe, `WAIT_IO` gets the time from the `Exec_Us` template parameter (default 43) in the option bits |
| Clear / home | 1.52 ms | 1.52 ms | 2 ms delay |
| Busy flag / address counter read | DB7 = BF, DB6..DB0 = AC | identical, 0 us | `WAIT_BUSY` |
| 4 bit bus | DB7..DB4, high nibble first, BF read as two nibbles | identical | io layer |
| DDRAM map | 1 line 00h..4Fh, 2 lines 00h..27h / 40h..67h, 80 bytes | identical | `ddram_address()` |
| CGRAM | 8 characters of 5 x 8 (codes 00h..07h, bit 3 ignored), 4 of 5 x 10, row 7 is the cursor line | identical (table 5) | `char_define()` |
| Function set | DL, N, F; N = 1 forces 5 x 8 | identical, duty 1/8, 1/11, 1/16 | same |
| Internal reset | clear, 8 bit / 1 line / 5 x 8, display off, increment; BF = 1 for 10 ms after VCC >= 4.5 V | identical | not relied on |
| Init by instruction, 8 bit | 30h, > 4.1 ms, 30h, > 100 us, 30h, function set, 08h, 01h, 06h | identical; power on wait > 15 ms after VCC > 4.5 V | 50 ms, 5 ms, 1 ms, 1 ms |
| Init by instruction, 4 bit | 3h, 3h, 3h, 2h, then function set as two nibbles | identical | option 2 nibble transfers |
| Character ROM | A00 Japanese, A02 European | ROM code 0A Japanese (A1h..DFh Katakana), 0B European | `HD44780_ROM_A00` = 0A, `HD44780_ROM_A02` = 0B, check the module's table for the A0h..FFh layout of 0B |
| Bus timing at 5 V | E cycle 500 ns, E high 230 ns, address setup 40 ns, data setup 80 ns, hold 10 ns | E cycle 400 ns, E high 150 ns, address setup 30 ns, data setup 40 ns, hold 10 ns, read data delay <= 100 ns, bus up to 2 MHz | an HD44780 timed io layer is within the ST7066 limits |
| Oscillator | 190..350 kHz, typ. 270 kHz | identical (R = 91 kOhm), external clock 125..350 kHz | execution times scale with 270 / fOSC |
| Supply | VCC 2.7..5.5 V, VLCD up to 11 V | identical, RS and R/W have internal pull ups, E has none | - |
| Display size | 8 x 2 per chip, 40 x 2 with segment extenders | 8 x 2 per chip, ST7065 / ST7063 extenders | same limits |

Result: no functional change is needed. The only practical difference is the 43 us data write time, which the head
passes to the io layer as `Exec_Us` (default 43, set 37 for a genuine HD44780 to gain 6 us per byte with a `WAIT_IO`
io layer). Reading the DDRAM (which the head doesn't do) has the same first-read-invalid rule on both controllers.
