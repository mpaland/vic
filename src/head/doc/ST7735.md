# ST7735 programming summary

Source: Sitronix, *ST7735R 262K Color Single-Chip TFT Controller/Driver* (132RGB x 162 dot), V0.2, 2009-08-05
(`ST7735.pdf`, 164 pages). The ST7735R is the controller of the 1.8" 128 x 160, 1.44" 128 x 128 and 0.96" 80 x 160
TFT modules. It implements a subset of the MIPI DCS user commands and is driven by the generic head
`src/head/MIPI_DCS.h` (`MIPI_DCS_ST7735`); the shared head description is in `MIPI_DCS.md`, the bigger sibling is
described in `ST7789.md`. This file holds everything that is specific to the ST7735R. Page numbers are datasheet
pages (equal to the PDF pages). V0.2 is an early revision: the power consumption table is "TBD", several tables
contradict each other (pointed out where they matter) and many defaults depend on the GM pins.

## 2 Interfaces

### 2.1 Interface selection (9.1, p. 26; 9.4, p. 33; 13.3, p. 161 .. 163)

| P68 | IM2 | IM1 | IM0 | SPI4W | Interface | Pins |
|---|---|---|---|---|---|---|
| x | 0 | x | x | 0 | 3 line serial (9 bit frames) | CSX, SCL on the D/CX pad, SDA on D0 (bidirectional) |
| x | 0 | x | x | 1 | 4 line serial (8 bit + D/CX) | CSX, SCL on the D/CX pad, D/CX on the WRX pad, SDA on D0 |
| 0 | 1 | 0 | 0 | x | 8080 8 bit | D7 .. D0, WRX, RDX, D/CX, CSX |
| 0 | 1 | 0 | 1 | x | 8080 16 bit | D15 .. D0 |
| 0 | 1 | 1 | 0 | x | 8080 9 bit | D8 .. D0 |
| 0 | 1 | 1 | 1 | x | 8080 18 bit | D17 .. D0 |
| 1 | 1 | IM1 | IM0 | x | 6800 with the same widths | E on the RDX pad, R/WX on the WRX pad |

Commands are always 8 bit on D7 .. D0; register parameters and status reads (04h, 09h, 0Ah .. 0Fh, DAh .. DCh) are 8 bit
on D7 .. D0 whatever the bus width (Table 9.2.1, p. 27). Unused data pins must be tied to VDDI or DGND.

### 2.2 Parallel bus (9.2, 9.3, p. 27 .. 32)

8080: CSX low enables the bus, D/CX = 0 marks a command, 1 a parameter or GRAM data; the rising WRX edge latches
D[17:0]; on a read the controller drives the bus after the falling RDX edge and the host samples at the rising
edge. 6800: E strobe with R/WX (0 = write, 1 = read). Every read starts with one dummy read after the command, then
the data (Figure 9.2.4; the command tables list the "dummy read" for every read command). All signals are ignored
while CSX = 1. WRX / RDX / E may be stopped at any time.

### 2.3 Serial interface (9.4 .. 9.6, p. 33 .. 39)

- MSB first, SDA is sampled at the rising SCL edge; read data are shifted out at the falling edge, the host samples
  at the rising edge. The level of SCL at the falling CSX edge is free (SPI mode 0 or 3).
- CSX high resets the serial interface; a falling CSX edge starts a transfer. Bytes may follow each other without
  toggling CSX: the next D/CX bit (3 line) or D7 (4 line) is expected at the next rising edge.
- 3 line: every 9 bit frame starts with the D/CX bit. 4 line: the D/CX pin is sampled with the 8th bit (D0).
- Reads (Figures 9.4.5, 9.4.6): after the command the controller drives SDA (the D0 pad, there is no separate SDO);
  8 bit reads (RDID1 .. 3, 0Ah .. 0Fh) have no dummy clock, the 24 bit RDDID and the 32 bit RDDST have one dummy clock
  cycle before the data. CSX must go high after the read before the next command. The serial read figures do not
  cover RAMRD (2Eh): 9.4 only names "8-bit, 24-bit and 32-bit read parameter" and the RAMRD text only mentions the
  parallel buses, while the 4 line timing table gives the read clock for "read command & data ram" (8.4, p. 25).
- Break / pause: CSX or RESX going high inside a byte discards the partial byte; CSX high between whole bytes is a
  pause, the command, parameter or GRAM stream continues when CSX goes low again. If a multi parameter command is cut
  by a new command, the parameters received so far are stored, the rest keep their previous value.

### 2.4 Pixel data layouts (9.8, p. 41 .. 55)

| Bus | 12 bit (3Ah = 03h) | 16 bit (3Ah = 05h) | 18 bit (3Ah = 06h) |
|---|---|---|---|
| 8 bit, 4 line SPI, 3 line SPI (each byte preceded by D/CX = 1) | 3 bytes per 2 pixels: `R1[3:0] G1[3:0]`, `B1[3:0] R2[3:0]`, `G2[3:0] B2[3:0]` | 2 bytes: `R[4:0] G[5:3]`, `G[2:0] B[4:0]` | 3 bytes: R[5:0], G[5:0], B[5:0], each in bits 7:2, bits 1:0 don't care |
| 9 bit | - | - | 2 transfers: `R[5:0] G[5:3]`, `G[2:0] B[5:0]` on D8 .. D0 (9.8.10, p. 47; the note under the figure says "3-times transfer", the figure shows 2) |
| 16 bit | 1 transfer on D11 .. D0 | 1 transfer `R[4:0] G[5:0] B[4:0]` on D15 .. D0 | 3 transfers per 2 pixels: `R1 G1`, `B1 R2`, `G2 B2`, each component on D15 .. D10 resp. D7 .. D2 (9.8.8, p. 46; the note again says 3 transfers per pixel) |

Only complete pixels are stored; a stream may contain an odd or even number of pixels (9.7, p. 40). RAMRD always
returns 18 bit pixels in the 18 bit format of the bus (10.1.23, p. 108).

## 3 Frame memory

### 3.1 Address counter and window (9.10, 9.11, p. 61 .. 63; 10.1.19 .. 10.1.21, p. 102 .. 106)

CASET (2Ah) and RASET (2Bh) set the window (XS, XE) / (YS, YE), 16 bit each, XS <= XE, YS <= YE. Valid ranges: GM = 11
columns 0 .. 127 (MV = 0) or 0 .. 159 (MV = 1), rows 0 .. 159 resp. 0 .. 127; GM = 00 columns 0 .. 131 / 0 .. 161, rows
0 .. 161 / 0 .. 131; data outside the range are ignored. (9.10 gives the full window as "XE=127 (83h)", which mixes the
two GM cases.) Pointer movement:

| Event | Column counter | Row counter |
|---|---|---|
| RAMWR / RAMRD accepted | XS | YS |
| pixel complete | +1 | unchanged |
| column > XE | XS | +1 |
| column > XE and row > YE | XS | YS |

With MV = 1 the roles are exchanged: the counter defined by CASET still runs first, but it addresses the physical rows.
Any other command ends a RAMWR / RAMRD stream. MX, MY, MV changes need a GRAM rewrite.

### 3.2 GRAM to panel mapping (Tables 9.11.1 / 9.11.2, p. 62; 9.9, p. 57 .. 60)

| MV | MX | MY | CASET addresses | RASET addresses |
|---|---|---|---|---|
| 0 | 0 | 0 | physical column c | physical row r |
| 0 | 0 | 1 | column c | row (Rmax - r) |
| 0 | 1 | 0 | column (Cmax - c) | row r |
| 0 | 1 | 1 | column (Cmax - c) | row (Rmax - r) |
| 1 | 0 | 0 | row r | column c |
| 1 | 0 | 1 | row (Rmax - r) | column c |
| 1 | 1 | 0 | row r | column (Cmax - c) |
| 1 | 1 | 1 | row (Rmax - r) | column (Cmax - c) |

Cmax / Rmax = 127 / 159 for GM = 11 and 131 / 161 for GM = 00. MX always mirrors the physical columns, MY the physical
rows, MV only swaps which of CASET / RASET addresses them. Physical column 0 is source S7 (GM = 11) or S1 (GM = 00),
physical row 0 is gate G2 resp. G1, with SMX = SMY = SRGB = 0; the pins SMX / SMY reverse the source / gate scan in
hardware (6.3, p. 15). ML (D4) and MH (D2) only change the refresh direction. RGB (D3) and the SRGB pin swap the colour
filter order.

### 3.3 Pixel formats (10.1.30, p. 118; 10.1.22, p. 107; 9.18, p. 75)

COLMOD (3Ah) bits 2:0 IFPF: `011` 12 bit, `101` 16 bit, `110` 18 bit, `111` not used; bits 7:3 are don't care (the
datasheet writes the values as 03h / 05h / 06h, its own notes use 55h / 66h). In all modes the data pass through the
LUT written with RGBSET (2Dh): 128 bytes, 32 red (6 bit each, indexed by the 5 bit red value), 64 green, 32 blue;
12 bit data use the first 16 entries per colour. The LUT is "random" after power on and H/W reset and kept by a S/W
reset (9.15); the datasheet does not say that an identity LUT is preloaded, the reference drivers never send 2Dh.

### 4.3 Read ID values

RDDID / RDID1 .. 3 return the module manufacturer ID (no default in the datasheet), the version ID2 (NVM value, bit 7
reads as 1, range 80h .. FFh) and the module ID3 (NVM value) (10.1.3, 10.1.31 .. 10.1.33). The datasheet gives no fixed
chip ID, so the ID cannot be used to tell an ST7735R from other controllers.

## 5 Orientation

MADCTL (36h): D7 MY row address order, D6 MX column address order, D5 MV row / column exchange, D4 ML vertical
refresh order, D3 RGB (0 = RGB, 1 = BGR filter), D2 MH horizontal refresh order (10.1.27, p. 113). Reset 00h, kept by
SWRESET. The vic head maps its orientations as follows (`MADCTL` constant in `MIPI_DCS.h`), the BGR bit is added from
`RGB_to_BGR` (default true for the ST7735, most modules use BGR panels or SRGB = 1):

| vic orientation | MADCTL bits | Logical size | Offset_X (CASET) | Offset_Y (RASET) |
|---|---|---|---|---|
| `orientation_0` | - | W x H | c0 | r0 |
| `orientation_0m` | MY | W x H | c0 | rm |
| `orientation_180` | MX MY | W x H | cm | rm |
| `orientation_180m` | MX | W x H | cm | r0 |
| `orientation_90` | MX MV | H x W | r0 | cm |
| `orientation_90m` | MX MY MV | H x W | rm | cm |
| `orientation_270` | MY MV | H x W | rm | c0 |
| `orientation_270m` | MV | H x W | r0 | c0 |

W x H is the native (portrait) panel size, c0 / r0 the column / row of the GRAM where the panel starts with MX = 0 /
MY = 0, and by Table 9.11 cm = Gc - W - c0, rm = Gr - H - r0 with the GRAM size Gc x Gr = 128 x 160 (GM = 11) or
132 x 162 (GM = 00). The head adds Offset_X to the CASET and Offset_Y to the RASET values, so in the MV orientations
the row offset goes into Offset_X. Module values (from the reference drivers, not from the datasheet):

| Module | GM | c0 / r0 | Offsets for 0 / 180 family | Offsets for 90 / 270 family |
|---|---|---|---|---|
| 1.8" 128 x 160 "red / black tab" | 11 | 0 / 0 | 0 / 0 | 0 / 0 |
| 1.8" 128 x 160 "green tab" | 00 | 2 / 1 | 2 / 1 in all four (symmetric: 132 - 128 - 2 = 2, 162 - 160 - 1 = 1) | 1 / 2 |
| 0.96" 80 x 160 | 00 | 26 / 1 | 26 / 1 (centred) | 1 / 26 |
| 0.96" 80 x 160, other batches | 11 | 24 / 0 | 24 / 0 | 0 / 24 |
| 1.44" 128 x 128 | ? | 2 / 3 (head comment, TFT_eSPI) | MY = 0: 2 / 3; MY = 1: 2 / 31 by the rule above (GM = 00) | swap |

For 128 x 128 the row offsets for MY = 0 and MY = 1 must add up to 162 - 128 = 34 (GM = 00) or 160 - 128 = 32 (GM = 11).
The datasheet documents no 128 x 128 configuration (GM = 01 / 10 are not defined), so the offsets of these modules
cannot be derived from it and have to be checked on the module.

## 6 Power, reset and sequences

- Power on / off (9.13, p. 68): VDD on before VDDI, VDDI off before VDD (the timing figure allows 0 ns between them).
  RESX must be held stable during power on, otherwise a hardware reset is needed afterwards. If the chip is in sleep
  out mode, the supplies may only be removed >= 120 ms after RESX was released (0 ms in sleep in). CSX may be tied low;
  RESX has priority over CSX. No damage and no visible artefacts if the sequence is not met.
- Reset (9.17, p. 74): RESX low >= 10 us (pulses < 5 us are rejected, 5 .. 9 us may or may not reset). After the rising
  edge the NVM is loaded within 5 ms: wait 5 ms before any command and 120 ms before SLPOUT. A reset in sleep out mode
  blanks the display for up to 120 ms. After any reset: sleep in, display off.
- SWRESET: wait 120 ms before the next command (in both sleep states, 10.1.2). SLPIN / SLPOUT: wait 120 ms before the
  next command (10.1.10, 10.1.11). These are stricter than the generic 5 ms values in `MIPI_DCS.md`.
- SLPOUT starts the oscillator and DC / DC converter, the display stays blank for 2 frames; SLPIN blanks the display,
  discharges the panel and stops booster and oscillator. DISPOFF / DISPON only blank / show the GRAM.
- Power levels (9.14, p. 69): normal (262K colours) > partial > idle (8 colours) > partial + idle > sleep in (only
  interface and GRAM on VDDI) > power off; transitions by 10h / 11h, 12h / 13h, 38h / 39h.
- Recommended sequence: the datasheet contains no register init list, only the power flow chart (9.14.2). The usual
  bring-up is: power on, RESX pulse, 5 ms (120 ms before SLPOUT), SWRESET + 120 ms (optional after RESX), SLPOUT + 120
  ms, panel registers (B1h .. C5h, E0h / E1h as required by the module), MADCTL, COLMOD, NORON, write the GRAM, DISPON.
  Shutdown: DISPOFF, SLPIN, 120 ms, then the supplies may be removed.

Drawing uses CASET / RASET / RAMWR with the offsets added and RGB565 (or RGB666) streams, `pixel_get()` sends RAMRD and
reads 3 bytes (the io layer handles the dummy read / clock), `display_enable()` = 29h / 28h, `display_inverse()` =
21h / 20h relative to `Invert`, `display_brightness()` sends nothing (no 51h / 53h), `shutdown()` = 28h, 10h, 120 ms.

Crosscheck findings (1 .. 4 and the offset comment of 8 are fixed in the head):

1. INVCTR comment: `0xB4, 1, 0x07  // display inversion control, no inversion` - 07h sets NLA = NLB = NLC = 1, i.e.
   line inversion drive in all three modes (reset 03h = dot inversion in normal mode). B4h is the LCD drive polarity
   scheme, not the image inversion; the value (from the reference drivers) is legal. Fixed: the comment said "no inversion".
2. Fixed: `pixel_get()` read the GRAM with COLMOD = 55h; the datasheet requires 3Ah = 66h for RAMRD (10.1.23,
   10.1.30 note 2), the head now switches to 66h for the read and back to 55h. Also, RAMRD over the serial interface is not described in this datasheet (2.3).
3. Fixed: `display_brightness()` sent 53h / 51h, which the ST7735R does not have; it sends nothing on the ST7735 now.
4. Fixed: `shutdown()` waited 5 ms after SLPIN; the ST7735R needs 120 ms before the next command (10.1.10), the
   head waits 120 ms now.
5. The RGBSET LUT (2Dh) is never written. By the datasheet its content is random after power on / H/W reset and it is
   applied to 12 / 16 / 18 bit data; the reference drivers rely on the hardware default as well.
6. The head never pulses RESX; it relies on the board / io layer for the hardware reset (>= 10 us, then 5 ms) and on
   SWRESET. SLPOUT 500 ms and SWRESET 150 ms meet the 120 ms rules.
7. DISPON is part of the vendor table, so the uninitialised GRAM (in the default 18 bit format and MADCTL 00h) is
   visible until `cls()` has run. Cosmetic only.
8. Offsets: the head comment gives "128 x 160 green tab: 2 / 1, 128 x 128: 2 / 3". These are the values for the
   non-MV orientations; for `orientation_90` / `270` (MV = 1) Offset_X and Offset_Y must be exchanged (1 / 2), and the
   128 x 128 pair changes with MY (section 5). The head comment now says that the values are swapped for MV.
9. `MIPI_DCS.md` describes the ST7735 with "8 bit 8080 ... RGB" and generic 5 ms SWRESET / sleep delays; the ST7735R
   has 8 / 9 / 16 / 18 bit 8080 and 6800 buses, no RGB interface, and needs 120 ms after SWRESET, SLPIN and SLPOUT.
