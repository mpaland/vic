# JD79667 programming summary

Source: Jadard, *JD79667AA All-in-one driver with TCON for Color application*, Data Sheet Version 1.0.3, 2023/06/20
(`JD79667.pdf`, 80 pages). The JD79667 drives four color (black / white / yellow / red) e-paper panels up to
200 x 384, e.g. 2.66" 184 x 360, 2.9" 168 x 384 and 1.54" 200 x 200 modules. It is driven by the vic head
`src/head/JD79667.h`, described in section 8. The datasheet describes the registers but has no init sequence and
no color assignment; both come from the public drivers compared in section 9.

## 1 Overview

| Item | Value |
|---|---|
| Panel | 200 sources (S0 .. S183 + 2 x 8 additional outputs) x 384 gates, VCOM, 4 border outputs VBD; two chips can be cascaded (MS pin) to 400 x 384 |
| Frame memory | 200 x 384 x 2 bit SRAM = 19200 byte, 4 pixels per byte |
| Supplies | VDD / VDDIO / VDDP 2.3 .. 3.6 V, VDD_15V 1.5 V from the internal regulator, VMTP 10.1 V for MTP programming only |
| Voltage generation | internal booster (external 47 uH inductor, NMOS, 3 diodes, 2.2 Ohm sense resistor, 1 uF capacitors): VGP / VGN +-20, +-17, +-15, +-10 V; source mode 0: VSP_0 / VSN_0 +-15 V fixed, VSPL_0 3 .. 15 V; mode 1: VSP_1, VSN_1, VSPL_1 +-3 .. +-15 V in 0.1 V; the modes can change frame by frame; DCVCOM 0 .. -4 V in 50 mV |
| Interface | 4-wire SPI (BS = L: CSB, DC, SCL, SDA) or 3-wire 9 bit SPI (BS = H), 10 MHz write, 6.6 MHz read; BUSY_N output, low while the controller works |
| Waveforms | LUT from the MTP (compressed, temperature dependent) or from registers (PSR LUT_EN, the LUT registers are not in this datasheet) |
| MTP | 6144 byte: LUT, 100 user bytes, default settings of the main registers, vendor settings |
| Temperature | internal sensor -25 .. 50 C +-2 C (8 bit + 2 fraction bits) or external LM75 on TSDA / TSCL (11 bit) |
| Extras | low power detection 2.2 .. 2.5 V, VCOM auto measurement, partial window, auto sequence (PON, DRF, POF, DSLP in one command) |
| Refresh | full update 12 .. 25 s (value of the reference drivers, GxEPD2 measured 21.4 s on the 2.9" panel; the datasheet gives no update time) |

State after reset: the POR values of section 4, notably PSR 0Fh 09h (200 x 384, scan up, shift right, LUT from
the MTP), CDI 97h (border floating), PLL 02h (50 Hz), TRES 0 x 0. If the MTP byte 175Bh is A5h the default
settings block of the MTP (section 6) replaces the POR values.

## 2 Interface and BUSY_N

| BS | Interface | Pins |
|---|---|---|
| L | 4-wire SPI | CSB, DC, SCL, SDA |
| H | 3-wire SPI, 9 bit | CSB, SCL, SDA; DC connected to VDD |

- Write: MSB first; 4-wire with DC = 0 for the command byte and DC = 1 for parameters / data, 3-wire with a
  leading D/C bit per 9 bit frame. CSB may go high between a command and its parameters and between parameters.
- Read (DSP 11h, TSC 40h, TSR 43h, LPD 51h, REV 70h, VV 81h, RMTP 92h, RMRB 9Fh, LVSEL E4h): after the command
  byte the chip drives SDA, the host samples on the rising edge of SCL and has to float SDA. RMTP and RMRB return
  a dummy byte first.
- BUSY_N: 0 = busy ("data / VCOM is transforming"), 1 = the host can send commands. It goes low after PON, POF,
  DRF, AMV, the temperature commands and during MTP programming, and returns high when the sequence is finished.
  POF, PON, DSLP, DSP, DRF, AUTO, TSC, LPD, AMV and RMTP are only accepted while BUSY_N = 1. The level in deep
  sleep is not specified; the reference drivers do not wait after DSLP.
- RST_N low resets all registers, switches the booster off and floats source, gate, border and VCOM. Deep sleep
  and the MTP program mode are left only with a hardware reset. The datasheet gives no RST_N pulse width
  (Figure 4.1: VDD stable > 0 ms before RST_N high, > 100 ms between power off and VDD off); the drivers use
  2 .. 40 ms low and wait for BUSY_N high afterwards.
- MS selects master (H, also for a single chip) or slave in cascade mode; BS, MS, TSCL and TSDA must not float.

AC timing (section 10.4):

| Parameter | Min |
|---|---|
| CSB setup TCSS / hold TCSH | 60 / 65 ns |
| CSB TSCC / high between transfers TCHW | 20 / 40 ns |
| SCL cycle write / read | 100 / 150 ns |
| SCL high and low, write / read | 35 / 60 ns |
| SDA setup / hold | 30 / 30 ns |
| DC setup / hold | 20 / 20 ns |
| Read access time TACC / output disable TOH | max 50 ns / 15 ns |

## 3 Frame memory and data format

DTM (10h) writes the frame memory from the first pixel of the first line; there is no address counter command,
every DTM starts at the origin of the frame (or of the partial window). A line is `HRES / 4` bytes, the frame
`HRES / 4 x VRES` bytes, 4 pixels per byte with the first pixel in bits 7:6.

| Pixel[1:0] | DDX = 1 (default) | DDX = 0 | Color with the panel LUT (DDX = 1) |
|---|---|---|---|
| 00 | Gray0 | Gray3 | black |
| 01 | Gray1 | Gray2 | white |
| 10 | Gray2 | Gray1 | yellow |
| 11 | Gray3 | Gray0 | red |

The datasheet only defines four gray levels that select a waveform; the color of each level is a property of
the LUT in the MTP of the panel. The assignment above is the one of all reference drivers (section 9).

| Hex | Parameters | POR | Function |
|---|---|---|---|
| 10 DTM | data | - | frame data, followed by DSP or DRF |
| 11 DSP | read 1 byte | - | data stop, D7 = data_flag: 1 = a complete frame was received; the datasheet says the user "must" send it after the data and that the refresh starts with data_flag = 1, the reference drivers skip it and start the refresh with DRF |
| 61 TRES | HRES[9:8], HRES[7:2] 00, VRES[9:8], VRES[7:0] | 0, 0 | resolution: sources (multiple of 4), gates; active outputs S0 .. HRES - 1 and G0 .. VRES - 1 |
| 65 GSST | S_start[9:8], S_start[7:2] 00, G_start[9:8], G_start[7:0] | 0, 0 | first source (multiple of 4) and first gate line |
| 83 PTL | HRST (2), HRED (2), VRST (2), VRED (2), PMODE | 0 | partial window: start / end in sources (HRST multiple of 4, HRED[1:0] always 11) and gates, 9th byte bit 0 = 1 enables the partial mode; the gates scan inside and outside of the window |

HRES[9:8], S_start[9:8], HRST[9:8], HRED[9:8] and bit 9 of the vertical values are always 0.

Registers used by all reference drivers but not described in this datasheet: 03h (POFS, power off sequence,
3 bytes), 4Dh, 60h (TCON, 2 bytes), B4h, B5h, E7h, E9h. GxEPD2 refers to the GDEY0266F51H panel specification
for a command list.

Datasheet inconsistencies: the register table 8.1 is shifted against the detail sections in several rows (codes,
bit names); PWR lists V_MODE as bit 3 in the description but not in the bit table; TRES 3rd parameter prints
"VRES(8) VRES(0)", PTL prints VRST for both vertical values in 8.1; the MTP table prints the addresses 176Dh and
177Fh twice; the register restriction table lost its column alignment; several electrical values are "to be
confirmed by design".

## 5 Orientation

PSR UD reverses the gate scan and SHL the source shift direction, so 0 and 180 degree and both mirrors are
possible in the controller. A 90 degree rotation is not, the data order is fixed line by line. The vic head keeps
PSR at UD = 1, SHL = 1 and maps every orientation in software (`to_phys()`):

| Orientation | physical (source x, gate y) from logical (x, y) |
|---|---|
| `orientation_0` | (x, y) |
| `orientation_0m` | (x, H - 1 - y) |
| `orientation_180` | (W - 1 - x, H - 1 - y) |
| `orientation_180m` | (W - 1 - x, y) |
| `orientation_90` | (W - 1 - y, x) |
| `orientation_90m` | (W - 1 - y, H - 1 - x) |
| `orientation_270` | (y, H - 1 - x) |
| `orientation_270m` | (y, x) |

W / H are the physical sources / gates; the logical size is swapped for 90 / 270.

## 6 Sequences and MTP

Power on (section 9.1, Figure 1): VDD / VDDIO on, reset, the temperature is measured (TS_AUTO), PON starts the
booster (phase A and B: VGP / VGN, phase C: VSP / VSPL / VSN) and BUSY_N returns high; a refresh then drives
VCOM and the sources from the LUT and ends as selected by FOPT. Power off (Figure 2): POF discharges source and
VCOM first, then the source and gate supplies. DSLP (Figure 3) switches VDD_15V off as well, RST_N wakes the chip.

Data transmission (section 9.3): temperature measurement, DTM with the frame, DSP / DRF, BUSY_N low for all
frames of the waveform; with FOPT = 0 the driver scans one more frame with the sources at 0 V and floats VCOM
afterwards, with FOPT = 1 VCOM and the sources float directly after the last frame. (The figures name "20h" and
"LUTC", commands of an older chip family.)

Operation flow of the reference drivers:

1. Hardware reset, wait for BUSY_N high.
2. Init registers (section 8), PON, wait for BUSY_N high.
3. DTM with the complete frame, DRF 00h, wait for BUSY_N high (12 .. 25 s).
4. POF 00h, wait for BUSY_N high, DSLP A5h. The next update starts with the hardware reset again.

The AUTO command (17h) can replace PON / DRF / POF (/ DSLP) after the data; no reference driver uses it.

MTP map (section 9.2):

| Address | Content |
|---|---|
| 0000h .. 15DFh | compressed LUT |
| 15E0h .. 16F6h | reserved |
| 16F7h .. 175Ah | 100 user reserved bytes (RMRB 9Fh) |
| 175Bh .. 1784h | default settings |
| 1785h .. 17FFh | vendor (JD) settings |

Default settings block (value column of the datasheet, i.e. the blank default): 175Bh enable code A5h; PSR 0Fh
09h; PWR 07h 00h 00h 00h 00h 00h; 4 reserved bytes 00h 00h 54h 44h; BTST 00h 06h 02h 07h 02h 07h 02h; reserved
00h; PLL 02h; CDI 97h; 2 reserved bytes 02h 02h; TRES 4 x 00h; GSST 4 x 00h; 4 reserved bytes FFh FFh FFh 00h;
PWS 00h; LVSEL 03h; 3 reserved bytes 03h 1Ch 00h. The reserved values 54h 44h, 02h 02h, 03h and 1Ch are the
parameters the reference drivers write to the undocumented registers 03h, 60h, B5h and E7h, so these bytes are
most likely their MTP defaults. The printed BTST defaults are shifted by one byte against the register POR values.

## 8 The vic head `src/head/JD79667.h`

```cpp
vic::head::JD79667<Screen_Size_X = 200, Screen_Size_Y = 384,    // logical size (sources x gates for orientation_0)
                   Orientation  = drv::orientation_0,            // 90 / 270 for landscape, done in software
                   Refresh_Delay = 25000>                        // ms, used when BUSY_N can't be read
JD79667(io::handle_type device);
```

- io layer: `io::write()` option 0 = command, 1 = data; `io::read()` option 2 returns one byte with bit 0 = 1
  while the controller is busy, i.e. the inverted level of the BUSY_N pin. The head polls it every 10 ms (up to
  30 s) after the reset, PON, DRF and POF. An io layer without BUSY read returns false, the head then waits
  200 ms after reset / PON / POF and `Refresh_Delay` after a refresh. The hardware reset is part of `io::init()`.
- init: 10 ms delay, BUSY, `4Dh 78h`, `00h 0Fh 29h`, `01h 07h 00h`, `03h 10h 54h 44h`,
  `06h 05h 00h 3Fh 0Ah 25h 12h 1Ah`, `50h 37h`, `60h 02h 02h`, `61h` (sources, gates), `E7h 1Ch`, `E3h 22h`,
  `B4h D0h`, `B5h 03h`, `E9h 01h`, `30h 08h`, `04h` + BUSY, clear to white. The panel is not refreshed by
  `init()` and the power stays on until `shutdown()`.
- Framebuffer: 2 bit per pixel in physical orientation, `sources / 4` bytes per line, bits 7:6 = first source.
  Colors: `color::none` and light colors (luminance >= 128) are white paper, red (R >= 128, G < 96, B < 96) and
  yellow (R >= 128, G >= 128, B < 96) go to their pigment, other dark colors are black. `pixel_get()` returns
  black, white, yellow or red.
- `line_horz()` and `line_vert()` are written directly into the framebuffer (color mapped and clipped once per
  line, a run along the sources as whole bytes), `box()` and the filled primitives use them.
- `present()` sends `10h` with the whole framebuffer and `12h 00h` and waits for BUSY. It does nothing when the
  framebuffer did not change since the last refresh; batch primitives with `dc::present_lock()` to get one
  refresh per screen. `shutdown()` sends `02h 00h`, waits for BUSY and enters deep sleep with `07h A5h`; `init()`
  (hardware reset) wakes the controller up.
- `static_assert`: physical width <= 200 and a multiple of 4, height <= 384.
- Not covered: partial window (83h), the AUTO sequence, temperature and low power read back, VCOM measurement,
  MTP access, cascade mode.

Crosscheck of the head (= reference driver sequence) against the datasheet:

| Item | Assessment |
|---|---|
| `4Dh 78h`, `E7h 1Ch`, `B4h D0h`, `B5h 03h`, `E9h 01h` | not in the datasheet; sent by all reference drivers, kept unchanged |
| `00h 0Fh 29h` PSR | 0Fh = POR (RES 00, UD, SHL, booster on); 29h = POR 09h + FOPT: no extra scan frame, the sources float after the waveform |
| RES = 00 for every panel size | the datasheet assigns RES 01 / 10 / 11 to 184 / 168 wide and 200 x 200 panels; the reference drivers leave RES at 00 on 168 x 384 and 184 x 360 panels and set the size with TRES only, the head does the same |
| `01h 07h 00h` PWR | POR values (all supplies internal, +-20 V gates); only 2 of the 6 parameters are sent, the source voltages stay at their MTP / POR values |
| `03h 10h 54h 44h` POFS | not in the datasheet (GxEPD2: power off timing); 54h 44h equal the reserved MTP defaults |
| `06h 05h 00h 3Fh 0Ah 25h 12h 1Ah` BTST | valid: 20 ms soft start for phase A and B; phase A strength 1 / period 64, B strength 11 / period 38, C strength 19 / period 27 |
| `50h 37h` CDI | valid: border Gray1 = white, DDX = 1, 10 hsync; the POR 97h leaves the border floating |
| `60h 02h 02h` TCON | not in the datasheet; equals the reserved MTP defaults |
| `61h` TRES | valid, the head asserts a width that is a multiple of 4 |
| `E3h 22h` PWS | valid: VCOM_W = 2 lines, SD_W = 2 x 500 ns |
| `30h 08h` PLL | valid: dynamic frame rate, FR = 000 |
| `04h` once in `init()` | valid; the booster stays on between refreshes until `shutdown()` |
| `10h` data, then `12h 00h` | DSP (11h) is not sent although the datasheet demands it; DRF starts the refresh in all reference drivers. Waveshare sends 12h with 01h, the parameter is don't care |
| BUSY poll directly after PON / DRF / POF | the datasheet gives no delay until BUSY_N falls; GxEPD2 waits 1 ms before polling, an io layer that reads the pin too early would end the wait at once |
| `02h 00h`, `07h A5h` | valid; POF is only accepted with BUSY_N = 1, the head waits before DSLP |
| Pixel codes 00 / 01 / 10 / 11 = black / white / yellow / red | not in the datasheet (LUT property), identical in all reference drivers |
| Verification | compared with the datasheet and the reference drivers and checked with the io trace and the unit test, not run on a panel |
