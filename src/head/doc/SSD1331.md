# SSD1331 programming summary

Source: Solomon Systech, *SSD1331 96RGB x 64 Dot Matrix OLED/PLED Segment/Common Driver with Controller*,
Rev 1.2, Nov 2007 (`SSD1331.pdf`). This is the programming view of the datasheet: interfaces, RAM layout,
command set, orientation bits and sequences. Pad lists and electrical limits are left out except where a
driver needs them. The last section describes how the vic head `src/head/SSD1331.h` uses the controller.

## 1 Overview

| Item | Value |
|---|---|
| Panel | 96 RGB x 64 (288 segment outputs SA/SB/SC 0..95, 64 common outputs) |
| GDDRAM | 96 x 64 x 16 bit, 65k colors (256 color mode is expanded into the 65k RAM) |
| Supplies | VDD 2.4 .. 3.5 V (logic), VDDIO 1.6 V .. VDD (interface), VCC 8 .. 18 V (panel) |
| Interfaces | 8/9/16 bit 6800, 8/9/16 bit 8080, SPI (write only) |
| Brightness | 256 step contrast per color (81h..83h), 16 step master current (87h), 64 gray levels by PWM |
| Acceleration | draw line, draw rectangle (filled), copy, dim window, clear window, continuous scrolling |
| Oscillator | Fosc typ. 890 kHz (800 .. 980), divider 1..16, frame rate F = Fosc / (D x K x MUX), K = phase1 + phase2 + 125 (136 at reset) |
| Reset timing | RES# low >= 3 us, reset done <= 2 us |

Bus selection pins BS[3:0]: `0000` SPI, `0100` 8 bit 6800, `0101` 16 bit 6800, `0110` 8 bit 8080, `0111` 16 bit 8080,
`1100` 9 bit 6800, `1110` 9 bit 8080.

State after RES#: display off, 64 MUX, start line 0, offset 0, no remap (SEG0 = column 0, COM0 = row 0),
column pointer 0, master current 0Fh, contrast A/B/C 80h, normal display (A4h), serial shift register cleared.

## 2 Interfaces

Control pins: `CS#`, `D/C#` (0 = command, 1 = GDDRAM data), `RES#`, `E(RD#)`, `R/W#(WR#)`, `D[15:0]`.

| Bus | Write | Read | Notes |
|---|---|---|---|
| 6800 | R/W# = 0, data latched on the falling edge of E while CS# = 0 | R/W# = 1 | tcycle >= 130 ns |
| 8080 form 1 | rising edge of WR# while CS# = 0 | rising edge of RD# | tcycle >= 130 ns |
| 8080 form 2 | RD#/WR# static, CS# is the latch | | |
| SPI | SCLK = D0, SDIN = D1, MSB first, D/C# sampled on the 8th clock | not possible | tcycle >= 150 ns (6.6 MHz), E and R/W# tied low |

Data bus width per mode: 8 bit on D[7:0], 9 bit on D[8:0], 16 bit on D[15:0]; unused pins tied low (except D2 in SPI mode).

Reads (parallel buses only): a dummy read is required after setting the address and before the first data byte.
The column (or row) pointer increments after every data write and every data read, not after commands.
No status register is documented.

## 3 GDDRAM and data formats

The RAM holds 96 columns x 64 rows of 16 bit pixels. A pixel is `C[4:0] B[5:0] A[4:0]` (MSB to LSB), color A drives
the SA segments, B the SB segments and C the SC segments. Remap bit A[2] (see section 5) reverses the segment order
(SC, SB, SA), the RAM word itself does not change. Which of A/C is red or blue is a property of the panel wiring:
the datasheet examples use C for blue and A for red, the common 0.96" modules show correct colors when the word is
sent as RGB565 (R in the MSB) with A[2] = 0.

Bus to RAM mapping (Table 9):

| Bus | Depth | Transfers | Byte / word content (MSB first) |
|---|---|---|---|
| 8 bit | 256 colors | 1 | `C4 C3 C2 B5 B4 B3 A4 A3` |
| 8 bit | 65k format 1 | 2 | `C4 C3 C2 C1 C0 B5 B4 B3`, `B2 B1 B0 A4 A3 A2 A1 A0` |
| 8 bit | 65k format 2 | 3 | `x x C4 C3 C2 C1 C0 x`, `x x B5 B4 B3 B2 B1 B0`, `x x A4 A3 A2 A1 A0 x` |
| 16 bit | 65k | 1 | `C4..C0 B5..B0 A4..A0` on D15..D0 |
| 9 bit | 65k | 2 | `C4..C0 x B5 B4 B3` on D8..D0, `B2 B1 B0 A4..A0 x` |

256 color mode fills the 65k word by copying bits: `C4 C3 C2 *C4 *C4 B5 B4 B3 *B5 *B5 *B5 A4 A3 *A4 *A4 *A4`.
In 9 and 16 bit mode the color depth is always 65k regardless of A[7:6].

Gray scale: color B has 6 bits (GS0 .. GS63), colors A and C have 5 bits and use the even entries GS0, GS2 .. GS62.
The gray scale table (B8h) holds the pulse width of the current drive phase in DCLK for the odd entries GS1, GS3 ..
GS63 (32 values, increasing, max 125), the even entries are interpolated `GSn = (GSn-1 + GSn+1) / 2`. B9h loads the
linear table GS1 = 1, GS2 = 3 .. GS63 = 125.

Address pointer: 15h sets the column start/end and moves the column pointer to the start, 75h the same for rows.
With horizontal increment (A0h A[0] = 0) the column pointer increments after every pixel, wraps from column end to
column start and then increments the row; the row wraps from row end to row start. With vertical increment
(A[0] = 1) the roles are swapped: row first, then column. A window is therefore a rectangle that is filled
row major (A[0] = 0) or column major (A[0] = 1) by a plain pixel stream.

## 4 Command set

All commands are written with D/C# = 0. Parameters follow as separate command bytes. Coordinates are RAM
coordinates and inclusive.

### 4.1 Fundamental commands

| Hex | Parameters | Reset | Function |
|---|---|---|---|
| 15 | A[6:0] start, B[6:0] end | 00h, 5Fh | Set column address and column pointer |
| 75 | A[5:0] start, B[5:0] end | 00h, 3Fh | Set row address and row pointer |
| 81 / 82 / 83 | A[7:0] | 80h | Contrast color A / B / C (segment current = contrast / 256 x IREF x scale) |
| 87 | A[3:0] | 0Fh | Master current, scale factor (A + 1) / 16 |
| 8A / 8B / 8C | A[7:0] | = contrast | Second precharge speed color A / B / C, all six bytes must be sent together |
| A0 | A[7:0] | 40h | Remap and data format, see section 5 |
| A1 | A[5:0] | 00h | Display start line (RAM row shown on COM0) |
| A2 | A[5:0] | 00h | Display offset (vertical shift by COM) |
| A4 / A5 / A6 / A7 | - | A4h | Normal display / all pixels GS63 / all pixels GS0 / inverse (GSn <-> GS63-n) |
| A8 | A[5:0] | 3Fh | Multiplex ratio N + 1, N = 15 .. 63 |
| AB | A = 00h, B/C/D contrast A/B/C, E[4:0] precharge | - | Dim mode settings (used by ACh) |
| AD | A[0] | 1 | Master configuration: write 8Eh (A[0] = 0, external VCC) after reset, active after AFh |
| AC / AE / AF | - | AEh | Display on in dim mode / display off (sleep) / display on |
| B0 | A[7:0] | 1Ah | Power save mode: 1Ah enable, 0Bh disable |
| B1 | A[3:0] phase 1, A[7:4] phase 2 | 74h | Precharge periods in DCLK, 1 .. 15 each (0 is invalid) |
| B3 | A[3:0] = D - 1, A[7:4] Fosc | D0h | Display clock divider 1 .. 16 and oscillator frequency (higher = faster) |
| B8 | 32 x A[6:0] | linear | Gray scale table GS1, GS3 .. GS63 |
| B9 | - | - | Load the linear gray scale table |
| BB | A[5:1] | 3Eh | Precharge voltage 0.10 x VCC (00h) .. 0.50 x VCC (3Eh) |
| BE | A[5:1] | 3Eh | VCOMH: 00h 0.44, 10h 0.52, 20h 0.61, 30h 0.71, 3Eh 0.83 x VCC |
| BC / BD / E3 | - | - | NOP |
| FD | A[2] | 12h | Command lock: 12h unlock, 16h lock (only FDh is accepted while locked) |

### 4.2 Graphic acceleration commands

| Hex | Parameters | Function |
|---|---|---|
| 21 | col0 row0 col1 row1, C B A | Draw line in the given color |
| 22 | col0 row0 col1 row1, C B A outline, C B A fill | Draw rectangle, the area is filled only if 26h A[0] = 1 |
| 23 | col0 row0 col1 row1, newcol newrow | Copy the area to the new position, overlapping is allowed |
| 24 | col0 row0 col1 row1 | Dim window: GS0..15 unchanged, GS16..19 -> GS4 .. GS60..63 -> GS15, idempotent |
| 25 | col0 row0 col1 row1 | Clear window, RAM of the area is set to 0 |
| 26 | A[0] fill enable, A[4] reverse copy | Fill for 22h (reset 0), color inversion during 23h (reset 0) |
| 27 | A[6:0] column offset, B[5:0] start row, C[6:0] rows, D[5:0] row offset, E[1:0] interval | Scroll setup: offset 0 = no scroll in that direction, B + C <= 64, E: 00 = 6, 01 = 10, 10 = 100, 11 = 200 frames; vertical scroll needs 64 MUX |
| 2E | - | Deactivate scrolling, the RAM has to be rewritten afterwards |
| 2F | - | Activate scrolling with the 27h settings |

GAC color bytes carry 5 bit colors A and C in bits 5:1 and the 6 bit color B in bits 5:0, i.e. for an RGB565 word
`w`: C = `(w >> 10) & 0x3E`, B = `(w >> 5) & 0x3F`, A = `(w << 1) & 0x3E`.

The datasheet specifies neither an execution time for a GAC command nor a busy flag. Copy + clear window is the
documented way to move an area (section 9.2.5).

## 5 Remap and data format (A0h)

| Bit | 0 | 1 |
|---|---|---|
| A[0] | horizontal address increment | vertical address increment |
| A[1] | RAM column 0 -> SEG0 | RAM column 95 -> SEG0 (horizontal mirror) |
| A[2] | segment order SA, SB, SC (e.g. RGB) | reverse order SC, SB, SA (e.g. BGR) |
| A[3] | COM left/right swap off | COM left/right swap on |
| A[4] | scan COM0 -> COM[N-1] | scan COM[N-1] -> COM0 (vertical mirror) |
| A[5] | COM split odd/even off (sequential COM pins) | COM split odd/even on (COM0, COM2 .. one side, COM1, COM3 .. the other) |
| A[7:6] | 00 256 colors | 01 65k format 1, 10 65k format 2 |

A[3] and A[5] match the panel wiring (Table 12 / Figure 26 of the datasheet), A[1] and A[4] mirror the image.
The known 96 x 64 modules use A[5] = 1 (0x72 / 0x76 in vendor code: 65k, COM split, scan remap, column remap, with
or without BGR).

vic orientation mapping used by the head (A[7:6] = 01 and A[5] = 1 always):

| Orientation | A[0] vertical inc. | A[1] column remap | A[4] COM scan remap | logical (x, y) -> RAM (col, row) |
|---|---|---|---|---|
| `orientation_0` | 0 | 0 | 0 | (x, y) |
| `orientation_0m` | 0 | 0 | 1 | (x, y) |
| `orientation_180` | 0 | 1 | 1 | (x, y) |
| `orientation_180m` | 0 | 1 | 0 | (x, y) |
| `orientation_90` | 1 | 1 | 0 | (y, x) |
| `orientation_90m` | 1 | 1 | 1 | (y, x) |
| `orientation_270` | 1 | 0 | 1 | (y, x) |
| `orientation_270m` | 1 | 0 | 0 | (y, x) |

The `m` orientations mirror the physical screen top/bottom after the rotation, like the MAX7219 and SSD1306 heads.
In the rotated modes the logical screen is 64 x 96 and the vertical address increment makes a logical row major
pixel stream land in the transposed RAM window.

## 6 Power on / off

Power on (Figure 19): VDD and VDDIO on, RES# low for >= 3 us then high, wait >= 3 us, VCC on, send AFh; the
SEG/COM outputs are driven 100 ms after AFh (tAF).
Power off (Figure 20): AEh, VCC off (leave floating), wait tOFF (typ. 100 ms), VDD/VDDIO off.

IREF: resistor to VSS, `R = (VCC - 3 V) / 10 uA` (about 910 kOhm at 12 V); ISEG max 160 uA at contrast FFh.

Typical init sequence of the 96 x 64 modules (vendor values, all used by the head):
`FD 12, AE, A0 <remap>, A1 00, A2 00, A4, A8 3F, AD 8E, B0 0B, B1 31, B3 F0, 8A 64, 8B 78, 8C 64, BB 3A, BE 3E,
87 06, 81 91, 82 50, 83 7D, 26 01, 2E, AF`.

## 7 The vic head `src/head/SSD1331.h`

```cpp
vic::head::SSD1331<Screen_Size_X = 96, Screen_Size_Y = 64,  // logical size, 64 x 96 for orientation_90 / 270
                   Orientation    = drv::orientation_0,
                   Interface_Mode = SSD1331_SPI,             // SSD1331_SPI (write only), SSD1331_PAR8, SSD1331_PAR16
                   RGB_to_BGR     = false,                   // remap bit A[2]
                   Use_GAC        = true,                    // accelerator for cls(), box() and move()
                   GAC_Delay      = 0>                       // ms delay after every GAC command
```

- io layer: `io::write()` option 0 = command, 1 = data (the D/C# line). The head always emits 8 bit bytes, a 16 bit
  bus io layer packs two data bytes into one word (first byte = D15..D8). `io::read()` option 1 reads pixels on the
  parallel buses and must perform the dummy read.
- Pixel format: 65k format 1, RGB565 big endian (`color::color_to_RGB565()`), R in the MSB. If red and blue are
  swapped on a module, set `RGB_to_BGR`.
- Addressing: every pixel stream sets the column/row window (15h/75h) first; single pixels and horizontal lines
  open a window from the pixel to the screen end so that consecutive pixels along x need no new address. The head
  tracks the controller pointer and only re-addresses when needed.
- `cls()` = clear window (25h) for black, filled rectangle (22h) for other colors; `box()` = draw rectangle with
  fill; `move()` = copy (23h), clipped to the screen. Without `Use_GAC` these stream pixels through the window and
  `move()` falls back to the `drv` pixel copy, which needs a readable bus.
- `pixel_get()` returns `color::none` on SPI (the context then blends against its background color), put the
  `head::framebuffer` in front if real pixels are needed.
- `display_enable()` = AFh / AEh, `display_brightness()` = master current 87h (level / 16),
  `display_contrast()` scales the three channel contrasts and keeps the 91h / 50h / 7Dh color balance,
  `display_inverse()` = A7h / A4h. `shutdown()` sends AEh.
- Not implemented: 256 color mode, dim mode, scrolling, gray scale table.
- GAC timing: the controller gives no busy indication; if a fast bus shows artifacts after fills set `GAC_Delay`
  (hobby drivers use 1 .. 3 ms) or disable the GAC.
