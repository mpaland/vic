# SSD1351 programming summary

Source: Solomon Systech, *SSD1351 128 RGB x 128 Dot Matrix OLED/PLED Segment/Common Driver with Controller*,
Advance Information Rev 1.3, Oct 2009 (`SSD1351.pdf`, 58 pages), the controller of the 1.5" 128 x 128 and 1.27"
128 x 96 RGB OLED modules. This is the programming view of the datasheet: interfaces, RAM layout and pixel
formats, command set, orientation bits and sequences. The last section describes the vic head
`src/head/SSD1351.h` and the review against the datasheet. Related: `SSD1331.md` (96 x 64 RGB with graphic
accelerator), `SSD1322.md` (same command family, gray scale).

## 1 Overview

| Item | Value |
|---|---|
| Panel | 128 RGB x 128 (384 segments SA / SB / SC 0 .. 127, 128 commons), common cathode |
| GDDRAM | 128 x 128 x 18 bit, 65k (16 bit) or 262k (18 bit) color formats |
| Supplies | VCI 2.4 .. 3.5 V, VDDIO 1.65 V .. VCI, VDD 2.4 .. 2.6 V external or from the internal regulator (ABh, needs VCI > 2.6 V), VCC 10 .. 18 V panel (external) |
| Interfaces | 8 / 16 / 18 bit 6800 / 8080, 4-wire SPI, 3-wire SPI; write only on SPI |
| Brightness | contrast per color C1h (256 steps each), master contrast C7h (16 steps), segment current max 200 uA |
| Gray scale | 63 entry gray scale table GS1 .. GS63 (B8h, 0 .. 180 DCLK) shared by the three colors, or the linear default (B9h) |
| Clock | Fosc 2.8 MHz typ., divided by 1 .. 1024 (B3h), reset D1h; frame rate = Fosc / (D x K x MUX), K = phase 1 + phase 2 + X, default X = 134, K = 5 + 8 + 134 = 147 |
| Extras | horizontal scroll (96h / 9Eh / 9Fh), start line / offset (vertical scroll), color swap, GPIO0 / GPIO1, command lock |
| Sleep | AEh, max 10 uA per supply (VCI 50 uA with the internal VDD left on), RAM kept |

Unlike the SSD1331 the SSD1351 has no graphic acceleration commands (no line / rectangle / copy); the datasheet
lists only the scroll commands in its "Graphic Acceleration Command" table (Table 9-2).

State after RES# (section 8.2): display off, 128 MUX, no column remap (SEG0 = column 0, COM0 = row 0), start
line 0, column counter 0, normal COM scan, commands A2h, B1h, B3h, BBh, BEh (and C1h, see FDh) locked. Register
reset values are listed in section 4; note that the display offset resets to 60h (96).

## 2 Interfaces

Control pins: `CS#`, `D/C#` (0 command, 1 data or command parameter), `RES#`, `E(RD#)`, `R/W#(WR#)`, `D[17:0]`.

| BS[3:0] | Interface |
|---|---|
| xx00 | 4-wire SPI |
| xx01 | 3-wire SPI |
| 0011 / 0010 | 8 bit 6800 / 8080 |
| 0111 / 0110 | 16 bit 6800 / 8080 |
| 1111 / 1110 | 18 bit 6800 / 8080 |

BS1 / BS0 are pins, BS3 / BS2 are set by command ABh A[7:6] (reset 00 = 8 bit).

- Command parameters are sent with D/C# = 1 ("Multiple byte command: D/C# = 0 for first byte, D/C# = 1 for other
  bytes"). 5Ch has to precede RAM data, 5Dh RAM reads.
- 6800: R/W# = 1 read, data latched on the falling edge of E; 8080: rising edge of WR# / RD# latches.
- 4-wire SPI: D0 = SCLK, D1 = SDIN, D2 open, D3 .. D17 and E tied low; MSB first on the rising edge of SCLK,
  D/C# sampled on the 8th clock. "Under serial mode, only write operations are allowed."
- 3-wire SPI: 9 bit frames (D/C# bit, D7 .. D0), D/C# pin tied low.
- Reads (parallel only): one dummy read after setting the address before the first real data (Figure 8-1 / 8-4).
  Table 8-2 mentions a status read without documenting its content.

AC timing (section 13, VDDIO 1.65 V .. VCI, VCI 2.4 .. 3.5 V):

| Bus | Key values |
|---|---|
| 6800 / 8080 | tcycle >= 300 ns, address setup 10 ns, write data setup 40 ns / hold 7 ns, access <= 140 ns; 8080 RD# low >= 150 ns, WR# low >= 60 ns |
| 4-wire SPI | tcycle >= 50 ns (20 MHz), SCLK high / low >= 20 ns, D/C# setup / hold 15 ns, data setup / hold 15 ns, CS# setup 20 ns / hold 10 ns |
| 3-wire SPI | tcycle >= 50 ns, same values |
| Reset | RES# low >= 2 us (tRES 2000 ns) |

## 3 GDDRAM and pixel formats

The RAM holds 128 columns x 128 rows of 18 bit pixels `A[5:0] B[5:0] C[5:0]`; color A drives SA, B drives SB, C
drives SC (Table 8-7). Column remap reverses the column order, color remap A0h A[2] = 1 swaps the segment order
to C, B, A; the RAM word itself is unchanged. Which color is red is a property of the panel.

Write formats (Table 8-8, MSB first; X = don't care):

| Bus | Depth (A0h A[7:6]) | Transfers per pixel | Content |
|---|---|---|---|
| 8 bit / SPI | 65k (00 / 01) | 2 | `C4 C3 C2 C1 C0 B5 B4 B3`, `B2 B1 B0 A4 A3 A2 A1 A0` |
| 8 bit / SPI | 262k (10) | 3 | `x x C5..C0`, `x x B5..B0`, `x x A5..A0` |
| 16 bit | 65k | 1 | `C4..C0 B5..B0 A4..A0` on D15 .. D0 |
| 16 bit | 262k format 1 (10) | 2 | `C5..C0` on D5 .. D0, then `B5..B0` on D13 .. D8 and `A5..A0` on D5 .. D0 |
| 16 bit | 262k format 2 (11) | 3 words per 2 pixels | `C1 / B1`, `A1 / C2`, `B2 / A2` with 6 bit fields on D13 .. D8 and D5 .. D0 |
| 18 bit | 262k | 1 | `C5..C0 B5..B0 A5..A0` on D17 .. D0 |

Reads (Table 8-9) use the same layouts. In 65k mode the 16 bit word is RGB565 shaped with C in the MSBs; how the
5 bit A / C values are expanded into the 6 bit RAM cells is not specified.

Address pointer: 15h sets the column start / end (0 .. 127) and moves the column pointer to the start, 75h the
same for rows. Horizontal increment (A0h A[0] = 0): column + 1 after every pixel, at the end column back to the
start column and row + 1, after the last row and column back to the window start (Figure 10-1). Vertical
increment (A[0] = 1): row first, then column. A window is therefore a rectangle filled row major or column major
by a plain pixel stream.

Scroll note (Table 9-2): after these commands "waiting time is required for update GDDRAM content", 500 ns per
pixel.

Datasheet inconsistencies:

- A0h A[5]: Table 9-1 gives COM split enabled (1) as reset (A0h = 20h), section 10.1.5 says A[5] = 0 at reset.
- A0h A[7:6]: section 10.1.5 mentions a 256 color mode, the table has only 65k and two 262k modes.
- B3h: the table gives 1 .. 1024 (powers of two, reset divide by 2), sections 8.5.1 / 10.1.13 say 1 .. 16 with
  reset 1.
- B1h: table "5 .. 31 DCLK", section 10.1.11 "5 to 31 in the unit of 2 DCLKs".
- A4h .. A7h: section 10.1.8 labels A6h "Entire Display OFF" but describes the normal display (the table is right).
- A[4] (COM scan) is described as "A[1]" in section 10.1.5 (typo); the FDh text mentions A[2] although FDh takes a
  full byte.
- Section 8.2 lists A2h, B1h, B3h, BBh, BEh as locked, Rev 1.3 added C1h to the FDh B0h / B1h description.

## 5 Remap (A0h) and orientation

| Bit | 0 | 1 |
|---|---|---|
| A[0] | horizontal address increment | vertical address increment |
| A[1] | RAM column 0 -> SEG0 (column 0) | RAM column 127 -> SEG0 (horizontal mirror) |
| A[2] | color sequence A, B, C | C, B, A (swap) |
| A[3] | reserved | reserved |
| A[4] | scan COM0 -> COM[N-1] | scan COM[N-1] -> COM0 (vertical mirror) |
| A[5] | COM split odd/even off (sequential) | COM split odd/even on (reset per table) |
| A[7:6] | 00 / 01 65k | 10 262k, 11 262k 16 bit format 2 |

vic orientation mapping used by the head (A[7:6] = 01 and A[5] = 1 always, A[2] = `RGB_to_BGR`):

| Orientation | A[0] vertical inc. | A[1] column remap | A[4] COM scan remap | logical (x, y) -> RAM (col, row) |
|---|---|---|---|---|
| `orientation_0` | 0 | 0 | 0 | (x, y) |
| `orientation_0m` | 0 | 0 | 1 | (x, y), upright on the Adafruit modules |
| `orientation_180` | 0 | 1 | 1 | (x, y) |
| `orientation_180m` | 0 | 1 | 0 | (x, y) |
| `orientation_90` | 1 | 1 | 0 | (y, x) |
| `orientation_90m` | 1 | 1 | 1 | (y, x) |
| `orientation_270` | 1 | 0 | 1 | (y, x) |
| `orientation_270m` | 1 | 0 | 0 | (y, x) |

In the rotated modes the vertical address increment makes a logical row major pixel stream land in the
transposed RAM window.

## 6 Power, reset, gray scale

Power on (section 8.9, internal VDD, VCI = VDDIO): VCI / VDDIO on, wait >= 1 ms (t0) for VDD, RES# low >= 2 us
(t1), >= 2 us after RES# low (t2) VCC on, when VCC is stable AFh; SEG/COM are on 200 ms (tAF) after AFh.
Power off: AEh, VCC off (floating), wait tOFF (typ. 100 ms), VCI / VDDIO off; VCI / VDDIO never before VCC.

VDD regulator (section 8.10): ABh A[0] = 1 needs VCI > 2.6 V, otherwise external VDD 2.4 .. 2.6 V and ABh A[0] = 0.
Sleep with the regulator off (Figure 8-18): AEh, ABh A[0] = 0 ... ABh A[0] = 1, wait >= 1 ms, AFh; the RAM is kept,
but no RAM access without VDD.

IREF (section 8.6): `ISEG = contrast / 256 x IREF x scale factor` (scale 1 .. 16 from C7h); IREF pin at VCC - 6 V,
`R1 = (VCC - 6 V) / 12.5 uA` = 800 kOhm at VCC = 16 V for 200 uA at contrast FFh. VSL: external VSL is the
default and the only valid B4h setting; it needs the resistor / diode network on VSL (application example:
50 Ohm and two 1N4148 to ground).

Gray scale (section 8.8): each 6 bit sub-pixel value selects GS0 .. GS63; GS0 has no precharge and no current
drive, GS1 = 0 means precharge only. B8h takes 63 settings, B9h restores the linear table (step 2 DCLK).

Reference init (Adafruit): `FD 12, FD B1, AE, B3 F1, CA 7F, A0 74, 15 00 7F, 75 00 7F, A1 00, A2 00, B5 00,
AB 01, B1 32, BE 05, A6, C1 C8 80 C8, C7 0F, B4 A0 B5 55, B6 01, AF` (A0h 74h = 65k, COM split, COM scan remap,
color swap).

| Parameter | Value |
|---|---|
| VCC / VCI / VDD / VDDIO | 10 .. 18 V (typ. 16) / 2.4 .. 3.5 V / 2.4 .. 2.6 V / 1.65 V .. VCI; absolute max VCC 19 V, VCI 4.0 V, VDD 2.75 V |

## 8 The vic head `src/head/SSD1351.h`

```cpp
vic::head::SSD1351<Screen_Size_X = 128, Screen_Size_Y = 128,   // logical size, swapped for orientation_90 / 270
                   Orientation = drv::orientation_0,           // remap bits, orientation_0m for the Adafruit modules
                   RGB_to_BGR  = true>                         // A0h A[2]
SSD1351(io::handle_type device);
```

- io layer: `io::write()` option 0 = command, 1 = parameters and pixel data; `io::read()` option 1 reads two
  pixel bytes after 5Dh on the parallel bus, SPI returns `color::none`.
- init: the reference sequence with the remap from the orientation table (65k, COM split, vertical increment
  for the rotated orientations, column remap = horizontal mirror, COM scan remap = vertical mirror, color swap),
  MUX = rows - 1, clear.
- Drawing: like the SSD1331 head without GAC, the window (15h / 75h / 5Ch) is set per primitive and RGB565
  pixels are streamed in blocks of 32 with write pointer tracking.
- `display_enable()` = AFh / AEh, `display_brightness()` = C7h, `display_contrast()` scales the three channel
  contrasts (C8h 80h C8h), `display_inverse()` = A7h / A6h, `shutdown()` = AEh.
- Not covered: 262k color formats, scrolling, gray scale table, the 128 x 96 start line offset (set A1h 60h).

Crosscheck against the datasheet:

| Item | Assessment |
|---|---|
| `FD 12, FD B1` first | correct, unlocks A2h, B1h, B3h, BBh, BEh and C1h which the init writes |
| A2h 00h | needed, the reset value is 60h |
| Remap byte | correct bits (A[0], A[1], A[2], A[4], A[5] = 1, A[7:6] = 01); the orientation table matches the SSD1331 head |
| RGB565 big endian on the 8 bit bus | matches the 65k 8 bit format (C in the first byte's MSBs) |
| B3h F1h, B1h 32h, BEh 05h, B6h 01h, C7h 0Fh | valid (divide by 2 / max Fosc, phase 5 / 3 DCLK, 0.82 x VCC, 1 DCLK, 16/16) |
| B4h A0h B5h 55h | the only valid value (external VSL), comment correct |
| ABh 01h | internal VDD (needs VCI > 2.6 V) and A[7:6] = 00 = 8 bit parallel; a 16 / 18 bit parallel io layer would need ABh 41h / C1h, not supported |
| `pixel_get()` | 5Dh then two bytes; the datasheet requires a dummy read first, which the io layer has to do (the head comment does not say so, unlike the SSD1331 head) |
| Power on timing | no delay after AFh; SEG/COM come on 200 ms later, harmless for RAM writes |
| SPI clock | io layer; up to 20 MHz (50 ns cycle) per Table 13-4 |
