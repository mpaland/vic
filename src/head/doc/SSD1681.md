# SSD1681 programming summary

Source: Solomon Systech, *SSD1681 200 Source x 200 Gate Red/Black/White Active Matrix EPD Display Driver with
Controller*, Product Preview Rev 0.13, Jun 2019 (`SSD1681.pdf`, 41 pages). The SSD1681 is the 200 x 200 member
of the SSD1680 family (1.54" panels) and shares its command set, LUT format and OTP layout. It is driven by the
vic head `src/head/SSD1680.h`; the head, the orientation handling and the detailed description of the shared
commands are in `SSD1680.md`, which also has a short SSD1680 / SSD1681 comparison. This file is the complete
SSD1681 reference with the chip specific values. Being a product preview, several electrical values are still
TBD in the datasheet.

## 1 Overview

| Item | Value |
|---|---|
| Panel | 200 sources x 200 gates, 1 VCOM, 1 border output VBD; black/white/red or black/white panels |
| RAM | two planes of 200 x 200 bit = 5000 byte each: RAM 0x24 black/white, RAM 0x26 red |
| Supplies | VCI 2.2 .. 3.7 V, VDDIO = VCI, VDD 1.8 V from the internal regulator, VPP 7.5 V for OTP programming only |
| Voltage generation | internal booster (external 47 uH inductor, NMOS, 3 diodes, 1 uF capacitors, 2.2 Ohm sense resistor): VGH 10 .. 20 V, VGL = -VGH (max 40 Vpp), VSH1 / VSH2 2.4 .. 17 V, VSL -5 .. -17 V, DCVCOM -0.2 .. -3.0 V in 0.1 V |
| Interface | 4-wire SPI (BS1 = L) or 3-wire 9 bit SPI (BS1 = H), max 20 MHz write, 2.5 MHz read; BUSY output |
| Waveforms | 5 LUTs (LUT0 .. LUT3 sources, LUT4 = VCOM), 12 groups x 4 phases, TP up to 255 frames, RP / SR 1 .. 256, frame rate per group 25 .. 200 Hz; from OTP or written with 32h |
| OTP | 36 waveform settings (WS, 159 bytes each), 36 temperature ranges, display mode per WS, VCOM, 4 byte waveform version, 10 byte user ID, init code |
| Temperature | internal sensor +-2 C from -25 .. 50 C or external I2C sensor (TSDA / TSCL, POR) |
| Extras | VCI low detection, HV ready detection, VCOM sensing, CRC, auto write RAM patterns |

State after reset: the POR values of section 4 (01h C7h = 200 MUX, 11h 03h, 18h 48h external sensor, 22h FFh,
3Ch C0h border HiZ, 3Fh 02h). SW reset 12h restores all registers except deep sleep, the RAM is not changed.

## 2 Interface and BUSY

| BS1 | Interface | Pins |
|---|---|---|
| L | 4-wire SPI | CS#, D/C#, SCL, SDA |
| H | 3-wire SPI, 9 bit | CS#, SCL, SDA, D/C# tied low |

- Write: MSB first, data sampled on the rising edge of SCL; 4-wire with D/C# = 0 for the command byte and 1 for
  parameters / RAM data (stable over the whole byte); 3-wire with a leading D/C# bit per 9 bit frame.
- Read (1Bh, 27h, 2Dh, 2Eh, 2Fh, 35h): command byte, then the chip drives SDA and shifts out MSB first on the
  falling edge of SCL (2.5 MHz max). 27h (read RAM, plane selected by 41h) returns a dummy byte first.
- BUSY (Table 5-2): high while the waveform is output, during OTP programming and external sensor communication,
  during the commands marked "BUSY" in section 4, and permanently in deep sleep. No command may be sent while
  BUSY is high. 2Fh A[2] is a readable busy flag.
- Deep sleep is left only with a hardware reset; the datasheet specifies no RES# pulse width.
- SPI timing (Table 11-1): fSCL max 20 MHz write and 2.5 MHz read, CS# high between read transfers >= 50 ns,
  read data hold 0 ns; all other values are TBD. The complete SSD1680 table (`SSD1680.md` section 2) is the
  practical reference.

## 3 RAM and address counter

X counts bytes of 8 sources (bit 7 = first source of the byte), 0 .. 24 (18h) for 200 sources; Y counts gate
rows 0 .. 199 (C7h). A plane is 25 x 200 = 5000 byte.

| RAM 0x26 | RAM 0x24 | 3 color panel (Table 6-4) | B/W panel (Table 6-5) |
|---|---|---|---|
| 0 | 0 | black (LUT0) | black (LUT0) |
| 0 | 1 | white (LUT1) | white (LUT1) |
| 1 | 0 | red (LUT2) | black (LUT2 = LUT0) |
| 1 | 1 | red (LUT3 = LUT2) | white (LUT3 = LUT1) |

| Hex | Parameters | POR | Function |
|---|---|---|---|
| 11 | A[2:0] | 03h | data entry: ID[1:0] 00 Y-- X--, 01 Y-- X++, 10 Y++ X--, 11 Y++ X++; AM (A[2]) 0 = counter runs along X, 1 = along Y |
| 44 | XSA[5:0], XEA[5:0] | 00h, 15h (as printed) | RAM X window in bytes; 200 sources need 00h .. 18h |
| 45 | YSA[7:0], YSA[8], YEA[7:0], YEA[8] | 000h, 127h (as printed) | RAM Y window; 200 gates need 000h .. 0C7h |
| 4E | XAD[5:0] | 00h | X address counter |
| 4F | YAD[7:0], YAD[8] | 000h | Y address counter |
| 24 | data | - | write RAM 0x24: 1 = white, 0 = black |
| 26 | data | - | write RAM 0x26: 1 = red, 0 = black or white |
| 27 | read | - | read RAM, first byte dummy |
| 41 | A[0] | 0 | read RAM option: 0 = RAM 0x24, 1 = RAM 0x26 |
| 46 / 47 | A[7] first value, A[6:4] height, A[2:0] width | 00h | auto write RAM 0x26 / RAM 0x24 with a regular pattern; height and width 8, 16, 32, 64, 128, 200 (codes 5 .. 7 all = 200); BUSY |

The POR window values 15h / 127h in the command table are the SSD1680 values (176 x 296), copied into this
preliminary datasheet; always set 44h / 45h explicitly. The counter moves after every byte in the AM direction
with the ID signs and wraps inside the window (see `SSD1680.md` section 3, the SSD1681 datasheet has no
separate description of 11h / 44h / 45h / 4Eh / 4Fh). With 11h 03h a frame is 200 rows of 25 bytes. Set
4Eh / 4Fh before each of 24h and 26h, they share the counter.

## 4 Command set

D/C# = 0 for the command byte, D/C# = 1 for parameters. "BUSY" = BUSY is high while the command runs.

|---|---|---|---|

| 03 | A[4:0] | 00h | VGH: 00h 20 V, 03h 10 V .. 17h 20 V in 0.5 V steps |

| 10 | A[1:0] | 00h | deep sleep: 01h mode 1 (RAM retained, not accessible), 03h mode 2 (RAM lost); BUSY stays high, hardware reset to leave |

## 5 Orientation

As on the SSD1680: 01h GD / SM / TB set the gate order and direction, 11h ID / AM the address direction; with
byte wide X addressing a 90 degree rotation is not possible in the controller. The vic head keeps 11h 03h and
rotates in software, the mapping table is in `SSD1680.md` section 5. 200 x 200 is square, so all eight
orientations use `Screen_Size_X = Screen_Size_Y = 200`.

## 6 Sequences and waveform

General operation flow (section 8.1, Figure 8-1):

1. VCI on, wait 10 ms.
2. Hardware reset, SW reset 12h, wait 10 ms.
3. 01h gate driver, 11h / 44h / 45h RAM size, 3Ch border.
4. 18h temperature sensor, load the waveform from OTP with 22h / 20h (or write it with 32h), wait BUSY low.
5. Image: 4Eh, 4Fh, 24h, 26h; soft start 0Ch; drive with 22h / 20h, wait BUSY low.
6. Deep sleep 10h, power off.

Waveform setting (section 6.7): 159 bytes per WS, bytes 0 .. 152 = 32h, 153 = 3Fh, 154 = 03h, 155 .. 157 = 04h,
158 = 2Ch; later register writes override the OTP. The 153 LUT bytes (Figure 6-6): 0 .. 59 VS for LUT0 .. LUT4
(12 bytes per LUT, one byte per group, phases A .. D as 2 bit fields with A in bits 7:6); 60 .. 143 per group
TP[nA], TP[nB], SR[nAB], TP[nC], TP[nD], SR[nCD], RP[n]; 144 .. 149 FR (two groups per byte); 150 .. 152 XON bits.
Source levels 00 VSS, 01 VSH1, 10 VSL, 11 VSH2; VCOM levels 00 DCVCOM, 01 VSH1 + DCVCOM, 10 VSL + DCVCOM.
TP 0 = phase skipped; RP / SR value + 1 repeats. The datasheet gives the FR range as 0 .. 7 without a table (the
SSD1680 table maps 1h .. 8h to 25 .. 200 Hz). The text of section 6.7 does not list XON and EOPT among the LUT
parameters although Figure 6-6 contains them.

Temperature search (section 6.9): 12 bit value in 1/16 C, TR0 .. TR35 are searched and the last range with
`lower < T <= upper` wins; no match means no update. OTP map: WS0 .. WS35 at 0 .. 5723 (159 bytes each), then
TR0 .. TR35 (3 bytes each).

## 8 The vic head `src/head/SSD1680.h` on the SSD1681

Typical instance: `vic::head::SSD1680<200, 200, drv::orientation_0, Tri_Color>`; `Source_S8` defaults to false
for the 200 pixel width. The head sends `12h`, `01h C7h 00h 00h`, `11h 03h`, `44h 00h 18h`,
`45h 00h 00h C7h 00h`, `3Ch 05h`, `21h 00h 00h`, `18h 80h`; `present()` writes 5000 bytes per plane after
`4Eh 00h, 4Fh 00h 00h` and refreshes with `22h F7h, 20h`. Details and the general crosscheck in `SSD1680.md`
section 8.

SSD1681 specific crosscheck:

| Item | Assessment |
|---|---|
| 01h, 44h, 45h for 200 x 200 | correct (C7h, 0 .. 18h, 0 .. C7h) |
| 21h with two bytes `00h 00h` | the SSD1681 table defines one parameter byte (the POR text mentions a B byte); B = 00h is harmless, `Source_S8 = true` would write an undocumented bit |
| 2Bh 04h 63h | not sent; the datasheet says both bytes "should be set" to reduce VCOM glitches; the OTP / reference flow does not list it, so its effect on the 1.54" panels is unclear |
| 3Fh / 03h / 04h / 2Ch | not sent, the OTP waveform setting is loaded by 22h F7h |
| 0Ch soft start | not sent (the flow step 5 lists it), POR values used |
| BUSY handling, deep sleep, reset | as on the SSD1680 (`SSD1680.md` section 8) |
| `static_assert` | checks width <= 200 and height <= 296 (union of both chips), 200 x 296 would pass but fits neither chip |
