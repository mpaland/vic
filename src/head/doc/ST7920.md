# ST7920 programming summary

Source: Sitronix, *ST7920 Chinese Fonts built in LCD controller/driver*, V3.3, 2004/03/29 (`ST7920.pdf`, 51
pages). The ST7920 drives the common 128 x 64 graphic LCD modules (and 192 x 32 / 256 x 32 variants); it has a
text mode with a Chinese font ROM and a graphic mode with a 64 x 256 bit GDRAM. This is the programming view of
the datasheet: interfaces, RAM maps, both instruction sets, sequences and the electrical values a driver needs.
The vic head `src/head/ST7920.h` uses the graphic mode; the last section describes it and what the review
against the datasheet found. The text mode instruction set is a superset of the HD44780 one, see `HD44780.md`.

## 1 Overview

| Item | Value |
|---|---|
| Drivers | 32 common x 64 segment per chip (plus a 33rd common for icons, 1/33 duty drive); with ST7921 segment extenders up to 32 x 256; 128 x 64 modules use the 2 line (2 x 32 row) arrangement with segment extenders |
| RAM | DDRAM 64 x 16 bit (text, 4 lines x 16 characters, 2 lines visible), CGRAM 64 x 16 bit (4 user characters 16 x 16), GDRAM 64 x 256 bit (graphic), IRAM (icons) |
| Font ROM | CGROM 2 Mbit: 8192 Chinese 16 x 16 characters (GB / BIG5), HCGROM 16 Kbit: 126 half width 8 x 16 characters |
| Variants | ST7920-0A BIG5 traditional, ST7920-0B GB simplified, ST7920-0C GB, BIG5 and Japanese |
| Supplies | VDD 2.7 .. 5.5 V, internal or external LCD voltage: built in voltage doubler (VOUT = 2 x VD2), VLCD = V0 - VSS 3.0 .. 7 V, bias levels V1..V4 from external resistors |
| Interfaces | 8 bit and 4 bit parallel (PSB = 1), clock synchronised serial (PSB = 0: CS, SID, SCLK), serial is write only |
| Oscillator | internal RC 540 kHz with external resistor (33 kOhm at 5 V, 18 kOhm at 2.7 V) or external clock on OSC1; instruction time 72 us (clear 1.6 ms) |
| Reset | automatic power on reset and XRESET pin (low active) |
| Power | normal typ. 450 uA, standby max. 30 uA (VDD = 5 V) |

Register state after reset (p. 18): entry mode I/D = 1, S = 0; display, cursor and blink off (D = C = B = 0);
no shift; function set DL = 1 (8 bit), RE = 0 (basic instructions); SR = 0 (CGRAM / IRAM address enabled);
reverse R1 R0 = 00 (all lines normal); G = 0 (graphic display off). RAM contents are not specified.

## 2 Interfaces

Interface selection (p. 7, 10): `PSB` = 1 parallel, 0 serial. In parallel mode the DL bit of function set selects
8 bit (DL = 1, reset value) or 4 bit (DL = 0). Pins: `RS` (CS in serial mode), `RW` (SID), `E` (SCLK),
`D7..D0`, `XRESET`. RS and RW have internal pull ups (22 .. 32 uA at 3 V, 75 .. 85 uA at 5 V), E has none (p. 46).

Parallel bus, like the HD44780 (p. 10, 25):

| RS | RW | Operation |
|---|---|---|
| 0 | 0 | write instruction register IR |
| 0 | 1 | read busy flag (DB7) and address counter (DB6..DB0) |
| 1 | 0 | write data register DR (DDRAM / CGRAM / IRAM / GDRAM) |
| 1 | 1 | read data register DR |

- 8 bit: one E cycle per byte. 4 bit: every byte is two transfers on DB7..DB4, high nibble first, DB3..DB0
  unused; the busy flag / address read and RAM reads are also two transfers.
- Busy flag: while BF = 1 no new instruction is accepted (p. 10); either poll BF or wait the execution time
  (section 4). The busy flag read itself takes 0 us.
- Reads: the first data read after an address set is a dummy read, the following reads need none until the next
  address set (p. 22, the timing diagrams on p. 25 show it). The RAM is 16 bit wide: every address is read and
  written as two bytes, high byte first, the address counter moves after the second byte.

Serial bus (PSB = 0, p. 26): `CS` = the RS pin, `SID` = the RW pin, `SCLK` = the E pin; write only, no busy flag
and no read back. CS is **high active**: SCLK is accepted only while CS = 1, CS = 0 resets the serial counter and
discards a partial transfer. With a single ST7920 CS may be tied high and only SCLK and SID are needed. SID is
sampled on the rising edge of SCLK (the demo code sets SID, then raises SCLK). A transfer is a sync byte
`1 1 1 1 1 RW RS 0` (F8h = write instruction, FAh = write data; 5 ones synchronise and reset the bit counter)
followed by the data byte split into two bytes, high nibble then low nibble, each in the upper four bits
(`D7 D6 D5 D4 0 0 0 0`, `D3 D2 D1 D0 0 0 0 0`), 24 clocks in total. The serial clock is asynchronous to the
internal clock and there is no instruction buffer: the host must wait the execution time of each byte before the
next one. The datasheet's 8051 demo (p. 27, 28) sends one sync byte per instruction / data byte, framed by CS; it
does not say whether several data bytes may follow one sync byte.

Parallel timing (p. 41 .. 43):

| Symbol | Parameter | VDD = 4.5 V | VDD = 2.7 V |
|---|---|---|---|
| TC | E cycle time (write / read) | >= 1200 ns | >= 1800 ns |
| TPW | E pulse width (write / read) | >= 140 ns | >= 160 ns / >= 320 ns |
| TR, TF | E rise / fall | <= 25 ns | <= 25 ns |
| TAS / TAH | RS, RW setup / hold | >= 10 ns / >= 20 ns | >= 10 ns / >= 20 ns |
| TDSW / TH | write data setup / hold | >= 40 ns / >= 20 ns | >= 40 ns / >= 20 ns |
| TDDR | read data delay | <= 100 ns | <= 260 ns |

Serial timing (p. 44, 45):

| Symbol | Parameter | VDD = 4.5 V | VDD = 2.7 V |
|---|---|---|---|
| TSCYC | SCLK cycle | >= 400 ns (2.5 MHz) | >= 600 ns (1.67 MHz) |
| TSHW / TSLW | SCLK high / low | >= 200 ns | >= 300 ns |
| TSDS / TSDH | SID setup / hold | >= 40 ns | >= 40 ns |
| TCSS / TCSH | CS setup / hold | >= 60 ns | >= 60 ns |

## 3 RAM

The address counter AC points into DDRAM, CGRAM, IRAM or GDRAM, depending on the last address instruction, and
increments or decrements (entry mode I/D) after each 16 bit access (p. 10, 22). AC is read with the busy flag.

DDRAM (p. 11): 64 x 16 bit, 4 lines of 16 words; each word holds one 16 x 16 character or two 8 x 16 characters
(high byte = left). Set DDRAM address is `1 0 AC5..AC0` (AC6 fixed to 0), the command bytes per line are:

| Text line | Command bytes (= address) | Content |
|---|---|---|
| 1 | 80h .. 8Fh | 16 words = 16 full width or 32 half width characters (256 dots) |
| 2 | 90h .. 9Fh | |
| 3 | A0h .. AFh | |
| 4 | B0h .. BFh | |

Only 2 lines (32 commons of 16 dots) are displayed at a time; the vertical scroll address (section 4) moves the
window. Not in the datasheet but following from the folded 32 x 256 wiring of the 128 x 64 modules (the same fold
as the GDRAM below): screen line 1 = 80h..87h, line 2 = 90h..97h, line 3 = 88h..8Fh, line 4 = 98h..9Fh, 8 full
width or 16 half width characters per screen line.

Character codes (p. 11, 13), written as two bytes, high byte first:

| Code | Font | Rule |
|---|---|---|
| 02h .. 7Fh (one byte) | HCGROM half width 8 x 16 (Table 6) | two characters per word, any byte position |
| 0000h, 0002h, 0004h, 0006h | CGRAM user character 0 .. 3 | full word, must start at the high byte of a word |
| A140h .. D75Fh | CGROM BIG5 16 x 16 | full word, word aligned |
| A1A0h .. F7FFh | CGROM GB 16 x 16 | full word, word aligned |

A 16 x 16 character written to the low byte position is displayed incorrectly (Table 4). The datasheet calls
the 8 x 16 font "half height" (and "16x8" in the feature list); the characters are 8 dots wide and 16 high.

CGRAM (p. 13, Table 5): 64 words of 16 bit, 4 characters of 16 rows. CGRAM address bits 5..4 = character
(= DDRAM code bits 2..1, code bits 15..4 must be 0, bits 3 and 0 are don't care), bits 3..0 = row 0..15. D15 is
the left dot. Row 15 (the 16th row) is ORed with the cursor. Write: (SR = 0) set CGRAM address `01 AC5..AC0`
(40h | address), then two bytes per row, high byte first.

GDRAM (p. 12, 15, 24): the GDRAM is 64 rows (vertical address 0 .. 63) x 16 words of 16 bit (horizontal address
0 .. 15), bit 15 of a word is the left pixel (Table 7). The datasheet write procedure is: set vertical address Y,
set horizontal address X (two consecutive address bytes, extended instruction set), write D15..D8, write D7..D0.
The vertical address does not increment (p. 24), so every row needs a new address pair. Only 32 rows are driven
at a time; the datasheet shows the RAM as a plain 64 x 16 word matrix (Table 7, the text refers to a "Table-8" that does not exist). A 128 x 64 panel
shows the upper 32 rows from vertical addresses 0 .. 31, horizontal addresses 0 .. 7, and the lower 32 rows from
the SAME vertical addresses 0 .. 31 at horizontal addresses 8 .. 15 (module wiring of the 256 segments as two
128 pixel halves). After setting the address the words are written high byte first; the horizontal address
increments after every word and wraps after 15, so one vertical address takes a row of the upper half (16 bytes)
followed by the matching row of the lower half (16 bytes). Text and graphics can be shown together (mix mode);
the datasheet does not describe how the two are combined.

IRAM: the icon RAM is addressed with SR = 0 and set IRAM address (extended instruction set) and drives the 33rd
common (the application on p. 50 uses 14 icons on 14 segments and 1 common). V3.3 no longer contains the IRAM
map (the revision history refers to an icon table that was replaced).

## 4 Instruction set

All instructions are written with RS = 0, RW = 0 (except busy flag / data access). Execution times at
fOSC = 540 kHz (p. 16, 17).

Basic instruction set (RE = 0):

| Instruction | Code (DB7 .. DB0) | Hex | Time | Function |
|---|---|---|---|---|
| Clear | `0000 0001` | 01 | 1.6 ms | fill DDRAM with 20h (space), AC = 00h, I/D = 1 |
| Home | `0000 001x` | 02 | 72 us | AC = 00h, cursor to origin, DDRAM unchanged |
| Entry mode | `0000 01 I/D S` | 04 .. 07 | 72 us | I/D = 1 increment (cursor right), S = 1 shift the whole display on write / read (left with I/D = 1, right with I/D = 0) |
| Display on/off | `0000 1 D C B` | 08 .. 0F | 72 us | D display, C cursor, B blink of the character at the cursor; DDRAM unchanged |
| Cursor / display shift | `0001 S/C R/L xx` | 10 .. 1F | 72 us | S/C R/L = 00 cursor left (AC - 1), 01 cursor right (AC + 1), 10 display left, 11 display right (cursor follows, AC unchanged) |
| Function set | `001 DL x RE x x` | 30 (8 bit), 20 (4 bit) | 72 us | DL = 1 8 bit bus, RE = 1 extended instruction set |
| Set CGRAM address | `01 AC5..AC0` | 40 .. 7F | 72 us | AC = CGRAM address 00h .. 3Fh, needs SR = 0 |
| Set DDRAM address | `10 AC5..AC0` | 80 .. BF | 72 us | AC = DDRAM address (AC6 = 0), see section 3 |
| Read busy flag / AC | RS = 0, RW = 1: `BF AC6..AC0` | - | 0 us | BF = 1 busy |
| Write RAM | RS = 1, RW = 0: data | - | 72 us | DDRAM / CGRAM / IRAM / GDRAM, two bytes per address |
| Read RAM | RS = 1, RW = 1: data | - | 72 us | dummy read after an address set |

Extended instruction set (RE = 1):

| Instruction | Code (DB7 .. DB0) | Hex | Time | Function |
|---|---|---|---|---|
| Standby | `0000 0001` | 01 | 72 us | enter standby (COM1..32 halted), any following instruction ends it, DDRAM retained |
| Scroll / RAM address select | `0000 001 SR` | 02, 03 | 72 us | SR = 1 vertical scroll address, SR = 0 IRAM (extended) / CGRAM (basic) address |
| Reverse | `0000 01 R1 R0` | 04 .. 07 | 72 us | toggle the reverse display of text line R1 R0 (00 = line 1 .. 11 = line 4); first call reverses, second restores |
| Extended function set | `001 DL x 1 G 0` | 34, 36 | 72 us | G = 1 graphic display on, RE stays 1 |
| Set IRAM / scroll address | `01 AC5..AC0` | 40 .. 7F | 72 us | SR = 1: vertical scroll displacement AC5..AC0; SR = 0: IRAM address |
| Set GDRAM address | `10 AC5..AC0`, then `1000 AC3..AC0` | 80 .. BF, 80 .. 8F | 72 us | vertical address 0 .. 63 first, then horizontal address 0 .. 15 |

Notes:

- The same codes mean different things in the two sets: 01h is clear with RE = 0 but standby with RE = 1, 80h..BFh
  is a DDRAM address with RE = 0 and a GDRAM address with RE = 1. RE keeps its value between instructions; change
  it only with the function set instruction (basic 30h, extended 34h, extended + graphic on 36h).
- DL and RE must not change in the same function set, change DL first, then RE (p. 21); DL, RE and G must not
  change at once, change DL or G first, then RE (p. 24). So graphic on is 34h then 36h, and back to basic is 34h
  (graphic off) then 30h.
- The extended instruction table on p. 17 lists the horizontal address format above the vertical one; the text on
  p. 12 and p. 24 says vertical first, then horizontal.
- The 4 bit function set is 20h; in 4 bit mode the extended set is 24h / 26h.

## 5 Orientation

The ST7920 has no segment or common direction bits and no rotation; the only display transformations are the
text shift, the vertical scroll and the line reverse. Any orientation of the graphics has to be made in software.
The vic head renders all eight `orientation_*` values in its framebuffer (section 8); `orientation_0` is the
upright 128 x 64 module.

## 6 Reset, power and initialisation

Reset (p. 37): XRESET pulse width Trw 10 us, reset start time Tres (VDD high to XRESET low) 50 ns; the table
gives no min / max column. The chip also has an automatic power on reset.

Init flow, 8 bit bus (p. 35):

| Step | Instruction | Wait after |
|---|---|---|
| Power on | | > 40 ms, then XRESET low -> high |
| 1 | function set `0011 x0xx` (30h) | > 100 us |
| 2 | function set 30h | > 37 us |
| 3 | display on/off `0000 1DCB` | > 100 us |
| 4 | display clear 01h | > 10 ms |
| 5 | entry mode set `0000 01 I/D S` | initialisation end |

Init flow, 4 bit bus (p. 36): power on, > 40 ms, XRESET; function set `0010` as a single nibble, > 100 us;
function set as two nibbles `0010`, `x0xx`, > 100 us; display on/off `0000`, `1DCB`, > 100 us; clear `0000`,
`0001`, > 10 ms; entry mode `0000`, `01 I/D S`. The datasheet has no serial flow; with PSB = 0 the same instructions
are sent in serial frames. Note that the flow asks > 10 ms after clear while the instruction table gives 1.6 ms.

Graphic mode start (from the p. 12 procedure and the RE / G rule): 34h (extended), write the GDRAM row by row
(address pair, 32 bytes), 36h (graphic display on).

LCD power (p. 8, 9, 37, 38): the built in doubler generates VOUT = 2 x VD2 (example VD2 = 2.7 V, VOUT = 5.4 V)
with 4.7 uF capacitors on CAP1P/CAP1M and VOUT (CAP2P open); V0..V4 come from an external resistor divider with
VDD >= V0 >= V1 >= V2 >= V3 >= V4, and the sum of the bleeder resistors R1..R5 should be > 20 kOhm when the doubler
is used. The contrast is set with the V0 voltage (external potentiometer), there is no software contrast. Drive
is 1/33 duty, 1/5 bias; at 540 kHz one clock is 1.85 us and a frame 1.85 us x 300 x 33 = 18.3 ms (55 Hz). XOFF is
"reserved, no connection" in V3.3. Standby (extended 01h) halts the commons; the older sleep mode was removed in
V3.0.

## 8 The vic head `src/head/ST7920.h`

```cpp
vic::head::ST7920<Screen_Size_X = 128, Screen_Size_Y = 64,   // logical size, 64 x 128 for orientation_90 / 270
                  Orientation = drv::orientation_0>           // done in software
ST7920(io::handle_type device);
```

- io layer: `io::write()` option 0 = instruction (RS = 0), 1 = data (RS = 1); the serial sync byte and the
  nibble split are the io layer's job, as is the 72 us pacing (or the busy flag on the parallel bus). The head
  only waits after power on (50 ms), the first function set (1 ms) and the clear (2 ms).
- init: 30h, 30h, 0Ch (display on), 01h, 06h, 34h (extended), 36h (graphic on), clear, present.
- Framebuffer: 1024 bytes row organised (16 bytes per row, bit 7 = left pixel) in physical orientation.
  `present()` writes 32 vertical addresses: 80h | y, 80h, 16 bytes of row y, 16 bytes of row y + 32.
- Orientation: `to_phys()` maps logical to physical coordinates like the other monochrome heads, the `m`
  orientations mirror the panel top/bottom after the rotation.
- `display_enable()` toggles the graphic display bit (36h / 34h), `shutdown()` = 34h, 30h, 08h.
- Not covered: text mode, CGRAM, scrolling, standby.

Review against the datasheet:

1. The init order follows the 8 bit flow (function set twice, display on/off, clear, entry mode) and then enters
   graphic mode with 34h before 36h; `shutdown()` leaves it with 34h before 30h. Both respect the rule that RE must
   not change together with DL or G. The clear (01h) is sent with RE = 0, so it is not mistaken for standby.
2. Waits: 50 ms after power on (> 40 ms) and 1 ms after the first function set (> 100 us) are fine. The flow asks
   > 100 us after display on/off, the head relies on the io layer pacing (72 us per byte). After clear the head
   waits 2 ms, which covers the 1.6 ms of the instruction table but not the > 10 ms of the init flow (p. 35, 36).
3. XRESET is not driven by the head (io layer / board), the automatic power on reset is relied on otherwise.
4. Every function set has DL = 1 (30h, 34h, 36h) and there is no single nibble transfer, so the 4 bit parallel
   bus is not supported; the head works with the 8 bit bus and the serial interface.
5. GDRAM addressing (vertical address, then horizontal address 0, 32 bytes high byte first per vertical address,
   a new address for every row because the vertical address does not increment) matches the procedure on p. 12
   and p. 24. The split of the 128 x 64 panel into horizontal addresses 0 .. 7 (upper half) and 8 .. 15 (lower half)
   is module wiring, not shown in the datasheet's Table 7.
6. Throughput: `present()` is 32 x (2 + 32) = 1088 transfers of 72 us, about 78 ms per frame, before the serial
   overhead. In serial mode there is no busy flag, the io layer has to delay; CS is high active and the serial
   clock is limited to 2.5 MHz (4.5 V) / 1.67 MHz (2.7 V). The head hands 2 byte command blocks and 16 byte data
   blocks to `io::write()`; one sync byte per byte (the datasheet demo) is the safe framing.
7. `display_enable()` only switches G; the display bit D stays 1 and the DDRAM holds spaces from the clear, so
   nothing else is visible. `shutdown()` turns the display off (D = 0) but does not use standby (extended 01h,
   max. 30 uA).
