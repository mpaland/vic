# PCD8544 programming summary

Source: Philips Semiconductors, *PCD8544 48 x 84 pixels matrix LCD controller/driver*, Product specification,
1999 Apr 12 (`PCD8544.pdf`, 32 pages). The PCD8544 is the controller of the Nokia 5110 / 3310 displays. This is
the programming view of the datasheet: serial interface, RAM layout, instruction set, LCD voltage generation and
sequences. The last section describes how the vic head `src/head/PCD8544.h` uses the controller and what the
review against the datasheet found. Related page organised monochrome controllers: `ST7565.md`, `SSD1306.md`.

## 1 Overview

| Item | Value |
|---|---|
| Panel | 84 columns (C0..C83) x 48 rows (R0..R47), 1/48 mux, one chip, no cascading |
| RAM | 84 x 48 bit = 504 byte in 6 banks of 8 rows (DDRAM, static, write only) |
| Supplies | VDD 2.7 .. 3.3 V (logic), VLCD 6.0 .. 8.5 V generated internally or 6.0 .. 9.0 V external, VSS |
| LCD voltage | on-chip charge pump (HV generator) programmed by Vop (VLCD = 3.06 V + Vop x 0.06 V, Vop up to 8.5 V generated), on-chip bias generator 1/(n + 4), 4 selectable temperature coefficients |
| Interface | serial only (SCE, D/C, SDIN, SCLK), MSB first, up to 4 Mbit/s, write only |
| Oscillator | on-chip (OSC tied to VDD), typ. 34 kHz, or external clock 10 .. 100 kHz on OSC |
| Temperature | -25 .. +70 C |
| Reset | RES low within 100 ms after power on (section 8.1, the AC table says 30 ms, see section 6); after reset: power down, horizontal addressing, display blank, Vop = 0 |

There are no mode pins: the PCD8544 has only the serial interface. T1, T3 and T4 go to VSS, T2 is left open
(test pads, section 6.1.6). VDD1/VDD2, VSS1/VSS2 and VLCD1/VLCD2 are pairs that must be connected together.
Unused row and column outputs are left unconnected.

State after RES (section 8.2): power down (PD = 1), horizontal addressing (V = 0), basic instruction set (H = 0),
display blank (D = E = 0), X = 0, Y = 0, temperature coefficient 0 (TC = 00), bias system BS = 000, Vop = 0 (the
HV generator is off, VLCD = 0). The RAM content is undefined after power on and is not cleared by RES.

## 2 Interface

Pins (section 6.1): `SCE` chip enable (low active), `D/C` mode select (0 = command, 1 = RAM data), `SDIN` serial
data, `SCLK` serial clock (0 .. 4.0 Mbit/s), `RES` reset (low active), `OSC` oscillator input. The controller never
drives the bus, there is no read back of any kind (no status, no RAM read, no busy flag), and the datasheet
specifies no execution times or waits between bytes.

Protocol (section 8, Figs. 8 .. 13):

- Bytes are 8 bit, MSB (DB7) first; SDIN is sampled on the rising edge of SCLK (SPI mode 0 or 3).
- D/C is read with the eighth SCLK pulse of each byte ("during the last bit"), so D/C may change during a
  stream and every byte carries its own D/C.
- While SCE is high the serial interface is held initialised: SCLK pulses are ignored and the interface draws no
  power. A falling edge on SCE starts a transmission with bit 7.
- If SCE stays low after the last bit, the next SCLK rising edge is bit 7 of the next byte, so any number of
  command and data bytes can be sent in one SCE low phase (Fig. 11). Pulling SCE high between bytes
  resynchronises the bit counter (Fig. 12).
- A RES pulse aborts a transmission: no data is written, the registers are cleared; if SCE is low after the
  rising edge of RES the interface expects bit 7 of a new byte (Fig. 13).
- After every data byte the address counter increments (section 3). Commands can be sent in any order.

Serial bus timing (section 12, VDD = 3.0 V +/- 10 %, levels 20 % .. 80 % of VDD, rise / fall <= 10 ns):

| Symbol | Parameter | Min |
|---|---|---|
| fSCLK | clock frequency | 0 .. 4.00 MHz (max) |
| Tcy | SCLK cycle | 250 ns |
| tWH1 / tWL1 | SCLK high / low | 100 ns / 100 ns |
| tsu2 | SCE setup (SCE low to first SCLK rising edge) | 60 ns |
| th2 | SCE hold (last SCLK to SCE high) | 100 ns |
| tWH2 | SCE high time | 100 ns |
| th5 | SCE start hold: previous SCLK rising edge to SCE falling edge | 100 ns |
| tsu3 / th3 | D/C setup / hold (around the 8th rising edge) | 100 ns / 100 ns |
| tsu4 / th4 | SDIN setup / hold | 100 ns / 100 ns |

## 3 RAM and addressing

The DDRAM is 6 banks (Y = 0 .. 5) of 84 bytes (X = 0 .. 83); a byte holds 8 vertical pixels of one column, bit 0
(LSB) = top row of the bank, bit 7 = bottom row, 1 = pixel on (Figs. 3, 4). Bank 0 is R0..R7 at the top of the
display, bank 5 is R40..R47; the X address corresponds directly to the column output Cx. Addresses outside
X 0 .. 83 (53h) and Y 0 .. 5 are not allowed (section 7.7).

The address counter (X6..X0, Y2..Y0) is set by the set X / set Y commands and increments after every data byte
according to the V bit of function set (section 7.7, Figs. 5, 6):

| Mode | V | Pointer movement after a byte |
|---|---|---|
| Horizontal (reset) | 0 | X++; after X = 83 X wraps to 0 and Y++ |
| Vertical | 1 | Y++; after Y = 5 Y wraps to 0 and X++ |

After the very last address (X = 83, Y = 5) both pointers wrap to (0, 0) in either mode. A whole frame in
horizontal mode is therefore 504 bytes from (0, 0) in bank major order, `data[bank * 84 + x]`; in vertical mode
the order is column major, `data[x * 6 + bank]`. There is no window, no start line / scroll register and no
icon row.

## 4 Instruction set

All commands are single bytes with D/C = 0, there are no parameter bytes. The H bit of function set selects
which half of the table is decoded: with H = 0 display control, set Y and set X; with H = 1 temperature control,
bias system and set Vop. NOP, function set and write data work in both modes (section 8.3.3, Table 1).

| Instruction | H | D/C | Code (DB7 .. DB0) | Hex | Function |
|---|---|---|---|---|---|
| NOP | 0/1 | 0 | `0000 0000` | 00 | no operation |
| Function set | 0/1 | 0 | `0010 0 PD V H` | 20 .. 27 | PD = 1 power down, V = 1 vertical addressing, H = 1 extended instruction set |
| Write data | 0/1 | 1 | `D7 .. D0` | - | write one byte to the DDRAM at (X, Y), then increment |
| Reserved | 0 | 0 | `0000 01xx` | 04 .. 07 | do not use |
| Display control | 0 | 0 | `0000 1 D 0 E` | 08, 09, 0C, 0D | DE = 00 blank (08h), 10 normal (0Ch), 01 all segments on (09h), 11 inverse video (0Dh) |
| Reserved | 0 | 0 | `0001 xxxx` | 10 .. 1F | do not use |
| Set Y address | 0 | 0 | `0100 0 Y2 Y1 Y0` | 40 .. 45 | bank 0 .. 5 |
| Set X address | 0 | 0 | `1 X6 .. X0` | 80 .. D3 | column 0 .. 83 |
| Reserved | 1 | 0 | `0000 0001` | 01 | do not use |
| Reserved | 1 | 0 | `0000 001x` | 02, 03 | do not use |
| Temperature control | 1 | 0 | `0000 01 TC1 TC0` | 04 .. 07 | VLCD temperature coefficient 0 .. 3 |
| Reserved | 1 | 0 | `0000 1xxx` | 08 .. 0F | do not use |
| Bias system | 1 | 0 | `0001 0 BS2 BS1 BS0` | 10 .. 17 | bias 1/(n + 4), n = 7 - BS, see Table 4 below |
| Reserved | 1 | 0 | `01xx xxxx` | 40 .. 7F | do not use |
| Set Vop | 1 | 0 | `1 Vop6 .. Vop0` | 80 .. FF | LCD operation voltage, 0 switches the charge pump off |

Codes not listed (for example 28h .. 3Fh) are not defined by the datasheet. Function set and its H bit stay in
effect until the next function set, so a typical stream is `21h, <extended commands>, 20h, <basic commands>`.

Function set bits (section 8.3): PD = 1 (power down) puts all LCD outputs to VSS (display off), switches the bias
generator, the VLCD generator and the oscillator off (an external clock may keep running, VLCD may be
disconnected) while the serial bus and the commands keep working; before entering power down the RAM should be
filled with 0 to reach the specified current. PD = 0 is "chip active". V selects the addressing mode of
section 3, H the instruction set.

Bias system (section 8.8, Table 4): the bias resistor chain is R - R - nR - R - R, giving a 1/(n + 4) bias.

| BS2 BS1 BS0 | Hex | n | Bias | Recommended mux rate |
|---|---|---|---|---|
| 000 | 10 | 7 | 1/11 | 1:100 |
| 001 | 11 | 6 | 1/10 | 1:80 |
| 010 | 12 | 5 | 1/9 | 1:65 |
| 011 | 13 | 4 | 1/8 | 1:48 |
| 100 | 14 | 3 | 1/7 | 1:40 / 1:34 |
| 101 | 15 | 2 | 1/6 | 1:24 |
| 110 | 16 | 1 | 1/5 | 1:18 / 1:16 |
| 111 | 17 | 0 | 1/4 | 1:10 / 1:9 / 1:8 |

For the PCD8544's own 1:48 mux the datasheet computes the optimum n = sqrt(48) - 3 = 3.93, rounded to 4, i.e.
BS = 011 (13h) and 1/8 bias (equation 1). The bias levels are V1 = VLCD, V2 = (n + 3)/(n + 4), V3 = (n + 2)/(n + 4),
V4 = 2/(n + 4), V5 = 1/(n + 4) of VLCD, V6 = VSS (Table 5; for 1/8 bias 7/8, 6/8, 2/8, 1/8 x VLCD). Many module
drivers (Adafruit, Sparkfun) use BS = 100 (14h) for the 5110 modules instead.

Temperature control (section 7.8, 8.7): the coefficient of the internally generated VLCD is selected by TC1 TC0,
typ. TC0 = 1, TC1 = 9, TC2 = 17, TC3 = 24 mV/K (DC table, VDD = 2.85 V, VLCD = 7.0 V). VLCD has to rise at low
temperatures to keep the contrast; the datasheet gives no sign convention for the coefficients.

Set Vop (section 8.9): VLCD = a + Vop x b with a = 3.06 V, b = 0.06 V, Vop = 00h .. 7Fh. The datasheet quotes a
programming range of "3.00 to 10.68" V at room temperature (10.68 = 3.06 + 127 x 0.06; the 3.00 lower end does not
match a = 3.06, and Vop = 0 turns the charge pump off). The internally generated VLCD is limited to 8.5 V (Vop
<= 5Ah at room temperature), and since VLCD increases at lower temperature Vop must be chosen so that 8.5 V is not
exceeded at -25 C. Optimum for 1:48: VLCD = (1 + sqrt(48)) / sqrt(2 x (1 - 1/sqrt(48))) x Vth = 6.06 x Vth, Vth
being the threshold voltage of the liquid crystal (equation 2). Module values of Vop 30h .. 40h (VLCD about
5.9 .. 6.9 V) are typical, the datasheet itself gives no Vop for a specific glass.

## 5 Orientation

The PCD8544 has no mirror, rotation, start line or scan direction bits: bank 0 is always the top (R0) and X = 0
always column C0. Any other orientation has to be produced in software (or by the module wiring). The vic head
renders all eight `orientation_*` values in its framebuffer (section 8); `orientation_0` is the upright Nokia
5110 module.

## 6 Reset, power and initialisation

Power on and reset (sections 8.1, 12.2, Fig. 16): after power on all registers and the RAM are undefined and a
RES pulse must be applied, the datasheet warns that the device may be damaged if it is not properly reset. RES
must be at or below 0.3 VDD when VDD reaches VDDmin, within 100 ms after VDD goes high (section 8.1); the AC
table gives tVHRL (VDD high to RES low) 0 .. 30 ms, and RES may already be low before VDD rises. RES low pulse
width tWL(RES) >= 100 ns. After the reset the chip is in power down with Vop = 0 (section 1), so the display only
comes up after function set PD = 0 and a non-zero Vop. The RAM must be written (or cleared) by software.

Power off: put the chip into power down (function set PD = 1, after filling the RAM with 0 for the lowest current)
before removing VDD; the oscillator note (section 6.1.11) also asks for power down before an external clock is
stopped, otherwise the display may be left in a DC state.

LCD power circuit (section 13, Fig. 17): the charge pump and the bias generator are internal, the only external
parts are the supply capacitors Cext >= 1.0 uF on VDD and VLCD (larger values reduce ripple). With an external
VLCD (6.0 .. 9.0 V) the generator is switched off by Vop = 0. VDD may be up to 5 V absolute with the internal
generator, 7 V with an external VLCD (limiting values, note 3), the operating range is 2.7 .. 3.3 V either way.

Datasheet example (Fig. 9 order): function set H = 1, bias system, set Vop, temperature control, function set
H = 0, display control, set Y, set X. The programming example of Table 6 (section 13) is:

| Step | D/C | Byte | Operation |
|---|---|---|---|
| 1 | - | - | SCE goes low |
| 2 | 0 | 21h | function set: PD = 0, V = 0, H = 1 (extended instruction set) |
| 3 | 0 | 90h | set Vop = 16, VLCD = a + 16 x b |
| 4 | 0 | 20h | function set: PD = 0, V = 0, H = 0 (basic instruction set) |
| 5 | 0 | 0Ch | display control: normal mode (D = 1, E = 0) |
| 6 .. 12 | 1 | 1Fh, 05h, 07h, 00h, 1Fh, 04h, 1Fh | data, X and Y start at 0 after reset (draws "PH") |
| 13 | 0 | 0Dh | display control: inverse video (D = 1, E = 1) |
| 14 | 0 | 80h | set X address 0 |
| 15 | 1 | 00h | data write |

The example relies on the reset values of the bias system (BS = 000) and the temperature coefficient, and its
Vop of 16 gives only 4.0 V, below the 6.0 V VLCD minimum of the DC table; it demonstrates the protocol, not a usable
contrast. A typical init is `21h, 80h | Vop, 04h, 10h | bias, 20h, 0Ch`, then address 40h, 80h and the frame.

## 8 The vic head `src/head/PCD8544.h`

```cpp
vic::head::PCD8544<Screen_Size_X = 84, Screen_Size_Y = 48,   // logical size, 48 x 84 for orientation_90 / 270
                   Orientation = drv::orientation_0,          // done in software
                   Vop = 0x38, Bias = 4>
PCD8544(io::handle_type device);
```

- io layer: `io::write()` option 0 = command, 1 = data (the D/C line), SPI mode 0, max. 4 MHz. The head never
  reads. Driving RES is left to the io layer / board.
- init: 21h, 80h | Vop, 04h, 10h | Bias, 20h, 0Ch, clear, present. `shutdown()` = 08h (blank), 24h (power down).
- Framebuffer: 504 bytes bank organised (bit 0 = top row) in physical orientation, `present()` sends 40h, 80h and
  the 504 bytes in one block (horizontal addressing).
- Orientation: `to_phys()` maps the logical vertex to the physical 84 x 48 panel, the `m` orientations mirror the
  panel top/bottom after the rotation (same table as `ST7565.h`). The controller registers never change.
- `display_enable()` = 0Ch / 08h, `display_contrast()` = 21h, 80h | level / 2, 20h, `display_inverse()` = 0Dh / 0Ch.

Review against the datasheet:

1. Command codes, the H bit handling (21h before the extended commands, 20h back to basic), the D / E encoding
   (08h, 0Ch, 0Dh), the set X / Y codes and the bank layout with bit 0 at the top are correct. The init order
   differs from Fig. 9, which is allowed ("each instruction can be sent in any order").
2. `Bias = 4` (14h) gives n = 3, 1/7 bias, which Table 4 recommends for 1:40 / 1:34; the datasheet optimum for
   the PCD8544's 1:48 mux is BS = 3 (13h, n = 4, 1/8 bias). The head comment states this; 4 is kept because it
   is what the Adafruit driver and the 5110 modules use. The contrast range shifts with the bias, so Vop and Bias
   have to be tuned together.
3. `Vop = 0x38` gives VLCD = 6.42 V, inside the 6.0 .. 8.5 V range. `display_contrast(level)` sends Vop =
   level / 2 up to 127, i.e. up to 10.68 V nominal; levels above about 180 (Vop > 5Ah) exceed the 8.5 V limit of the
   internal generator even at room temperature, and levels 0 / 1 give Vop = 0, which switches the charge pump off.
   The head does not clamp.
4. `present()` relies on the horizontal wrap after X = 83 to send the whole RAM in one block. That is only correct
   when the physical panel is 84 x 48; the head only asserts that the physical height is a multiple of 8, a
   different `Screen_Size_X` / `Screen_Size_Y` would produce a misaligned image or write past the RAM.
5. `shutdown()` enters power down without clearing the RAM first; the datasheet asks for an all-0 RAM to reach the
   specified 1.5 uA power down current (section 8.3.1). The trailing 20h of `display_contrast()` sets PD = 0, so a
   contrast change after `shutdown()` wakes the chip up again.
6. The temperature coefficient is fixed to TC = 0 (typ. 1 mV/K). Not used: vertical addressing, the all segments
   on mode (09h), the external VLCD mode.
