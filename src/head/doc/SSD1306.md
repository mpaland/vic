# SSD1306 programming summary

Source: Solomon Systech, *SSD1306 128 x 64 Dot Matrix OLED/PLED Segment/Common Driver with Controller*,
Rev 1.1, Apr 2008 with the charge pump application note Rev 0.4 (`SSD1306.pdf`). This is the programming view of
the datasheet: interfaces, RAM layout, command set, orientation bits and sequences. The last section describes
how the vic head `src/head/SSD1306.h` uses the controller and what the review against the datasheet found.

## 1 Overview

| Item | Value |
|---|---|
| Panel | 128 segments x 64 commons, monochrome |
| GDDRAM | 128 x 64 bit = 1024 byte, organised in 8 pages of 8 rows |
| Supplies | VDD 1.65 .. 3.3 V (logic), VCC 7 .. 15 V (panel), VBAT 3.3 .. 4.2 V for the internal charge pump |
| Interfaces | 8 bit 6800, 8 bit 8080, 4-wire SPI, 3-wire SPI, I2C |
| Brightness | 256 step contrast (81h), segment current max 100 uA |
| Oscillator | divider 1..16, frame rate F = Fosc / (D x K x MUX), K = phase1 + phase2 + 50 (54 at reset) |
| Reset timing | RES# low >= 3 us |

Bus selection pins BS[2:0]: `000` 4-wire SPI, `001` 3-wire SPI, `010` I2C, `100` 8 bit 6800, `110` 8 bit 8080.

State after RES#: display off, 128 x 64 mode (64 MUX), no remap (SEG0 = column 0, COM0 = row 0), start line 0,
column pointer 0, normal COM scan direction, contrast 7Fh, normal display (A4h), serial shift register cleared.

## 2 Interfaces

Control pins: `CS#`, `D/C#` (0 = command, 1 = GDDRAM data), `RES#`, `E(RD#)`, `R/W#(WR#)`, `D[7:0]`.

| Bus | Protocol | Timing |
|---|---|---|
| 6800 | R/W# = 0 write / 1 read, data latched on the falling edge of E while CS# = 0 | see Table 13-2 |
| 8080 | rising edge of WR# latches a write, rising edge of RD# a read, CS# = 0 | tcycle >= 300 ns |
| 4-wire SPI | SCLK = D0, SDIN = D1, MSB first, D/C# sampled on the 8th clock, write only | tcycle >= 100 ns (10 MHz) |
| 3-wire SPI | 9 bit frames: D/C# bit first, then D7..D0; the D/C# pin is tied low, write only | tcycle >= 100 ns |
| I2C | SCL = D0, SDA = D1 (SDAIN) + D2 (SDAOUT), slave address `0111 10 SA0` (SA0 = level of the D/C# pin, 3Ch or 3Dh), write only in practice | tcycle >= 2.5 us (400 kHz) |

I2C frame: `S, slave address + R/W# = 0, [control byte, data bytes ...], P`. The control byte is `Co D/C# 0 0 0 0 0 0`:
Co = 0 means all following bytes are data of the same kind, Co = 1 means one byte follows and then another control
byte. So `00h` starts a command stream, `40h` a data stream, `80h` / `C0h` a single command / data byte.

Reads (parallel buses only, "no data read in serial mode"): a dummy read is required before the first data byte,
the column pointer increments after every data read and write. The status read (D/C# = 0) returns bit 6 = 1 for
display off.

## 3 GDDRAM

The RAM is 8 pages (PAGE0 .. PAGE7) of 128 bytes. One byte holds 8 vertical pixels of one column: bit 0 is the top
row of the page (COM 8 x page), bit 7 the bottom row. Without remap PAGE0 is COM0..COM7 at the top and column 0 is
SEG0 at the left.

Three addressing modes (20h):

| Mode | A[1:0] | Pointer movement after a byte |
|---|---|---|
| Page (reset) | 10 | column++, wraps to the column start inside the page, the page is not changed (set page with B0h..B7h, column with 00h..0Fh / 10h..1Fh) |
| Horizontal | 00 | column++, at the column end back to the column start and page++, at the page end back to the page start |
| Vertical | 01 | page++, at the page end back to the page start and column++ |

In horizontal and vertical mode the window is given by 21h (column start/end) and 22h (page start/end), both also
reset the pointers to the start. A whole 128 x 64 frame in horizontal mode is therefore 1024 bytes in page major
order: `data[page * 128 + column]`.

The display start line (40h..7Fh) selects which RAM row is shown on COM0 (vertical scroll of the whole RAM), the
display offset (D3h) shifts the COM outputs instead.

## 4 Command set

All commands are written with D/C# = 0, parameters follow as command bytes.

### 4.1 Fundamental

| Hex | Parameters | Reset | Function |
|---|---|---|---|
| 81 | A[7:0] | 7Fh | Contrast |
| A4 / A5 | - | A4h | Display follows the RAM / entire display on (ignores the RAM) |
| A6 / A7 | - | A6h | Normal (1 = pixel on) / inverse display |
| AE / AF | - | AEh | Display off (sleep) / display on |

### 4.2 Scrolling

| Hex | Parameters | Function |
|---|---|---|
| 26 / 27 | A 00h, B[2:0] start page, C[2:0] interval, D[2:0] end page, E 00h, F FFh | Continuous horizontal scroll right / left by one column |
| 29 / 2A | A 00h, B[2:0] start page, C[2:0] interval, D[2:0] end page, E[5:0] vertical offset | Vertical and right / left horizontal scroll |
| 2E | - | Deactivate scrolling, the RAM has to be rewritten afterwards |
| 2F | - | Activate scrolling (last setup command wins) |
| A3 | A[5:0] top fixed rows, B[6:0] scroll rows | Vertical scroll area, A + B <= MUX |

Interval C[2:0]: 000 = 5, 001 = 64, 010 = 128, 011 = 256, 100 = 3, 101 = 4, 110 = 25, 111 = 2 frames. RAM access and
changing the scroll parameters are prohibited while scrolling is active.

### 4.3 Addressing

| Hex | Parameters | Reset | Function |
|---|---|---|---|
| 00 .. 0F | - | 0 | Lower nibble of the column start address (page mode) |
| 10 .. 1F | - | 0 | Upper nibble of the column start address (page mode) |
| 20 | A[1:0] | 10b | Memory addressing mode, see section 3 |
| 21 | A[6:0] start, B[6:0] end | 0, 127 | Column address window (horizontal / vertical mode) |
| 22 | A[2:0] start, B[2:0] end | 0, 7 | Page address window (horizontal / vertical mode) |
| B0 .. B7 | - | 0 | Page start address (page mode) |

### 4.4 Hardware configuration

| Hex | Parameters | Reset | Function |
|---|---|---|---|
| 40 .. 7F | - | 40h | Display start line 0 .. 63 |
| A0 / A1 | - | A0h | Segment remap: column 0 -> SEG0 / column 127 -> SEG0 (horizontal mirror, affects only new data) |
| A8 | A[5:0] | 3Fh | Multiplex ratio N + 1, N = 15 .. 63 |
| C0 / C8 | - | C0h | COM scan direction COM0 -> COM[N-1] / COM[N-1] -> COM0 (vertical mirror, immediate) |
| D3 | A[5:0] | 00h | Display offset, vertical shift by COM |
| DA | A[5:4] in `0 0 A5 A4 0 0 1 0` | 12h | COM pins: A[4] = 0 sequential, 1 alternative (reset); A[5] = 1 COM left/right remap |

COM pin configuration (Table 10-3): the alternative configuration interleaves odd and even COM lines on the two
sides of the die and is the wiring of the 128 x 64 panels, 128 x 32 panels use the sequential configuration.

### 4.5 Timing, driving, charge pump

| Hex | Parameters | Reset | Function |
|---|---|---|---|
| D5 | A[3:0] = D - 1, A[7:4] Fosc | 80h | Display clock divider 1 .. 16 and oscillator frequency |
| D9 | A[3:0] phase 1, A[7:4] phase 2 | 22h | Precharge periods in DCLK, 1 .. 15 each |
| DB | A[6:4] | 20h | VCOMH deselect level: 00h 0.65, 20h 0.77, 30h 0.83 x VCC |
| E3 | - | - | NOP |
| 8D | A[7:0]: 10h disable, 14h enable | 10h | Charge pump (application note), must be enabled before AFh; not available on the SSD1309 |

## 5 Orientation

Two bits mirror the image: A0h/A1h (segment remap, horizontal) and C0h/C8h (COM scan direction, vertical).
90 degree rotations are not possible in the controller, they need a rotated framebuffer.

| Orientation | Segment remap | COM scan |
|---|---|---|
| `orientation_0` | A0h | C0h |
| `orientation_0m` | A0h | C8h |
| `orientation_180m` | A1h | C0h |
| `orientation_180` | A1h | C8h |

## 6 Power on / off

Power on (Figure 8-16): VDD on, RES# low for >= 3 us then high, wait >= 3 us, VCC on (or enable the charge pump),
send AFh; SEG/COM are driven 100 ms after AFh.
Power off (Figure 8-17): AEh, VCC off, wait tOFF (typ. 100 ms), VDD off. VDD must never be switched off before VCC.

IREF: resistor to VSS, `R = (VCC - 2.5 V) / 12.5 uA` (400 kOhm at 7.5 V).

Init sequence of the application note:
`AE, D5 80, A8 3F, D3 00, 40, A0/A1, C0/C8, DA 12, 81 7F, A4, A6, 8D 14, AF`.

## 7 The vic head `src/head/SSD1306.h`

```cpp
vic::head::SSD1306<Screen_Size_X = 128, Screen_Size_Y = 64,   // Screen_Size_Y must be a multiple of 8
                   Orientation    = drv::orientation_0,        // 0, 0m, 180, 180m
                   Interface_Mode = SSD1306_I2C,               // SSD1306_SPI3, SSD1306_SPI4, SSD1306_I2C, SSD1306_MEM
                   Framebuffer    = true,                      // render in RAM, send with present()
                   Charge_Pump    = true,                      // enable the charge pump (false for external VCC)
                   Controller     = SSD1306_CTRL_SSD1306,      // SSD1306_CTRL_SSD1306, SSD1306_CTRL_SSD1309, SSD1306_CTRL_SH1106
                   Column_Offset  = (SH1106 ? 2 : 0)>          // first RAM column of the panel
```

The SH1106 (Sino Wealth, `SH1106.pdf`, 132 x 64 RAM) is the controller of most 1.3" OLED modules. It is
command compatible with the SSD1306 except: no memory addressing mode (20h), no column / page window (21h /
22h), only page addressing (B0h | page, 00h | low column nibble, 10h | high column nibble) with the column
pointer stopping at 131; the 128 pixel panels are mapped to RAM columns 2 .. 129; the charge pump is
`ADh 8Bh` (on) / `ADh 8Ah` (off) instead of 8Dh 14h, and 30h .. 33h select the pump voltage. SSD1306 code on
an SH1106 shows the image shifted by two columns and the last pages missing. The SSD1309 is an SSD1306 with
external VCC only (no 8Dh command).

- io layer: `io::write()` option 0 = command, 1 = data. The head emits 8 bit bytes for all interfaces. In I2C mode
  the control byte (`00h` / `40h`) is the first byte of every block, in 3-wire SPI mode the io layer has to build the
  9 bit frames from the option and the byte.
- init: `AE, A8 N-1, D3 00, 40, A0/A1, C0/C8, DA 12 (or 02 for 32 lines), 81 7F, A4, A6, D5 80, [8D 14], D9 22,
  DB 30, 20 00, AF`, then clear and present.
- With `Framebuffer` all drawing goes into a page organised RAM copy, `present()` sets the window to the whole RAM
  (21h offset .. offset + width - 1, 22h 00 N/8-1) and sends the 1024 bytes as one block (I2C: control byte + data
  in one transfer). On the SH1106 every page is addressed (B0h | page, 00h | 2, 10h | 0) and sent separately.
- Without framebuffer every pixel is a read-modify-write of one page byte: set window, read (the io layer does the
  dummy read), set window again (the pointer moved on the read), write. Only possible on the parallel buses.
- `display_enable()` = AFh / AEh, `display_contrast()` = 81h.

Review against the datasheet: the command values, the I2C control bytes, the page layout and the orientation bits
are correct. Changed with the review: `Charge_Pump` template parameter, `static_assert` on the page multiple,
then the `Controller` (SSD1309, SH1106) and `Column_Offset` parameters. Not supported: 90 / 270 degree
orientations, scrolling, page addressing mode on the SSD1306 (used on the SH1106 only).
