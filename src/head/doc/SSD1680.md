# SSD1680 programming summary

Source: Solomon Systech, *SSD1680 176 Source x 296 Gate Red/Black/White Active Matrix EPD Display Driver with
Controller*, Advance Information Rev 1.4, Apr 2021 (`SSD1680.pdf`, 47 pages). The SSD1681 (*200 Source x 200
Gate ...*, `SSD1681.pdf`) shares the command set; the SSD1680 drives the 2.13" (122 x 250) and 2.9" (128 x 296)
panels, the SSD1681 the 1.54" (200 x 200) panels. The SSD1681 details are in `SSD1681.md`, section 9 here
compares both. Both chips are driven by the vic head `src/head/SSD1680.h`, described in section 8.

## 1 Overview

| Item | Value |
|---|---|
| Panel | 176 sources x 296 gates, 1 VCOM, 1 border output VBD; black/white/red or black/white panels |
| RAM | two planes of 176 x 296 bit: RAM 0x24 black/white, RAM 0x26 red |
| Supplies | VCI 2.2 .. 3.7 V, VDDIO = VCI, VDD 1.8 V from the internal regulator (capacitor on VDD), VPP 7.5 V only for OTP programming |
| Voltage generation | internal booster with external inductor (47 uH), NMOS, 3 diodes and capacitors: VGH 10 .. 20 V, VGL = -VGH (max 40 Vpp); VSH1 / VSH2 2.4 .. 17 V; VSL -5 .. -17 V; DCVCOM -0.2 .. -3.0 V |
| Interface | 4-wire SPI (CS#, SCL, SDA, D/C#) or 3-wire SPI with 9 bit frames (BS1 pin), 20 MHz write, 2.5 MHz read; BUSY output pin high while the controller works |
| Waveforms | 5 LUTs (LUT0 .. LUT3 for the sources, LUTC for VCOM) in 12 groups of 4 phases; from OTP (36 temperature ranges) or written by the MCU (32h); display mode 1 = full update, display mode 2 = partial / fast update (needs a mode 2 waveform) |
| Temperature | internal sensor +-2 C from -25 .. 50 C (18h 80h) or external I2C sensor on TSDA / TSCL (POR); the temperature selects the OTP waveform |
| Extras | auto write RAM patterns (46h / 47h), CRC of RAM / OTP, VCI low detection, HV ready detection, VCOM sensing, OTP for waveforms, VCOM, user ID, init code |
| Frame rate | 25 .. 200 Hz per waveform group |
| Refresh | full update 1 .. 4 s depending on temperature (value of the OTP waveforms of the panels used with the head, the datasheet gives no update time); the panel must not be driven during BUSY |

State after power on / reset: POR values of all registers as in section 4, notably 01h 127h (296 MUX), 11h 03h,
44h 00h .. 15h, 45h 000h .. 127h, 18h 48h (external sensor), 21h 00h 00h, 22h FFh, 3Ch C0h (border HiZ).
SW reset (12h) restores these values except the deep sleep register and does not touch the RAM.

## 2 Interface and busy handling

| BS1 | Interface | Pins |
|---|---|---|
| L | 4-wire SPI | CS#, D/C#, SCL, SDA |
| H | 3-wire SPI (9 bit) | CS#, SCL, SDA; D/C# tied low |

- 4-wire write (section 6.1.2): SDA is shifted in MSB first on the rising edge of SCL, D/C# = 0 command,
  D/C# = 1 parameter or RAM data, D/C# has to be stable for the whole byte. Commands and their parameters can be
  sent in one CS# low phase.
- 3-wire write (section 6.1.3): 9 bit frames, the first bit is D/C# (0 command, 1 data), then D7 .. D0.
- Read (commands 1Bh, 27h, 2Dh, 2Eh, 2Fh, 35h): the command byte is written, then SDA turns around and the chip
  shifts out data MSB first on the falling edge of SCL, max 2.5 MHz. SDA is bidirectional, so a read needs an
  MCU pin that can switch direction. RAM read (27h) returns a dummy byte first.
- BUSY pin (Table 5-2): high during reset, waveform output (master activation), OTP access, communication with
  the external sensor, auto write RAM, VCOM sense, HV / VCI detection and in deep sleep. "When Busy is High ...
  command should not be sent". The status bit read 2Fh contains a busy flag (A[2]) as well, but it needs the read
  path; drivers normally poll the BUSY pin (or wait the maximum time).
- Deep sleep is left only with a hardware reset (RES# low); BUSY stays high in deep sleep.
- RES# low duration: the datasheet gives no minimum; the head and the reference drivers use >= 10 us
  (implemented in `io::init()`).

AC timing (Table 12-1, VDDIO 2.2 .. 3.7 V):

| Parameter | Write | Read |
|---|---|---|
| fSCL max | 20 MHz | 2.5 MHz |
| CS# low before the first SCL rising edge | 60 ns | 100 ns |
| CS# low after the last SCL falling edge | 65 ns | 50 ns |
| CS# high between transfers | 100 ns | 250 ns |
| SCL high / low | 25 / 25 ns | 180 / 180 ns |
| SDA setup / hold (write) | 10 / 40 ns | - |
| SDA out valid before rising / hold after falling (read) | - | 50 ns typ. / 0 ns |

## 3 RAM organisation and address counter

The RAM is addressed in X (source direction, in bytes of 8 pixels, bit 7 = first source, X = 0 .. 21 = 15h for
176 sources) and Y (gate direction, rows 0 .. 295 = 127h). Each plane holds one bit per pixel:

| RAM 0x26 (red) | RAM 0x24 (B/W) | 3 color panel (Table 6-4) | B/W panel (Table 6-5) |
|---|---|---|---|
| 0 | 0 | black, LUT0 | black, LUT0 |
| 0 | 1 | white, LUT1 | white, LUT1 |
| 1 | 0 | red, LUT2 | black, LUT2 = LUT0 |
| 1 | 1 | red, LUT3 = LUT2 | white, LUT3 = LUT1 |

Window and counter commands (section 8.2 .. 8.5):

| Hex | Parameters | Function |
|---|---|---|
| 11 | A[2:0] | data entry mode: A[1:0] = ID (00 Y-- X--, 01 Y-- X++, 10 Y++ X--, 11 Y++ X++ [POR]), A[2] = AM (0 counter runs along X [POR], 1 along Y) |
| 44 | XSA[5:0], XEA[5:0] | RAM X window in bytes, POR 00h .. 15h (176 sources = 22 bytes) |
| 45 | YSA[8:0], YEA[8:0] | RAM Y window in rows, 16 bit each (low byte, then bit 8), POR 000h .. 127h |
| 4E | XAD[5:0] | X address counter |
| 4F | YAD[8:0] | Y address counter (2 bytes) |
| 24 | data ... | write black/white RAM: 1 = white, 0 = black |
| 26 | data ... | write red RAM: 1 = red, 0 = not red |
| 27 | dummy, data ... | read RAM (the first byte is dummy), RAM selected by 41h |
| 41 | A[0] | read RAM option: 0 = RAM 0x24 [POR], 1 = RAM 0x26 |
| 46 / 47 | A[7:0] | auto write RAM 0x26 / 0x24 with a regular pattern (fast clear), BUSY while running |

After every RAM byte the counter moves by one in the AM direction (X by one byte, Y by one row), with the sign
from ID, and wraps inside the window: in X mode at the end of a row it returns to the X start and steps Y
(Figure on p. 37). The counter has to be set inside the window, otherwise "undesirable image" (section 8.5);
neither 44h / 45h nor 11h move the counter, so 4Eh / 4Fh have to follow. The window settings are 0 .. 15h and
0 .. 127h; the command table gives XSA / XAD as 6 bit fields, section 8.3 / 8.5 as 5 bit fields (both hold 15h).
With ID[0] = 0 the figure on p. 37 also reverses the pixel order inside the byte ("4, 3, 2, 1"), the text does not
say so explicitly.

With entry mode 03h a frame is written row by row, `(width + 7) / 8` bytes per row, rows 0 .. gates - 1.
A full plane is 22 x 296 = 6512 byte; 24h and 26h each need the counter set again (4Eh / 4Fh) because the
counter is shared.

Auto write (46h / 47h): A[7] value of the first step, A[6:4] step height in gates (8, 16, 32, 64, 128, 256, 296),
A[2:0] step width in sources (8, 16, 32, 64, 128, 176). The datasheet gives only these fields; read literally,
height 296 and width 176 make a single step, i.e. a solid fill of the plane with the A[7] value.

## 4 Command set

Commands with D/C# = 0, all parameters with D/C# = 1. "Wait BUSY" marks commands that set BUSY.

### 4.1 Panel and voltage setup

| Hex | Parameters | POR | Function |
|---|---|---|---|
| 01 | MUX[7:0], MUX[8], `0 0 0 0 0 GD SM TB` | 127h, 00h | driver output (section 8.1 prints the POR as 13Fh, the table 127h): gate lines MUX + 1 (16 .. 296); GD = 1 starts with G1 (G1, G0, G3, G2 ...); SM = 1 no left / right interlace (G0, G2 .. G294, G1, G3 .. G295); TB = 1 scan G295 -> G0 |
| 03 | A[4:0] | 00h | VGH: 00h = 20 V, 03h = 10 V .. 17h = 20 V in 0.5 V steps (the table lists 07h / 08h twice) |
| 04 | A, B, C | 41h A8h 32h | VSH1, VSH2, VSL. A / B with bit 7 = 1: 8Eh 2.4 V .. CEh 8.8 V in 0.1 V; bit 7 = 0: 23h 9 V .. 4Bh 17 V in 0.2 V. C: 0Ah -5 V .. 3Ah -17 V in 0.5 V steps (even values). POR = 15 V, 5 V, -15 V; VSH1 >= VSH2 |
| 0C | A, B, C, D | 8Bh 9Ch 96h 0Fh | booster soft start: A / B / C phase 1 / 2 / 3 with bit 7 = 1, A[6:4] driving strength 1 (weakest) .. 8, A[3:0] minimum GDR off time (3h = 2.6 .. Eh = 16.5 time units); D[5:4] / [3:2] / [1:0] duration of phase 3 / 2 / 1: 10, 20, 30, 40 ms |
| 2C | A[7:0] | 00h | VCOM register: 08h = -0.2 V .. 78h = -3.0 V, 04h per 0.1 V |
| 3C | A | C0h | border waveform VBD: A[7:6] 00 GS transition (A[2] = 0 follow LUT with VCOM at red, 1 follow LUT; A[1:0] = LUT0 .. LUT3), 01 fixed level (A[5:4]: VSS, VSH1, VSL, VSH2), 10 VCOM, 11 HiZ; 05h (transition, LUT1) is the reference value |
| 3F | A | - | end option EOPT: 22h = 2 scan frames discharge the pixels, VCOM and HV are discharged; 07h = no scan frame, pixels keep their voltage, VCOM and VGL float (wait for the discharge before the next operation) |

### 4.2 Operation

| Hex | Parameters | POR | Function |
|---|---|---|---|
| 10 | A[1:0] | 00h | deep sleep: 01h mode 1 (RAM retained, not accessible), 03h (11b) mode 2 (RAM lost); BUSY stays high, hardware reset to leave |
| 12 | - | - | software reset of all commands except deep sleep, RAM unaffected, BUSY high during the reset |
| 14 | `0 A[6:4] 0 A[2:0]` | 00h | HV ready detection (needs clock + analog enabled): cool down 10 ms x (n + 1), m loops; result in 2Fh A[5]; BUSY |
| 15 | A[2:0] | 04h | VCI detection level: 03h 2.2 V, 04h 2.3 V .. 07h 2.6 V; result in 2Fh A[4]; BUSY |
| 18 | A | 48h | temperature sensor: 80h internal, 48h external |
| 1A | A[11:4], A[3:0] << 4 | 7Fh (as printed) | write the temperature register (12 bit) |
| 1B | read 2 bytes | - | read the temperature register |
| 1C | A, B, C | 00h | write to the external sensor: A[7:6] number of bytes (00 address + pointer, 01 + 1st parameter, 10 + 2nd parameter, 11 address only), A[5:0] pointer; BUSY |
| 20 | - | - | master activation: run the sequence enabled by 22h, BUSY high during the update, do not interrupt |
| 21 | A, B | 00h 00h | display update control 1: A[7:4] red RAM option, A[3:0] BW RAM option (0 normal, 4 bypass as 0, 8 inverse); B[7] = 1 sources S8 .. S167 instead of S0 .. S175 (the 122 / 128 wide panels) |
| 22 | A | FFh | display update control 2, the sequence for 20h (table below) |
| 2F | read 1 byte | 01h | status: A[5] HV not ready, A[4] VCI low, A[2] busy, A[1:0] chip ID 01; A[5] / A[4] only valid after 14h / 15h |
| 7F | - | - | NOP, terminates a RAM write / read |

Display update control 2 (22h) option bytes:

| Value | Sequence run by 20h |
|---|---|
| 80h / 01h | enable clock / disable clock |
| C0h / 03h | enable clock + analog / disable analog + clock |
| 91h / 99h | clock, load LUT with display mode 1 / 2, clock off |
| B1h / B9h | clock, load temperature, load LUT mode 1 / 2, clock off |
| C7h / CFh | clock, analog, display with mode 1 / 2, analog off, OSC off (LUT already loaded) |
| F7h | clock, analog, load temperature, load LUT, display mode 1, analog off, OSC off (full update) |
| FFh | the same with mode 2 (POR) |

### 4.3 Waveform, OTP and VCOM

| Hex | Parameters | Function |
|---|---|---|
| 08 / 09 / 0A | - / 4 bytes / read | program / write / read the initial code setting (OTP, reserved bytes, application note) |
| 28 | - | VCOM sense (clock + analog), result into the VCOM register; BUSY |
| 29 | `0 1 0 0 A[3:0]` | VCOM sense duration (A + 1) s, POR 09h = 10 s |
| 2A | - | program the VCOM register into OTP; BUSY |
| 2D | read 11 bytes | OTP display option: VCOM OTP selection, VCOM register, display mode bytes, waveform version |
| 2E | read 10 bytes | user ID |
| 30 / 31 | - | program WS OTP (from RAM) / load WS OTP; BUSY |
| 32 | 153 bytes | write the LUT register (VS, TP, SR, RP, FR, XON), see 6.3 |
| 34 / 35 | - / read 2 bytes | CRC calculation (BUSY) / CRC status A[15:0] |
| 36 | - | program the OTP selection (37h / 38h data); BUSY |
| 37 | 10 bytes | display option: A[7] spare VCOM OTP; B .. F[3:0] display mode 1 / 2 per WS0 .. WS35; F[6] RAM ping-pong for display mode 2 (not for mode 1); G .. J module ID / waveform version |
| 38 | 10 bytes | user ID |
| 39 | A[1:0] | OTP program mode: 00 normal, 11 internal programming voltage ("exactly follow the reference code") |

## 5 Orientation

The controller has no rotation, only address directions: 01h GD / SM / TB select the gate order and direction,
11h ID reverses X (byte order, and per the p. 37 figure the pixel order in the byte) and / or Y, AM selects the
fast direction. A 90 degree rotation is not possible in hardware because the X unit is a byte of 8 sources.
The head therefore keeps the controller at 11h 03h, TB = 0, and maps every orientation in software
(`to_phys()`):

| Orientation | physical (source x, gate y) from logical (x, y) |
|---|---|
| `orientation_0` | (x, y) |
| `orientation_0m` | (x, H - 1 - y) |
| `orientation_180` | (W - 1 - x, H - 1 - y) |
| `orientation_180m` | (W - 1 - x, y) |
| `orientation_90` | (W - 1 - y, x) |
| `orientation_90m` | (W - 1 - y, H - 1 - x) |
| `orientation_270` | (y, H - 1 - x) |
| `orientation_270m` | (y, x) |

W / H are the physical sources / gates; the logical size is swapped for 90 / 270.

## 6 Sequences and waveforms

### 6.1 Operation flow (section 9, Figure 9-1 / 9-2)

1. Power on: VCI on, wait 10 ms.
2. Hardware reset, software reset 12h, wait 10 ms (BUSY is high during 12h).
3. Init: 01h gate driver, 11h data entry, 44h / 45h RAM window, 3Ch border.
4. Temperature 18h, load the waveform from OTP with 22h / 20h (or write it with 32h), wait BUSY low.
5. Image: 4Eh, 4Fh, 24h, [26h]; soft start 0Ch; drive the panel with 22h / 20h, wait BUSY low.
6. Power off (VCI off, Figure 9-1) or deep sleep mode 2 (10h 03h, Figure 9-2).

Steps 4 and 5 can be combined with 22h F7h (temperature + LUT + display mode 1). A partial / fast update uses
display mode 2 (22h CFh / FFh, or C7h after writing a LUT with 32h): the OTP display mode bits (37h) select which
WS has mode 2, 37h F[6] enables "RAM ping-pong" for display mode 2 (not explained further). The datasheet only
describes the commands, the partial update procedure itself is in the panel vendor documents.

### 6.2 Temperature and OTP search (section 6.8 .. 6.11)

The temperature value is 12 bit two's complement in 1/16 C (`190h` = 25 C, `E70h` = -25 C). The controller
searches TR0 .. TR35 and takes the last range with `lower < T <= upper`; if no range matches, the display is not
updated. Each TR entry is 3 bytes (`temp_L[7:0]`, `temp_H[3:0] temp_L[11:8]`, `temp_H[11:4]`). A temperature
measured by the MCU can be written with 1Ah; the 22h options without "load temperature value" (91h, 99h) then
load the LUT for the register value.

### 6.3 Waveform setting (section 6.6 / 6.7)

A waveform setting (WS) is 159 bytes: 0 .. 152 = 32h (LUT), 153 = 3Fh (EOPT), 154 = 03h (VGH), 155 .. 157 = 04h
(VSH1, VSH2, VSL), 158 = 2Ch (VCOM). Commands written later override the OTP values. The 153 LUT bytes:

| Bytes | Content |
|---|---|
| 0 .. 59 | VS[nX-LUTm]: 12 bytes per LUT (LUT0 .. LUT3, LUT4 = LUTC), one byte per group with phases A B C D as 2 bit fields (A in bits 7:6) |
| 60 .. 143 | per group n: TP[nA], TP[nB], SR[nAB], TP[nC], TP[nD], SR[nCD], RP[n] (7 bytes x 12) |
| 144 .. 149 | FR[n] as 4 bit nibbles, two groups per byte |
| 150 .. 152 | XON[nAB] / XON[nCD] bits, 8 per byte |

VS for the sources: 00 VSS, 01 VSH1, 10 VSL, 11 VSH2; for LUTC: 00 DCVCOM, 01 VSH1 + DCVCOM, 10 VSL + DCVCOM.
TP = 0 .. 255 frames (0 skips the phase), RP / SR = 0 .. 255 meaning 1 .. 256 repeats. FR (Table 6-7): 1h 25 Hz,
2h 50 Hz .. 8h 200 Hz in 25 Hz steps, 9h 37.5 Hz .. Fh 187.5 Hz (the text says 0 .. 7, the table uses 4 bits).
XON = 1 keeps all gates on during that phase pair.

## 8 The vic head `src/head/SSD1680.h`

```cpp
vic::head::SSD1680<Screen_Size_X = 122, Screen_Size_Y = 250,    // logical size (sources x gates for orientation_0)
                   Orientation  = drv::orientation_0,            // 90 / 270 for landscape, done in software
                   Tri_Color    = false,                         // black/white/red panel, second plane
                   Source_S8    = (physical width <= 160),       // 21h B[7], true for 122 / 128 wide panels
                   Refresh_Delay = 3000>                         // ms, used when BUSY can't be read
SSD1680(io::handle_type device);
```

- io layer: `io::write()` option 0 = command, 1 = data; `io::read()` option 2 returns one byte with bit 0 =
  BUSY level, the head polls it every 10 ms after the software reset and the master activation (up to 10 s).
  An io layer without BUSY read returns false and the head waits `Refresh_Delay`. The hardware reset is part of
  `io::init()`.
- init: 10 ms delay, 12h + BUSY, 01h (gates - 1, 00h), 11h 03h, 44h (0, bytes - 1), 45h (0, gates - 1), 3Ch 05h,
  21h (00h, 80h / 00h), 18h 80h, clear to white. The panel is not refreshed by `init()`.
- Framebuffer: 1 bit per pixel in physical orientation (bytes along the sources, bit 7 = source 0), 1 = white.
  Colors: `color::none` and light colors (luminance >= 128) are paper, dark colors are ink, red colors
  (R >= 128, G < 96, B < 96) go to the red plane on tri color panels. `pixel_get()` returns black, white or red.
- `present()` uploads the plane(s) (4Eh 00h, 4Fh 00h 00h, 24h [26h]), runs 22h F7h, 20h and waits for BUSY.
  It does nothing when the framebuffer did not change since the last refresh; batch primitives with
  `dc::present_lock()` to get one refresh per screen. `shutdown()` enters deep sleep mode 1.
- `static_assert`: physical width <= 200 and height <= 296 (union of both chips).
- Not covered: partial / fast updates with MCU LUTs, external temperature sensor, the auto write commands.

Crosscheck against the datasheet:

| Item | Assessment |
|---|---|
| 01h, 11h 03h, 44h, 45h, 4Eh, 4Fh parameter formats | correct (9 bit values as low byte + bit 8) |
| 24h 1 = white, 26h 1 = red, red pixels white in RAM 0x24 | correct (Table 6-4: red wins over B/W) |
| 3Ch 05h | GS transition, follow LUT, LUT1 (white) - valid |
| 21h B[7] = 80h for <= 160 px wide panels | valid for the SSD1680; the datasheet does not say which RAM X address maps to S8 in that mode |
| 18h 80h | needed, the POR is the external sensor (48h) |
| 22h F7h + 20h | valid single step full update (temperature, LUT mode 1, display) |
| 10h 01h on `shutdown()` | valid; BUSY stays high afterwards and only a hardware reset (`init()`) wakes the chip, a `present()` after `shutdown()` would poll BUSY for the full 10 s timeout |
| BUSY poll right after 12h / 20h | the first poll happens immediately; the datasheet flow waits 10 ms after 12h and gives no BUSY rise time, a minimum delay before polling would be safer |
| 0Ch soft start | not sent (POR values used); the datasheet flow sends it before driving the panel |
| RES# low >= 10 us | not specified by the datasheet (io layer value) |
| `static_assert` | accepts 200 x 296, which fits neither chip (SSD1680 176 x 296, SSD1681 200 x 200) |

## 9 SSD1680 vs SSD1681

| Item | SSD1680 (Rev 1.4) | SSD1681 (Rev 0.13, product preview) |
|---|---|---|
| Outputs / RAM | 176 sources x 296 gates, 2 x 176 x 296 bit | 200 sources x 200 gates, 2 x 200 x 200 bit |
| 01h POR | 127h (296 MUX) | C7h (200 MUX) |
| 21h B[7] source mode | S0 .. S175 or S8 .. S167 | not defined (only "B[7:0] = 00h [POR]") |
| 2Bh | - | VCOM control, 04h 63h, reduces glitches when ACVCOM toggles |
| 3Fh POR | not given | 02h; 22h normal, 07h keep source level |
| 1Ah POR | 7Fh (as printed) | 7FFh |
| 44h / 45h POR | 15h / 127h | printed as 15h / 127h (copied from the SSD1680, 200 x 200 needs 18h / C7h) |
| 46h / 47h steps | height up to 296, width up to 176 | height and width up to 200 |
| Command descriptions | sections 8.1 .. 8.5 (01h, 11h, 44h, 45h, 4Eh / 4Fh) | command table only |
| SPI timing | complete table | only 20 MHz write / 2.5 MHz read, the rest TBD |
| Flow | power off or deep sleep mode 2 | deep sleep 10h, power off |
| Everything else | identical command set, LUT format (153 + 6 bytes), OTP layout, voltages, electrical values | |
