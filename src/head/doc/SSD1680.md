# SSD1680 / SSD1681 programming summary

Sources: Solomon Systech *SSD1680 176 Source x 296 Gate Red/Black/White Active Matrix EPD Display Driver with
Controller* Rev 1.4 (`SSD1680.pdf`) and *SSD1681 200 Source x 200 Gate ...* (`SSD1681.pdf`). Both controllers
share the command set; the SSD1680 drives the 2.13" (122 x 250) and 2.9" (128 x 296) panels, the SSD1681 the
1.54" (200 x 200) panels. The last section describes the vic head `src/head/SSD1680.h`.

## 1 Overview

| Item | Value |
|---|---|
| RAM | two planes of 176 x 296 bit (SSD1680) / 200 x 200 bit (SSD1681): RAM 0x24 black/white, RAM 0x26 red |
| Supplies | VCI 2.2 .. 3.7 V, VDDIO = VCI, internal booster for the gate / source voltages, external capacitors and inductor |
| Interface | 4 wire SPI (CS#, SCLK, SDA, D/C#), 3 wire SPI (9 bit), 20 MHz write; BUSY pin high while the controller works |
| Waveforms | LUT from OTP (temperature compensated) or written by the MCU (32h), display mode 1 = full update, mode 2 = partial (needs a LUT) |
| Temperature | internal sensor (18h 80h) or external I2C sensor; the temperature selects the OTP waveform |
| Refresh | full update 1 .. 4 s depending on temperature, the panel must not be driven during BUSY |

Sequence after power on (datasheet section 9): VCI on, wait 10 ms, hardware reset (RES# low >= 10 us),
software reset 12h, wait BUSY; 01h gate driver, 11h data entry, 44h / 45h RAM window, 3Ch border; 18h
temperature sensor and 22h / 20h LUT load (or combined with the display update); write the image (4Eh, 4Fh,
24h, 26h); 22h update sequence, 20h master activation, wait BUSY; power off or deep sleep (10h).

## 2 Interface and busy handling

SPI: command byte with D/C# = 0, parameters and RAM data with D/C# = 1, MSB first, data latched on the
rising edge of SCLK. The BUSY pin is high during reset, LUT load, master activation and the auto write
commands; the controller ignores commands while BUSY. There is no busy flag on the bus, BUSY must be
polled (or the maximum times waited). Deep sleep is left only with a hardware reset.

## 3 RAM organisation

The RAM is addressed in X (source direction, in bytes of 8 pixels, bit 7 = first source) and Y (gate
direction, rows). Window and counter:

| Hex | Parameters | Function |
|---|---|---|
| 11 | A[2:0] | data entry mode: A[1:0] = ID (00 Y-- X--, 01 Y-- X++, 10 Y++ X--, 11 Y++ X++ [POR]), A[2] = AM (0 counter runs along X [POR], 1 along Y) |
| 44 | XSA[5:0], XEA[5:0] | RAM X window in bytes, POR 00h .. 15h (176 sources = 22 bytes) |
| 45 | YSA[8:0], YEA[8:0] | RAM Y window in rows, 16 bit each, POR 000h .. 127h |
| 4E | XAD[5:0] | X address counter |
| 4F | YAD[8:0] | Y address counter (2 bytes) |
| 24 | data ... | write black/white RAM: 1 = white, 0 = black |
| 26 | data ... | write red RAM: 1 = red, 0 = not red |
| 27 | dummy, data ... | read RAM (the first byte is dummy), RAM selected by 41h |
| 46 / 47 | A[7:0] | auto write RAM 0x26 / 0x24 with a regular pattern (fast clear), BUSY while running |

With entry mode 03h a frame is written row by row, `(width + 7) / 8` bytes per row, rows 0 .. gates - 1.

## 4 Commands

| Hex | Parameters | Function |
|---|---|---|
| 01 | MUX[8:0] (2 bytes), GD SM TB | driver output: number of gate lines - 1 (SSD1680 POR 127h = 296, SSD1681 POR C7h = 200), GD first gate, SM scan sequence (0 interlaced), TB scan direction |
| 03 / 04 | | gate / source driving voltage |
| 0C | A, B, C, D | booster soft start (POR 8Bh 9Ch 96h 0Fh) |
| 10 | A[1:0] | deep sleep: 01h mode 1 (RAM retained), 11b (03h) mode 2 (RAM lost); hardware reset to leave |
| 12 | | software reset of all commands except deep sleep, BUSY high during the reset |
| 18 | A | temperature sensor: 80h internal, 48h external (POR) |
| 1A | A[11:0] | write the temperature register |
| 20 | | master activation: run the sequence enabled by 22h, BUSY high during the update |
| 21 | A, B | display update control 1: A[7:4] red RAM option, A[3:0] BW RAM option (0 normal, 4 bypass as 0, 8 inverse); B[7] = 1 sources S8 .. S167 instead of S0 .. S175 (the 122 / 128 wide panels) |
| 22 | A | display update control 2, the sequence for 20h: 80h enable clock, C0h clock + analog, 91h / 99h load LUT mode 1 / 2, B1h / B9h load temperature + LUT, C7h / CF display mode 1 / 2, F7h load temperature + LUT + display mode 1 (full update), FFh the same with mode 2, 01h / 03h disable clock / analog |
| 2C | A | VCOM register |
| 32 | 153 bytes (SSD1680) | write the waveform LUT |
| 37 | 10 bytes | write register for display option (ping pong, LUT end option) |
| 3C | A | border waveform: A[7:6] 00 GS transition (A[2], A[1:0]), 01 fixed level (A[5:4]), 10 VCOM, 11 HiZ (POR C0h); 05h (transition, LUT1) is the reference value |
| 3F | A | LUT end option |
| 41 | A | read RAM option for 27h (0 = RAM 0x24, 1 = RAM 0x26) |
| 7F | | NOP, terminates a RAM write / read |

## 5 The vic head `src/head/SSD1680.h`

```cpp
vic::head::SSD1680<Screen_Size_X = 122, Screen_Size_Y = 250,    // logical size (sources x gates for orientation_0)
                   Orientation  = drv::orientation_0,            // 90 / 270 for landscape, done in software
                   Tri_Color    = false,                         // black/white/red panel, second plane
                   Source_S8    = (physical width <= 160),       // 21h B[7], true for 122 / 128 wide panels
                   Refresh_Delay = 3000>                         // ms, used when BUSY can't be read
SSD1680(io::handle_type device);
```

- io layer: `io::write()` option 0 = command, 1 = data; `io::read()` option 2 returns one byte with bit 0 =
  BUSY level, the head polls it every 10 ms after the software reset and the master activation (up to 10 s).
  An io layer without BUSY read returns false and the head waits `Refresh_Delay`. The hardware reset is part of
  `io::init()`.
- init: 12h + BUSY, 01h (gates - 1, 00h), 11h 03h, 44h (0, bytes - 1), 45h (0, gates - 1), 3Ch 05h, 21h (00h,
  80h / 00h), 18h 80h, clear to white. The panel is not refreshed by `init()`.
- Framebuffer: 1 bit per pixel in physical orientation (bytes along the sources, bit 7 = source 0), 1 = white.
  Colors: `color::none` and light colors (luminance >= 128) are paper, dark colors are ink, red colors
  (R >= 128, G < 96, B < 96) go to the red plane on tri color panels. `pixel_get()` returns black, white or red.
- `present()` uploads the plane(s) (4Eh 00h, 4Fh 00h 00h, 24h [26h]), runs 22h F7h, 20h and waits for BUSY.
  It does nothing when the framebuffer did not change since the last refresh; batch primitives with
  `dc::present_lock()` to get one refresh per screen. `shutdown()` enters deep sleep mode 1.
- Not covered: partial / fast updates with MCU LUTs, external temperature sensor, the auto write commands.
