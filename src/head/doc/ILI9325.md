# ILI9325 programming summary

Source: ILI Technology, *ILI9325 a-Si TFT LCD Single Chip Driver, 240RGBx320 Resolution and 262K color*,
Version 0.43 (`ILI9325-0.43.pdf`). This is the programming view of the datasheet: interfaces, GRAM layout, the
registers a driver needs, orientation bits and sequences. The RGB/VSYNC moving picture interfaces, gamma
correction details, OTP programming and the electrical tables are only mentioned. The last section describes how
the vic head `src/head/ILI9325.h` uses the controller and what the review against the datasheet found.

## 1 Overview

| Item | Value |
|---|---|
| Panel | 240 RGB x 320, 720 source outputs S1..S720, 320 gate outputs G1..G320 |
| GRAM | 240 x 320 x 18 bit (172,800 byte), 262k colors, 65k colors with 16 bit transfers |
| Supplies | IOVCC 1.65 .. 3.3 V (interface), VCI 2.5 .. 3.3 V (analog), VCC digital; step-up circuits generate DDVDH, VGH, VGL, VCL |
| Interfaces | i80 system interface 8 / 9 / 16 / 18 bit, SPI, plus RGB (6 / 16 / 18 bit) and VSYNC interfaces for moving pictures |
| Registers | 16 bit index register (IR), 16 bit registers, 18 bit GRAM data |
| Features | window address area, partial display (2 images), vertical scroll, resizing (1/2, 1/4), 8 color mode, frame rate 30 .. 112 Hz |

Interface selection pins IM[3:0]: `0010` 16 bit, `0011` 8 bit, `010x` SPI (IM0 = ID bit), `1010` 18 bit, `1011` 9 bit.

Reset (nRESET low): registers at their reset values, display off, sleep/standby cleared; power stabilising is the
job of the power on sequence (section 6).

## 2 System interface

Every access is "write index, then data". Control pins: `nCS`, `RS` (0 = index / status, 1 = register / GRAM),
`nWR`, `nRD`, `DB[17:0]`.

| RS | nWR | nRD | Function |
|---|---|---|---|
| 0 | edge | 1 | Write index register |
| 0 | 1 | edge | Read status |
| 1 | edge | 1 | Write register or GRAM (via WDR) |
| 1 | 1 | edge | Read register or GRAM (via RDR) |

Bus widths and bit positions (Figures 2 .. 5, 23):

| Bus | Pins | Register write (16 bit) | GRAM pixel |
|---|---|---|---|
| 18 bit | DB[17:0] | D15..D0 on DB15..DB0 | 1 transfer, R5..R0 G5..G0 B5..B0 on DB17..DB0 |
| 16 bit | DB[17:10], DB[8:1] | D15..D0 on the 16 lines | TRI = 0: 1 transfer RGB565 (R5 R4 R3 R2 R1 G5 .. G0 B5 .. B1); TRI = 1, DFM = 0: 16 bits then B1 B0 on DB17 DB16; TRI = 1, DFM = 1: R5 R4 on DB2 DB1 then 16 bits |
| 9 bit | DB[17:9] | 2 transfers: D15..D8 then D7..D0 on DB17..DB10, DB9 unused | 2 transfers: bits 17..9 then 8..0 (always 18 bit) |
| 8 bit | DB[17:10] | 2 transfers: upper byte then lower byte | TRI = 0: 2 transfers RGB565; TRI = 1, DFM = 0: R5 R4 (bits 1:0), R3..G2, G1..B0; TRI = 1, DFM = 1: 3 bytes with 6 bits each in bits 7:2 |
| SPI | SDI, SDO, SCL, nCS | start byte, then upper and lower byte | like the 8 bit bus (2 bytes RGB565, or 3 bytes with TRI = 1, DFM = 1) |

The index register is always written as a 16 bit value (upper byte 00h). In 8 / 9 bit mode the upper/lower byte
counters can be resynchronised by writing index 00h four times.

SPI: the start byte is `0 1 1 1 0 ID RS RW` (ID = level of the IM0/ID pin, RS = 0 index / status, 1 register /
GRAM, RW = 0 write, 1 read), MSB first, nCS frames the whole transfer. A GRAM read returns 5 dummy bytes after the
start byte before the pixel data, a status / register read returns 1 dummy byte.

Reads: the first GRAM read after setting the address is a dummy read (the read data register is one access behind),
then every read returns one pixel and the address counter advances. In 65k format the 8 / 16 bit buses and SPI
return the upper 16 bits RD17..RD2 (RGB565), the 9 / 18 bit buses the full 18 bits. Register R00h returns the device
code 9325h.

## 3 GRAM, address counter and window

GRAM addresses are `AD[16:0]`: AD[7:0] is the column (00h .. EFh, 240 columns), AD[16:8] the line (000h .. 13Fh,
320 lines). R20h sets AD[7:0], R21h sets AD[16:8]; writing R21h loads the address counter (AC). Every write to
R22h stores one pixel and moves the AC by +1 or -1 according to the entry mode:

| R03h bit | Name | Meaning |
|---|---|---|
| D3 | AM | 0: horizontal update (column changes first), 1: vertical update (line changes first) |
| D4 | I/D0 | 1: column increments, 0: decrements |
| D5 | I/D1 | 1: line increments, 0: decrements |
| D7 | ORG | origin moves with I/D inside a window (high speed write, keep 0 for reads) |
| D12 | BGR | 1: swap R and B when writing |
| D14 | DFM | transfer format with TRI = 1 (see section 2) |
| D15 | TRI | 1: 18 bit pixels on the 8 / 16 bit bus or SPI |

Window address area (R50h .. R53h): HSA/HEA (columns) and VSA/VEA (lines) limit the GRAM area that the AC runs
through, with wrap to the next line / column at the window edge. Rules: `00h <= HSA < HEA <= EFh`,
`000h <= VSA < VEA <= 13Fh`, the datasheet asks for `HEA - HSA >= 4`. The AC must be set inside the window.
In high speed (ORG) mode the GRAM is written in four pixel units, which is not used by the head.

The display shows GRAM line 0 on the gate selected by SCN (R60h) in the direction GS, and column 0 on S1 or S720
depending on SS (R01h). The scan direction bits change the output mapping only, the GRAM is not rearranged
("when changing SS or BGR, RAM data must be rewritten").

## 4 Registers

Write with RS = 0 the index, then with RS = 1 the 16 bit value. Reset values are 0000h unless noted.

| Index | Name | Bits | Function |
|---|---|---|---|
| 00h | Driver code | read | 9325h. Writing 0001h ("start oscillator") is used by the vendor init sequences and is referenced by the sleep / standby text, it is not in the register table |
| 01h | Driver output control | SS (D8), SM (D10) | SS = 1 shifts S720 -> S1 (horizontal mirror), SM gate scan mode (interlace) |
| 02h | LCD driving wave | B/C (D9), EOR (D8) | 0700h: line inversion |
| 03h | Entry mode | see section 3 | |
| 04h | Resize control | RSZ, RCH, RCV | 0000h: no resizing |
| 07h | Display control 1 | D1 D0 (D1:D0), CL (D3), DTE (D4), GON (D5), BASEE (D8), PTDE1/0 (D13:D12) | Display on = 0133h (BASEE, GON, DTE, D = 11), off = 0000h; CL = 1 selects 8 colors |
| 08h | Display control 2 | FP (D11:D8), BP (D3:D0) | front / back porch 2 .. 14 lines, FP + BP <= 16, 0202h |
| 09h | Display control 3 | PTS, PTG, ISC | non display area levels, interval scan |
| 0Ah | Display control 4 | FMARKOE, FMI | frame marker output |
| 0Ch | RGB interface control 1 | RIM, DM, RM, ENC | 0000h: system interface, internal clock |
| 0Dh | Frame marker position | FMP | |
| 0Fh | RGB interface control 2 | DPL, EPL, HSPL, VSPL | signal polarities |
| 10h | Power control 1 | STB (D0), SLP (D1), AP (D6:D4), APE (D7), BT (D10:D8), SAP (D12) | STB standby, SLP sleep, AP amplifier current, APE power supply enable, BT step-up factor, SAP source driver enable |
| 11h | Power control 2 | VC (D2:D0), DC0 (D6:D4), DC1 (D10:D8) | VCI1 ratio (111 = 1.0 x VCI), step-up frequencies |
| 12h | Power control 3 | VRH (D3:D0), PON (D4), VCIRE (D7) | VREG1OUT = VCI x 1.6 .. 2.4, PON enables VGL, VCIRE internal 2.5 V reference |
| 13h | Power control 4 | VDV (D12:D8) | VCOM amplitude 0.70 .. 1.24 x VREG1OUT |
| 20h / 21h | GRAM address | AD[7:0] / AD[16:8] | column / line of the address counter |
| 22h | GRAM data | 18 bit | write / read port, see section 2 |
| 29h | Power control 7 | VCM (D5:D0) | VCOMH = VREG1OUT x (0.685 + 0.005 x VCM) |
| 2Bh | Frame rate | FRS (D3:D0) | 0 = 30 Hz .. 8 = 51, 9 = 56, Ah = 62, Bh = 70, Ch = 80, Dh = 93, Eh = 112 Hz |
| 30h .. 3Dh | Gamma control 1 .. 10 | KP, RP, VRP, KN, RN, VRN | gamma curve, panel specific |
| 50h / 51h | Horizontal address start / end | HSA / HEA (D7:D0) | window columns, reset 00h / EFh |
| 52h / 53h | Vertical address start / end | VSA / VEA (D8:D0) | window lines, reset 000h / 13Fh |
| 60h | Gate scan control 1 | SCN (D5:D0), NL (D13:D8), GS (D15) | scan start gate, number of lines (NL + 1) x 8, GS = 1 scans G320 -> G1 (vertical mirror); A700h = 320 lines, mirrored |
| 61h | Gate scan control 2 | REV (D0), VLE (D1), NDL (D2) | REV = 1 grayscale inversion (normal panels need it), VLE vertical scroll enable |
| 6Ah | Vertical scroll | VL (D8:D0) | scroll amount in lines |
| 80h .. 85h | Partial image 1 / 2 | PTDP, PTSA, PTEA | display position, RAM start / end line |
| 90h | Panel interface control 1 | RTNI (D4:D0), DIVI (D9:D8) | clocks per line (16 .. 31) and clock divider, 0010h |
| 92h | Panel interface control 2 | NOWI (D10:D8) | gate non-overlap period, 0600h |
| 95h / 97h | Panel interface control 4 / 5 | RTNE, DIVE, NOWE | the same for the RGB interface |
| A1h / A2h / A5h | OTP VCM | | one time programming of the VCOMH value (key AA55h) |

## 5 Orientation

The controller has no rotation. The head maps logical coordinates to GRAM addresses and selects the AC direction
so that a logical row major stream is written with native auto increment. The GRAM stays 240 columns x 320 lines
with SS = 1 and GS = 1 (the common module wiring) as the base for `orientation_0`.

| Orientation | Logical size | R03h AM, I/D | logical (x, y) -> GRAM (column, line) |
|---|---|---|---|
| `orientation_0` | 240 x 320 | 0, 11 (0030h) | (x, y) |
| `orientation_0m` | 240 x 320 | 0, 01 (0010h) | (x, 319 - y) |
| `orientation_180` | 240 x 320 | 0, 00 (0000h) | (239 - x, 319 - y) |
| `orientation_180m` | 240 x 320 | 0, 10 (0020h) | (239 - x, y) |
| `orientation_90` | 320 x 240 | 1, 10 (0028h) | (239 - y, x) |
| `orientation_90m` | 320 x 240 | 1, 00 (0008h) | (239 - y, 319 - x) |
| `orientation_270` | 320 x 240 | 1, 01 (0018h) | (y, 319 - x) |
| `orientation_270m` | 320 x 240 | 1, 11 (0038h) | (y, x) |

The `m` orientations mirror the physical screen top/bottom after the rotation, like the MAX7219 and SSD1306 heads.
A window (blit) is set with the mapped corners of the logical rect, the AC then wraps inside the window in the
configured direction.

## 6 Power sequences

Power on (Figure 44): VCI and IOVCC on, power on reset / display off; registers before power supply start-up;
power supply initial settings (VC, VRH, VCM, VDV, PON = 0, BT = 000), wait >= 50 ms; power supply operation
settings (BT, PON = 1, AP, APE = 1, DC0, DC1), wait >= 80 ms for the step-up circuits; other registers; display on
(SAP = 1, DTE = 1, D = 11, GON = 1).

Display off / power off: DTE = 0, D = 00, GON = 0, PON = 0; power supply halt SAP = 0, AP = 000; then VCI / IOVCC off.

Standby / sleep (Figure 43): after the display off sequence set STB = 1 (standby, only the GRAM is powered) or
SLP = 1 (sleep, only the RC oscillator runs). Wake up: STB = 0 / SLP = 0, write R10h = 0190h, wait >= 80 ms, display
on sequence. In standby / sleep only "exit" and "start oscillation" are accepted.

## 7 The vic head `src/head/ILI9325.h`

```cpp
vic::head::ILI9325<Screen_Size_X = 240, Screen_Size_Y = 320,  // logical size, 320 x 240 for orientation_90 / 270
                   Orientation    = drv::orientation_0,
                   Interface_Mode = 0,                        // 0 device (SPI), 8 / 9 / 16 / 18 bit memory bus
                   Color_256k     = false,                    // RGB666 pixels (the 9 / 18 bit buses are always 18 bit)
                   RGB_to_BGR     = false>                    // entry mode BGR bit
ILI9325(io::handle_type device, void* mem_reg_addr, void* mem_data_addr, bool spi_id_bit);
```

- Device mode: `io::write()` option 0 = index register (2 bytes, 00h idx), option 1 = data (2 or 3 bytes); the io
  layer builds the SPI start byte from the option and handles the 5 dummy bytes of a read. Memory modes write the
  index and data registers with `io::mem::write()` in the bus width.
- init: vendor power on sequence with the 50 / 80 / 20 ms waits, entry mode from the orientation table, frame rate
  80 Hz (2Bh 000Ch), gamma set, full GRAM window, gate scan A700h, REV = 1, then clear.
- Drawing: `pixel_set()` sets R20h / R21h only if the AC is not already at the pixel (tracked along logical x),
  `line_horz()` is one address and a pixel stream, `blit()` sets the window to the clipped block, streams it and
  restores the full window, `cls()` streams the whole GRAM from logical (0, 0).
- `pixel_get()` reads one pixel (RGB565 on the 8 / 16 bit buses and SPI, 18 bit on the 9 / 18 bit buses), returns
  `color::none` if the interface can't read (SPI io layer without read support).
- `display_enable()` writes R07h 0133h / 0000h (GRAM retained), `shutdown()` runs the display off sequence and
  enters sleep (SLP = 1); `init()` wakes the controller up again.

Review against the datasheet (changed in head version 0.30):

1. Orientation was accepted as template parameter but never used; all eight orientations are implemented now
   (section 5).
2. 9 bit bus: register data was sent as `data >> 9` and `data`, the datasheet wants the upper and lower byte on
   DB17..DB10 (`byte << 1`, DB9 unused). Pixels keep the 9 + 9 bit split.
3. 18 bit bus: the index was written shifted by one (`idx << 1`); register bits D15..D0 are on DB15..DB0.
4. The 9 and 18 bit buses transfer 18 bit pixels only, `Color_256k = false` produced RGB565 words on them.
5. The GRAM window and the number of lines (R50h .. R53h, R60h) are derived from the sizes instead of being hard
   coded, `shutdown()` now runs the display off and sleep sequence instead of clearing the screen.
6. 18 bit read-back on the 8 / 16 bit buses is not documented (Figure 28 shows RD17..RD2 only), the head reads
   RGB565 there. SPI with 18 bit pixels needs TRI = 1, DFM = 1 (3 x 6 bit, left aligned) which the head does not
   emit, keep `Color_256k = false` on SPI.
