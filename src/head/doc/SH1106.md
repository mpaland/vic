# SH1106 programming summary

Source: Sino Wealth, *SH1106 132 X 64 Dot Matrix OLED/PLED Segment/Common Driver with Controller*, V2.2
(revision history up to 2.2, 2012; `SH1106.pdf`, 49 pages). This is the programming view of the datasheet:
interfaces, RAM layout, command set, orientation bits and sequences. The SH1106 is driven by the vic head
`src/head/SSD1306.h` with `Controller = SSD1306_CTRL_SH1106`; the shared head is described in `SSD1306.md`,
section 8 here only covers the SH1106 specific path. Section 9 lists the differences to the SSD1306.

## 1 Overview

| Item | Value |
|---|---|
| Panel | up to 132 segments x 64 commons, monochrome, common cathode panels |
| RAM | 132 x 64 bit = 1056 byte, 8 pages (PAGE0 .. PAGE7) of 132 bytes |
| Supplies | VDD1 1.65 .. 3.5 V (logic), VDD2 3.0 .. 4.2 V (charge pump input), VPP 6.4 .. 14.0 V external or 6.4 .. 9.0 V from the internal pump |
| Voltage generation | internal charge pump with 2 flying capacitors (C1P/C1N, C2P/C2N), output 6.4 / 7.4 / 8.0 / 9.0 V selected by 30h .. 33h, enabled by ADh 8Bh |
| Interfaces | 8 bit 6800, 8 bit 8080, 4-wire SPI, 3-wire SPI, I2C 400 kHz (IM[2:0] pins) |
| Brightness | 256 step contrast (81h), segment current max 200 uA, IREF 12.5 uA |
| Oscillator | internal RC oscillator (CLS = H) or external clock on CL (CLS = L), fOSC 315 / 360 / 420 kHz (min / typ / max) |
| Extras | segment remap (ADC), COM scan direction, display start line (vertical scroll), display offset, read-modify-write mode, status read |
| Not available | horizontal / vertical addressing modes, column / page windows, hardware scrolling commands |

State after RES# (datasheet "Reset Circuit", p. 18): display off with SEG/COM in high impedance, 132 x 64 mode,
no remap (SEG0 = column 00h, COM0 = row 00h), serial shift register cleared, start line 0, column counter 0,
normal COM scan direction, contrast 80h, internal DC-DC selected (ADh 8Bh). Other POR values from the command
table (p. 30-31): page B0h, pump voltage 32h (8.0 V), MUX 3Fh, offset 00h, clock D5h 50h, precharge D9h 22h,
COM pads DAh 12h, VCOM DBh 35h.

## 2 Interfaces

Control pins: `CS#`, `A0` (= D/C#: 0 command, 1 display data; SA0 in I2C mode), `RES#`, `RD#(E)`,
`WR#(R/W#)`, `D[7:0]`. In serial and I2C mode D0 = SCL, D1 = SI / SDA, D7 .. D2 are high impedance and
should be tied to VDD1 or VSS (open is allowed).

| Interface | IM0 | IM1 | IM2 | Notes |
|---|---|---|---|---|
| 6800 | 0 | 0 | 1 | R/W# = 1 read, 0 write, E high = latch while CS# = 0 |
| 8080 | 0 | 1 | 1 | data latched on the rising edge of WR#, RD# low = bus output |
| 4-wire SPI | 0 | 0 | 0 | SCL, SI, A0, CS#; write only |
| 3-wire SPI | 1 | 0 | 0 | 9 bit frames, A0 tied low; write only |
| I2C | 0 | 1 | 0 | SCL, SDA, A0 = SA0, CS# tied low |

The pad table on p. 4 and Table 1 on p. 8 agree on this coding (note that it differs from the SSD1306 BS
pins).

- 4-wire SPI (p. 10): SI is shifted in MSB first on every rising edge of SCL, A0 is sampled on the 8th
  clock. A falling edge of CS# starts a transfer, CS# high resets the shift register and counter. CS#
  permanently low works but is not recommended.
- 3-wire SPI (p. 11): 9 bit shift register, first bit D/C# (1 = RAM, 0 = command), then D7 .. D0.
- I2C (p. 13-14): slave address `011110 SA0` (3Ch / 3Dh), slave mode only, pull-ups to VDD1. After the
  address follow control bytes `Co D/C# 0 0 0 0 0 0`: Co = 1 means one data byte and then another control byte,
  Co = 0 means only data bytes follow; D/C# = 0 command, 1 RAM data. So `00h` starts a command stream, `40h` a
  data stream, `80h` / `C0h` a single command / data byte, identical to the SSD1306.
- Reads: on the parallel buses a dummy read is required after setting the address before the first real data
  read (Figure 1, p. 9). The status read (A0 = 0) returns `BUSY ON/OFF x x x 0 0 0`: bit 7 = BUSY (commands
  are rejected while high, "busy check is not required if enough time is provided"), bit 6 = 1 display off.
  The serial sections say "read is not possible while in serial interface mode" and the read data command says
  "no display data can be read via the serial interface", while the I2C protocol section (p. 13) describes
  reading status and RAM data with R/W# = 1 ("output data immediately after the slave-address according to the
  D/C bit, which was sent during the last write access"). The datasheet contradicts itself here and does not
  mention a dummy read for I2C; treat I2C reads as unverified.

AC timing (p. 37-44), values for VDD1 = 2.4 .. 3.5 V, in brackets for 1.65 .. 3.5 V:

| Bus | Key values |
|---|---|
| 8080 | tCYC8 >= 300 ns (600), WR# low >= 100 ns (200), RD# low >= 120 ns (240), data setup 40 ns (80), RD# access <= 140 ns (280) |
| 6800 | tCYC6 >= 300 ns (600), same structure as 8080 |
| 4-wire SPI | tSCYC >= 250 ns (500), i.e. 4 MHz (2 MHz); SCL high / low >= 100 ns (200), A0 and data setup 150 / 100 ns (300 / 200) |
| 3-wire SPI | tSCYC >= 250 ns (500) |
| I2C | fSCL <= 400 kHz, tLOW >= 1.3 us, tHIGH >= 0.6 us, data setup >= 100 ns |
| Reset | RES# low tRW >= 5 us (10 us), internal reset done tR <= 1 us (2 us) |

## 3 Display data RAM

The RAM is 8 pages of 132 bytes. One byte holds 8 vertical pixels of one column: D0 is the top row of the page
(line 8 x page), D7 the bottom row (Figure 8, p. 16). Without remap column 00h drives SEG0 and column 83h
(131) drives SEG131; with ADC = 1 (A1h) column 83h drives SEG0.

There is only page addressing (p. 15, 19):

- The page is set with B0h .. B7h, the column with two commands: 00h .. 0Fh (lower 4 bits) and 10h .. 1Fh
  (upper 4 bits), column 0 .. 131.
- The column counter increments after every data write and read "until address 131 is accessed"; the page
  is not changed. The datasheet does not state what happens after column 131 (no wrap to the next page is
  described), so every page has to be addressed explicitly. The example on p. 15: going from page 0 column 83h to
  page 1 column 00h needs both the page and the column address again.
- A whole 132 x 64 frame is 8 transfers of `B0h | page, 00h | col_lo, 10h | col_hi, data[132]`.

128 pixel wide panels are normally wired to SEG2 .. SEG129, i.e. RAM columns 2 .. 129 (column offset 2); this
is a module property, the datasheet itself only describes the 132 column RAM. With the symmetric 2 column margin
the offset stays 2 with and without segment remap.

The display start line (40h .. 7Fh) selects the RAM line shown on COM0 (COM63 with reversed scan), changing it
scrolls the display vertically. The display offset (D3h) shifts the COM mapping instead.

Read-modify-write (E0h / EEh, p. 28): after E0h the column address is incremented by writes only, not by reads;
EEh returns the column to the value it had at E0h. Sequence: page, column, E0h, dummy read, then read / modify /
write per byte, EEh.

## 4 Command set

All commands are written with A0 = 0. Two byte commands (81h, A8h, ADh, D3h, D5h, D9h, DAh, DBh) take their
parameter as the next command byte. "Do not use any other command, or the system malfunction may result"
(p. 31).

| Hex | Parameters | Reset | Function |
|---|---|---|---|
| 00 .. 0F | - | 00h | Lower 4 bits of the column address |
| 10 .. 1F | - | 10h | Upper 4 bits of the column address (column 0 .. 131) |
| 30 .. 33 | A[1:0] in the opcode | 32h | Charge pump output VPP: 30h 6.4 V, 31h 7.4 V, 32h 8.0 V, 33h 9.0 V |
| 40 .. 7F | A[5:0] in the opcode | 40h | Display start line 0 .. 63 |
| 81 | A[7:0] | 80h | Contrast, ISEG = A / 256 x IREF x 16; "set 80h when the contrast control is not used" |
| A0 / A1 | - | A0h | Segment remap (ADC): column 0 -> SEG0 / column 131 -> SEG0 |
| A4 / A5 | - | A4h | Display follows the RAM / entire display on (RAM is kept, has priority over A6h / A7h) |
| A6 / A7 | - | A6h | Normal (RAM 1 = pixel on) / reverse display |
| A8 | A[5:0] | 3Fh | Multiplex ratio A + 1 = 1 .. 64 |
| AD | 8Ah / 8Bh | 8Bh | DC-DC control: 8Bh = DC-DC turned on with the next display on, 8Ah = off (external VPP); only while the display is off |
| AE / AF | - | AEh | Display off (sleep mode) / on |
| B0 .. B7 | A[3:0] in the opcode | B0h | Page address 0 .. 7 |
| C0 / C8 | D3 = direction, D2 .. D0 don't care | C0h | COM scan COM0 -> COM[N-1] / COM[N-1] -> COM0, immediate effect (vertical flip) |
| D3 | A[5:0] | 00h | Display offset (COM shift), e.g. 10h moves COM16 to COM0, 64 - 16 = 30h the other way |
| D5 | A[3:0] divide - 1, A[7:4] oscillator | 50h | Divide ratio 1 .. 16; oscillator 0h = -25 % .. 5h = nominal .. Fh = +50 % in 5 % steps |
| D9 | A[3:0] precharge, A[7:4] discharge | 22h | Periods in DCLK 1 .. 15 each, 0 is invalid |
| DA | `0 0 0 D 0 0 1 0` | 12h | COM pads: 02h sequential, 12h alternative (see below) |
| DB | A[7:0] | 35h | VCOM deselect level, VCOM = beta x VREF, beta = 0.430 + A x 0.006415 for 00h .. 3Fh (35h = 0.770), 40h .. FFh: beta = 1 |
| E0 | - | - | Start read-modify-write |
| E3 | - | - | NOP |
| EE | - | - | End read-modify-write, column returns to the start |

Data access (A0 = 1): write display data (column + 1), read display data (column + 1, dummy read first, parallel
only). Status read: A0 = 0 with RD#, see section 2.

DC-DC status (Table 8, p. 22): DC-DC on + display on = built-in DC-DC drives the panel; DC-DC off + display on
= external VPP must be supplied; display off = sleep in both cases.

COM pad configuration (p. 26): sequential (02h) maps COM31 .. 0 to one side and COM32 .. 63 to the other;
alternative (12h, POR) maps COM62, 60 .. 0 to one side and COM1, 3 .. 63 to the other. 128 x 64 modules use the
alternative mode. There is no left / right swap bit (the SSD1306 DAh A[5]).

Sleep mode (AEh, p. 23): stops the oscillator and the DC-DC, SEG/COM outputs Hz, RAM and settings are kept,
the MCU can still access the RAM.

## 5 Orientation

Like the SSD1306 two bits mirror the image, 90 degree rotations need a rotated framebuffer:

| Orientation | Segment remap | COM scan |
|---|---|---|
| `orientation_0` | A0h | C0h |
| `orientation_0m` | A0h | C8h |
| `orientation_180m` | A1h | C0h |
| `orientation_180` | A1h | C8h |

A1h maps RAM column 131 to SEG0, so a panel on SEG2 .. SEG129 shows RAM columns 129 .. 2 and the column offset
of 2 is still correct. The datasheet does not say whether the segment remap affects RAM data written before
(the SSD1306 only remaps new data); the head writes the whole RAM after init anyway.

## 6 Power on / off and initialization

Power on with the built-in DC-DC (p. 32):

1. VDD1 and VDD2 on with RES# = L, keep RES# low > 10 us after the power is stable.
2. RES# = H, wait > 2 us (initialized default state).
3. Panel setup: A0h / A1h, DAh, C0h / C8h, A8h, D5h.
4. DBh, 81h, 30h .. 33h (pump voltage "suggested from factory").
5. Clear the RAM to 00h.
6. ADh 8Bh, wait until VPP is stable ("typically 100 ms").
7. AFh, "typically 150 ms" wait.
8. Start line, page, column, display data.

With external VPP (p. 33): VDD1 on with RES# low > 10 us, release RES#, the same setup and RAM clear, then
external VPP on and wait for it to stabilize (typ. 100 ms), ADh 8Ah, AFh, typically 50 ms wait, then data.

Power off (p. 34): AEh, external VPP off, wait until VPP reaches 0 V (typ. 100 ms), then VDD1 / VDD2 off.

IREF: resistor R1 from IREF to VSS, `R1 = (V(IREF) - VSS) / 12.5 uA`, about 510 kOhm in the application circuits.
Application capacitors: 4.7 uF on VDD/VCOMH/VPP, 0.22 uF flying capacitors (p. 45-48). VDD2 has to be left
disconnected when VPP is supplied externally (revision 2.1 / 2.2 note).

Frame rate: 104 Hz typ. at fOSC = 360 kHz, divide ratio 1, 64 MUX and 54 DCLK per row (p. 36); the 54 DCLK
correspond to the POR periods 2 + 2 plus 50, like the K of the SSD1306.

## 8 The vic head `src/head/SSD1306.h` on the SH1106

```cpp
vic::head::SSD1306<128, 64, drv::orientation_0, SSD1306_I2C, true /* Framebuffer */, true /* Charge_Pump */,
                   SSD1306_CTRL_SH1106 /* Controller */, 2 /* Column_Offset, the default for the SH1106 */>
```

See the vic head section of `SSD1306.md` for the template parameters, the io layer convention and the
framebuffer.
SH1106 specific behaviour:

- init: `AE, A8 N-1, D3 00, 40, A0/A1, C0/C8, DA 12 (02 for 32 lines), 81 7F, A4, A6, D5 80, AD 8B (AD 8A without charge pump), D9 22,
  DB 30, AF`; the memory addressing mode command 20h is skipped for the SH1106. Then `cls()` and `present()`.
- `set_address()` sends `B0h | page, 00h | (col & 0Fh), 10h | (col >> 4)` with `col = x + Column_Offset`, the
  end column and end page are ignored.
- `present()` addresses every page separately and sends `Screen_Size_X` bytes per page (I2C: control byte 40h
  per block, blocks of 32 data bytes). Columns 0, 1, 130, 131 are never written.
- Without framebuffer a pixel is a read-modify-write of one page byte with the address set twice (the read moves
  the column counter); the E0h / EEh mode of the SH1106 is not used. Reads need a parallel bus.

Crosscheck against the datasheet:

| Item | Head | Datasheet | Assessment |
|---|---|---|---|
| Addressing | page mode only, 20h / 21h / 22h not sent | page mode only | correct |
| Column offset 2, remap A1h | offset 2 in both remap states | column 131 -> SEG0 with A1h | correct for panels on SEG2 .. SEG129 |
| Charge pump on | `AD 8B` before AFh, display off | DC-DC only while display off, on with AFh | correct |
| Charge pump off (`Charge_Pump = false`) | `AD 8A` before AFh | POR is DC-DC on (8Bh); the external VPP flow sends `AD 8A` | correct (fixed, no command was sent before and the internal DC-DC stayed on) |
| D5 80h | divide 1, A[7:4] = 8 | 8 = +15 % oscillator, POR 50h | works, about 15 % higher frame rate than POR |
| DB 30h | meant as 0.83 x VCC (SSD1306 coding) | beta = 0.430 + 48 x 0.006415 = 0.738, POR 35h = 0.770 | works, different meaning, slightly below POR |
| 81 7Fh | contrast 7Fh | POR 80h | no issue |
| Delays | none after AD 8B / AFh | typ. 100 ms after the DC-DC is enabled, 150 ms after AFh | minor; RAM access is allowed meanwhile, only the panel voltage ramps later |
| Reset pulse | done by `io::init()` | RES# low >= 10 us at VDD1 < 2.4 V (5 us above) | io layer must respect it (SSD1306: 3 us) |
| SPI clock | io layer | max 4 MHz (2 MHz below 2.4 V) | lower than the 10 MHz of the SSD1306, the io layer has to limit it |
| Pump voltage 30h .. 33h | not sent, POR 8.0 V | "suggested from factory" | acceptable |

## 9 SSD1306 vs SH1106

| Item | SSD1306 | SH1106 |
|---|---|---|
| RAM | 128 x 64 (8 pages x 128) | 132 x 64 (8 pages x 132), 128 pixel panels at columns 2 .. 129 |
| Supplies | VDD 1.65 .. 3.3 V, VCC 7 .. 15 V, VBAT 3.3 .. 4.2 V for the pump | VDD1 1.65 .. 3.5 V, VDD2 3.0 .. 4.2 V for the pump, VPP 6.4 .. 14.0 V |
| Charge pump | 8Dh 14h on / 10h off, POR off | ADh 8Bh on / 8Ah off, POR on; 30h .. 33h set VPP 6.4 .. 9.0 V |
| Bus select | BS[2:0]: 000 4-wire SPI, 001 3-wire, 010 I2C, 100 6800, 110 8080 | IM[0:2]: 000 4-wire SPI, 100 3-wire, 010 I2C, 001 6800, 011 8080 |
| Addressing modes | 20h: page, horizontal, vertical | page only, no 20h |
| Windows | 21h column, 22h page | none |
| 00h .. 1Fh column | page mode only, 7 bit column | always, column 0 .. 131 |
| Column end | wraps inside the page (page mode) | increments "until 131", wrap not specified |
| Scrolling | 26h / 27h / 29h / 2Ah / 2Eh / 2Fh / A3h | none, only the start line |
| Read-modify-write | no | E0h / EEh |
| Status byte | bit 6 = display off | bit 7 = BUSY, bit 6 = display off |
| Contrast POR | 7Fh | 80h |
| Segment current | max 100 uA | max 200 uA |
| MUX (A8h) | 16 .. 64 | 1 .. 64 |
| D5h POR | 80h | 50h, oscillator in 5 % steps |
| D9h | phase 1 / phase 2, POR 22h | precharge / discharge, POR 22h |
| DAh | A[4] sequential / alternative, A[5] left/right remap | only D4 sequential / alternative |
| DBh | A[6:4]: 00h 0.65, 20h 0.77, 30h 0.83 x VCC, POR 20h | A[7:0], beta = 0.430 + A x 0.006415, POR 35h = 0.770 |
| Reset pulse | >= 3 us | >= 5 us (>= 10 us below 2.4 V) |
| SPI clock | 10 MHz | 4 MHz (2 MHz below 2.4 V) |
| I2C | 3Ch / 3Dh, 400 kHz, write only | 3Ch / 3Dh, 400 kHz, reads described (contradictory) |
| Same | 40h start line, 81h, A0h / A1h, A4h .. A7h, A8h, AEh / AFh, B0h .. B7h, C0h / C8h, D3h, E3h, the I2C control byte | |

Plain SSD1306 code does not work on an SH1106: 20h / 21h / 22h are not SH1106 commands ("do not use any other
command"), the column counter never advances to the next page and column 0 is not the first visible column.
The typical symptom is an image shifted by two columns with the lower pages missing.
