# SSD1322 programming summary

Source: Solomon Systech *SSD1322 480 x 128, 16 Gray Scale Dot Matrix OLED/PLED Segment/Common Driver with
Controller* Rev 1.2 (`SSD1322.pdf`), the controller of the 256 x 64 gray scale OLED modules (Newhaven
NHD-3.12, 2.7" / 3.12" modules). The last section describes the vic head `src/head/SSD1322.h`.

## 1 Overview

| Item | Value |
|---|---|
| Panel | up to 480 segments x 128 commons, 16 gray levels |
| GDDRAM | 480 x 128 x 4 bit = 30 KB, two pixels per byte |
| Supplies | VDD 2.4 .. 2.6 V (or internal regulator from VCI 2.4 .. 3.5 V), VCC 10 .. 20 V panel |
| Interfaces | 8 bit 6800 / 8080, 4 wire SPI, 3 wire SPI (BS[1:0] pins), write only on SPI |
| Brightness | contrast current C1h (256 steps), master contrast C7h (16 steps), 15 entry gray scale table |
| Clock | Fosc divided by 1 .. 1024 (B3h), frame rate = Fosc / (D x K x MUX), K = phase 1 + phase 2 + 122 at reset |

## 2 Interface

4 wire SPI: `CS#`, `D/C#` (0 command, 1 parameters / data), `SCLK`, `SDIN`, MSB first, clock cycle >= 100 ns
(10 MHz). Command parameters are sent with D/C# = 1, exactly like RAM data. Reads need the parallel bus.

## 3 RAM organisation

Column addresses (15h) count in units of 4 pixels (two bytes), 0 .. 119, rows (75h) 0 .. 127. A pixel is a
nibble; with the nibble remap bit (A0h A[2]) set the high nibble of a byte is the left pixel, the datasheet
default maps the low nibble to the left pixel. The common 256 x 64 modules sit in the middle of the RAM:
column 28 (1Ch) .. 91 (5Bh), 64 rows. With horizontal increment the pointer runs through the columns of the
window and then the next row, so a 256 x 64 frame is 8192 bytes after setting the window once.

Reference init (NHD-3.12 / u8g2): `FD 12, AE, B3 91, CA 3F, A2 00, A1 00, A0 14 11, B5 00, AB 01, B4 A0 FD,
C1 9F, C7 0F, B9, B1 E2, D1 A2 20, BB 1F, B6 08, BE 07, A6, A9, AF` (A0h 14h = nibble remap + COM scan remap for
the module orientation).

## 5 The vic head `src/head/SSD1322.h`

```cpp
vic::head::SSD1322<Screen_Size_X = 256, Screen_Size_Y = 64,   // logical size, 64 x 256 for orientation_90 / 270
                   Orientation = drv::orientation_0,          // done in software, orientation_0m for the NHD modules
                   Column_Offset = 0x1C,                      // first RAM column in 4 pixel units
                   Contrast = 0x9F>
SSD1322(io::handle_type device);
```

- io layer: `io::write()` option 0 = command, 1 = parameters and data (the D/C# line).
- init: the reference sequence with remap A0h 04h 11h (horizontal increment, nibble remap, dual COM; the
  mirrors are done in software), MUX = rows - 1, clear, present.
- Framebuffer: 4 bit per pixel in physical orientation, high nibble = left pixel, 8 KB for 256 x 64;
  `present()` sets the window (15h offset, offset + width / 4 - 1; 75h 0, rows - 1) and sends the frame after
  5Ch. Colors are reduced with `color::color_to_L4()`.
- `display_enable()` = AFh / AEh, `display_contrast()` = C1h, `display_brightness()` = C7h level / 16,
  `display_inverse()` = A7h / A6h, `shutdown()` = AEh.
- Not covered: partial display, gray scale table, read back.
