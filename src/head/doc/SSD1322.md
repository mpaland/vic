# SSD1322 programming summary

Source: Solomon Systech, *SSD1322 480 x 128, Dot Matrix High Power OLED/PLED Segment/Common Driver with
Controller*, Advance Information Rev 1.2, Jul 2010 (`SSD1322.pdf`, 60 pages), the controller of the 256 x 64 gray
scale OLED modules (Newhaven NHD-3.12, 2.7" / 3.12" modules). This is the programming view of the datasheet:
interfaces, RAM layout, command set, gray scale and sequences. The last section describes the vic head
`src/head/SSD1322.h` and the review against the datasheet. Related: `SSD1351.md` (same command family, RGB).

## 1 Overview

| Item | Value |
|---|---|
| Panel | up to 480 segments x 128 commons, 16 gray levels, common cathode; single COM (128 MUX) or dual COM (64 MUX, two COM pins per row) |
| GDDRAM | 480 x 128 x 4 bit = 30 KB (30720 byte), two pixels per byte |
| Supplies | VCI 2.4 .. 3.5 V, VDDIO 1.65 V .. VCI, VDD 2.4 .. 2.6 V external or from the internal regulator (ABh, needs VCI > 2.6 V), VCC 10 .. 20 V panel supply (external) |
| Interfaces | 8 bit 6800 / 8080, 4-wire SPI, 3-wire SPI (BS[1:0] pins), write only on SPI |
| Brightness | contrast current C1h (256 steps), master contrast C7h (16 steps), segment current max 300 uA (IREF 10 uA) |
| Gray scale | 15 entry gray scale table GS1 .. GS15 (B8h, 0 .. 180 DCLK pulse width) or the linear default (B9h) |
| Clock | Fosc 1.94 MHz typ., divided by 1 .. 1024 (B3h), frame rate = Fosc / (D x K x MUX), K = phase 1 + phase 2 + X, X = 10 + GS15 = 122 at reset, K = 138 at reset |
| Extras | partial display (A8h), display start line / offset, GPIO0 / GPIO1, command lock, external or internal VSL |
| Sleep | AEh, < 10 uA per supply with the RAM kept |

State after RES# (section 8.2): display off, 128 MUX, no remap (SEG0 = column 0, COM0 = row 0), start line 0,
column counter 0, normal COM scan, contrast 7Fh. The other reset values are listed in section 4.

## 2 Interfaces

Control pins: `CS#`, `D/C#` (0 command, 1 data or command parameter), `RES#`, `E(RD#)`, `R/W#(WR#)`, `D[7:0]`.

| BS[1:0] | Interface |
|---|---|
| 00 | 4-wire SPI |
| 01 | 3-wire SPI |
| 10 | 8 bit 8080 |
| 11 | 8 bit 6800 |

(Table 7-2; 0 = VSS, 1 = VDDIO. The pin table calls GPIO0 / GPIO1 "reserved, keep NC" although B5h drives them.)

- Command parameters are sent with D/C# = 1, exactly like RAM data (Table 9-1). 5Ch has to precede RAM data.
- 6800: R/W# = 1 read, 0 write; data latched on the falling edge of E while CS# = 0.
- 8080: rising edge of WR# latches a write, rising edge of RD# a read.
- 4-wire SPI: D0 = SCLK, D1 = SDIN, D2 left open, D3 .. D7, E and R/W# tied low; MSB first on the rising edge of
  SCLK, D/C# sampled on the 8th clock. "Under serial mode, only write operations are allowed."
- 3-wire SPI: 9 bit frames, D/C# bit first, then D7 .. D0; D/C# pin tied low.
- Reads (parallel only): a dummy read is required after setting the address before the first real data byte
  (Figure 8-1 / 8-4). Table 8-2 lists a status read, its content is not documented.

AC timing (section 13, VDDIO = 1.6 V, VCI = 3.3 V):

| Bus | Key values |
|---|---|
| 6800 / 8080 | tcycle >= 300 ns, address setup 10 ns, write data setup 40 ns / hold 7 ns, access time <= 140 ns; 8080 RD# low >= 150 ns, WR# low >= 60 ns |
| 4-wire SPI | tcycle >= 100 ns (10 MHz), SCLK high / low >= 20 ns, D/C# setup / hold 15 ns, data setup / hold 15 ns, CS# setup 20 ns, hold 10 ns |
| 3-wire SPI | tcycle >= 100 ns, same clock and data values |
| Reset | RES# low tRES >= 3 us (Table 13-1); the power on sequence asks for >= 100 us |

## 3 GDDRAM

The RAM is 120 column addresses x 128 rows. One column address covers 4 pixels = 2 bytes, column 0 .. 119
(77h), row 0 .. 127 (7Fh). A pixel is a nibble = gray level GS0 .. GS15.

Byte and nibble order inside a column (Table 8-6 / 8-7, Figure 10-5), D0 = first byte written, D1 = second:

| A[1] col remap | A[2] nibble remap | D1[3:0] | D1[7:4] | D0[3:0] | D0[7:4] |
|---|---|---|---|---|---|
| 0 (reset) | 0 (reset) | SEG0 | SEG1 | SEG2 | SEG3 |
| 0 | 1 | SEG3 | SEG2 | SEG1 | SEG0 |
| 1 | 0 | SEG479 | SEG478 | SEG477 | SEG476 |
| 1 | 1 | SEG476 | SEG477 | SEG478 | SEG479 |

So without remap the 4 pixels of a column arrive as (pixel 3, pixel 2), (pixel 1, pixel 0) with the high nibble
first; with the nibble remap the stream is in natural order: first byte high nibble = SEG0 (left), low nibble =
SEG1, second byte SEG2 / SEG3. The column remap mirrors the whole 480 segment range including the order inside
the column.

Address pointer: 15h sets the column start / end and moves the column pointer to the start, 75h the same for
rows. Horizontal increment (A0h A[0] = 0): after every column (2 bytes) the column pointer increments, at the end
column it returns to the start column and the row increments; after the end row and end column both return to
the start (Figure 10-1 / 10-3). Vertical increment (A[0] = 1): the row increments first, then the column.

The common 256 x 64 modules sit in the middle of the RAM: column 28 (1Ch) .. 91 (5Bh) = SEG112 .. SEG367, 64
rows. With horizontal increment the pointer runs through the columns of the window and then the next row, so a
256 x 64 frame is 8192 bytes after setting the window once. The 28 column margin is symmetric (119 - 91 = 28),
so the window stays the same with the column remap.

Display start line (A1h) selects the RAM row shown on COM0, the display offset (A2h) shifts the COM mapping
(Figure 10-8 / 10-9). Partial display (A8h start row, end row) shows only that row range, A9h exits.

Datasheet inconsistencies:

- A4h .. A7h: Table 9-1 says A4h all off, A5h all on, A6h normal, A7h inverse; section 10.1.9 labels A4h "normal"
  and A6h "entire display off". The reference sequences use A6h as normal display, which matches the table.
- B3h: Table 9-1 gives the divider as 1 .. 1024 in powers of two, section 10.1.15 says 1 .. 16 with reset 1.
- B1h: Table 9-1 says phase 1 is 5 .. 31 DCLK, section 10.1.14 "5 to 31 in the unit of 2 DCLKs".
- B9h: section 10.1.20 lists GS2 = 2, Table 9-1 and Figure 8-13 GS2 = 8 (step 8).
- D1h: Table 9-1 marks A[5:4] = 00b reserved and 10b normal, section 10.1.26 recommends 00b.
- A[4] (COM scan) is described as "A[1]" in section 10.1.6 (typo).
- MUX ratio: the frame rate text of section 8.5 refers to "command A8h", the MUX command is CAh (A8h is the
  partial display).

## 5 Orientation

Hardware options: A[1] column remap mirrors horizontally (together with A[2] for the in-column order, see
section 3), A[4] COM scan remap mirrors vertically, A[0] vertical increment changes the fill direction. Because a
column address is 4 pixels wide, 90 degree rotations are not possible in hardware.

The vic head keeps the remap at A0h `04h 11h` (horizontal increment, nibble remap, dual COM up to 64 rows, no mirror) and maps
all orientations in software in its framebuffer (`to_phys()`, W / H = physical width / height):

| Orientation | physical (x, y) from logical (x, y) |
|---|---|
| `orientation_0` | (x, y) |
| `orientation_0m` | (x, H - 1 - y), upright on the NHD modules |
| `orientation_180` | (W - 1 - x, H - 1 - y) |
| `orientation_180m` | (W - 1 - x, y) |
| `orientation_90` | (W - 1 - y, x) |
| `orientation_90m` | (W - 1 - y, H - 1 - x) |
| `orientation_270` | (y, H - 1 - x) |
| `orientation_270m` | (y, x) |

## 6 Power, reset, gray scale

Power on (section 8.9, Figure 8-14, internal VDD, VCI = VDDIO):

1. VCI and VDDIO on, wait >= 1 ms (t0) for the internal VDD.
2. RES# low for >= 100 us (t1), then high; the registers are reset after t1.
3. >= 100 us after RES# low (t2) switch VCC on.
4. When VCC is stable send AFh; SEG/COM are on after 200 ms (tAF).
5. "After VCI become stable, wait for at least 300 ms to send command."

Power off: AEh, VCC off (floating), wait tOFF (typ. 100 ms, min 0 ms), then VCI / VDDIO off. VCI / VDDIO must
not be switched off before VCC; VDD and VCC must never be pulled to ground.

VDD regulator (section 8.10): ABh A[0] = 1 enables it (typ. 2.5 V), VCI must be > 2.6 V; with VCI < 2.6 V VDD has
to come from an external source and ABh 00h is required. VCI >= VDD and VCI >= VDDIO always.

IREF (section 8.6): `ISEG = contrast / 256 x IREF x scale factor x 2`, scale factor 1 .. 16 from C7h. The IREF pin
is at VCC - 6 V, so `R1 = (VCC - 6 V) / 10 uA`, 1.2 MOhm at VCC = 18 V. VSL: external VSL (B4h A0h) needs the
resistor and diode network on VSL (application example: 50 Ohm and two 1N4148 to ground).

Segment drive (section 8.7): phase 1 reset (B1h A[3:0]), phase 2 first precharge to VP (B1h A[7:4], level BBh),
phase 3 second precharge (B6h), phase 4 current drive with the PWM width from the gray scale table.

Gray scale (section 8.8): GS0 has no precharge and no current drive, GS1 has phase 2 only. B8h is followed by
15 bytes GS1 .. GS15 (0 .. 180 DCLK, increasing, GS1 may be 0) and must be activated with 00h. B9h loads the linear
table GS0 = 0, GS1 = 0, GS2 = 8, GS3 = 16 .. GS14 = 104, GS15 = 112. The frame rate depends on GS15 (X = 10 +
GS15). A gamma table compensates the panel response (Figure 10-15).

Reference init (NHD-3.12 / u8g2): `FD 12, AE, B3 91, CA 3F, A2 00, A1 00, A0 14 11, B5 00, AB 01, B4 A0 FD,
C1 9F, C7 0F, B9, B1 E2, D1 A2 20, BB 1F, B6 08, BE 07, A6, A9, AF` (A0h 14h = nibble remap + COM scan remap for
the module orientation).

| Parameter | Value |

| VCC / VCI / VDD / VDDIO | 10 .. 20 V / 2.4 .. 3.5 V / 2.4 .. 2.6 V / 1.65 V .. VCI; absolute max VCC 21 V, VCI 4.0 V, VDD 2.75 V |

## 8 The vic head `src/head/SSD1322.h`

```cpp
vic::head::SSD1322<Screen_Size_X = 256, Screen_Size_Y = 64,   // logical size, 64 x 256 for orientation_90 / 270
                   Orientation = drv::orientation_0,          // done in software, orientation_0m for the NHD modules
                   Column_Offset = 0x1C,                      // first RAM column in 4 pixel units
                   Contrast = 0x9F>
SSD1322(io::handle_type device);
```

- io layer: `io::write()` option 0 = command, 1 = parameters and data (the D/C# line).
- init: the reference sequence with remap A0h 04h 11h (horizontal increment, nibble remap, dual COM up to 64 rows; the
  mirrors are done in software), MUX = rows - 1, clear, present.
- Framebuffer: 4 bit per pixel in physical orientation, high nibble = left pixel, 8 KB for 256 x 64;
  `present()` sets the window (15h offset, offset + width / 4 - 1; 75h 0, rows - 1) and sends the frame after
  5Ch. Colors are reduced with `color::color_to_L4()`.
- `display_enable()` = AFh / AEh, `display_contrast()` = C1h, `display_brightness()` = C7h level / 16,
  `display_inverse()` = A7h / A6h, `shutdown()` = AEh.
- `static_assert`: physical width multiple of 4, `width / 4 + Column_Offset <= 120`, height <= 128.
- Not covered: partial display, gray scale table, read back.

Crosscheck against the datasheet:

| Item | Assessment |
|---|---|
| Parameters with D/C# = 1, 5Ch before the data | correct |
| A0h 04h 11h | correct: nibble remap gives the high nibble = left pixel stream used by the framebuffer, B = 11h dual COM with A[5] = 0 |
| 15h / 75h window, 8192 byte frame | correct, one window per frame with horizontal increment |
| B3h 91h, B1h E2h, B6h 08h, BBh 1Fh, BEh 07h, C7h 0Fh, B9h | valid values (divide by 2, phase 5 / 14 DCLK, 8 DCLK, 0.60 x VCC, 0.86 x VCC, 16/16, linear table) |
| B4h A0h FDh | per Table 9-1 and section 10.1.16 A0h selects the **external** VSL (A2h = internal). The value is the one of the reference sequence and needs the external VSL network on the module; the head comment said "internal VSL" (fixed) |
| D1h A2h 20h | normal per Table 9-1 (the text of 10.1.26 contradicts) |
| A6h / A7h | normal / inverse per Table 9-1 (section 10.1.9 contradicts) |
| ABh 01h | internal VDD needs VCI > 2.6 V; modules with VCI < 2.6 V need an external VDD and ABh 00h, not configurable |
| Dual COM up to 64 rows | B[4] = 1 requires MUX <= 64; panels with more rows get A0h B = 01h (single COM) | correct (fixed, dual COM was always on) |
| Power on timing | no delay in `init()`; the datasheet wants >= 300 ms after VCI before the first command and AFh only after VCC is stable (io layer / hardware responsibility) |
| Reset pulse | 3 us (Table 13-1) vs 100 us (power on sequence), done by `io::init()` |
