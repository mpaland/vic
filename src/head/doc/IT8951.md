# IT8951 programming summary

Sources: ITE, *IT8951 EPD Timing Controller, Preliminary Specification V0.2.4.3 (for D version)*, 2017/07/28
(52 pages, public copy: <https://files.waveshare.com/upload/1/18/IT8951_D_V0.2.4.3_20170728.pdf>); ITE, *IT8951
Programming Guide (Host I80 Command Based)* v2.7, 2017/09/04, with ITE's example code; E Ink, *E-paper mode
declaration*. The datasheet is marked confidential and is not part of this repository.

The IT8951 drives gray level e-paper panels up to 2048 x 2048, e.g. the Waveshare 6" 800 x 600, 6" HD 1448 x 1072,
9.7" 1200 x 825, 7.8" / 10.3" 1872 x 1404 HATs and the M5Paper (960 x 540). It is driven by the vic head
`src/head/IT8951.h`, described in section 9. The datasheet has the bus protocol, the base commands and the pixel
formats; the display commands, the registers and the init sequence are in the programming guide only. The
reference drivers are compared in section 10, the points which only hardware can settle are listed in section 11.

## 1 Overview

| Item | Value |
|---|---|
| Panel | source / gate driver interface up to 2048 x 2048, AC and DC VCOM panels, 16 / 32 gray levels, variable frame rate |
| Image memory | built-in mobile SDRAM, 32 Mbit (IT8951E / TE / VG) or 64 Mbit (IT8951E-64 / VG-64); the image buffer holds 1 byte per pixel |
| Display engine | 8 LUT engines with up to 256 frames each, partial region display, waveforms from a serial flash, alpha blending, fill rectangle |
| Host interfaces | Intel 80 / Motorola 68 (16 bit), SPI slave, I2C slave (7 bit address 46h or 35h), USB 2.0 device; selected with TEST_CFG[2:0] (001 = SPI) |
| Host features | all registers and the whole memory are accessible, image load with 0 / 90 / 180 / 270 degree rotation, 2 / 3 / 4 / 8 bit pixels, RGB565 / RGB888 / ARGB8888 to gray conversion, three 2048 x 8 x 4 FIFOs |
| Supplies | core 1.8 V +-0.09 V, I/O and analog 3.3 V +-0.15 V; power on order 1.8 V, then 3.3 V, RESET_N released last |
| Temperature | built-in sensor (external diode 3904 / 3906) or external I2C sensor; operation 0 .. 70 C |
| Packages | LQFP-128 (IT8951E), TQFP-128 (IT8951TE), VFBGA-128 (IT8951VG) |
| Firmware | the chip runs a firmware (ARM core) which implements the host commands; the commands 0034h .. 0302h are firmware commands |

## 2 Power modes

| Command | State | Clocks | SDRAM |
|---|---|---|---|
| SYS_RUN 0001h | active | all on | normal operation |
| STANDBY 0002h | standby | gated off, PLL and oscillator on | self refresh |
| SLEEP 0003h | sleep | PLL, panel power and oscillator off | self refresh |

Standby and sleep are left with SYS_RUN (asynchronous wake up). The image buffer is kept in both modes. The panel
power (source / gate supplies, VCOM) is switched on by the firmware for every display update and off afterwards;
the command 0038h switches it manually and is normally not needed.

## 3 SPI interface

4-wire SPI slave: SPI2_CS_N, SPI2_SCK, SPI2_SI (host to chip), SPI2_SO (chip to host), plus HOST_HRDY (output,
high = ready) and RESET_N (active low).

| Item | Value |
|---|---|
| Mode | 0 (CPOL = 0, CPHA = 0); the datasheet lists mode 0 and 3, the programming guide "mode 0 only" |
| Clock | max. 24 MHz, 12 MHz suggested; about 2 MHz if HRDY can't be polled inside a packet |
| Timing | CS_N low to first clock >= 10 ns, last clock to CS_N high >= 10 ns, clock high / low >= 20 ns, data setup / hold 10 ns |
| Bit / byte order | MSB first, 16 bit words with the high byte first |

Every CS low period is one packet and starts with a 16 bit preamble which selects the packet type. To change the
type the host has to raise CS and start a new packet.

| Packet | Preamble | Content |
|---|---|---|
| Command | 6000h | one command word |
| Write data | 0000h | one or more data words (arguments, register values, pixel words) |
| Read data | 1000h | one dummy word (not valid), then the data words |

- Every command argument is sent as its own write data packet by all drivers; pixel words follow in one or more
  write data packets.
- Reads of more than one word must be one burst (one preamble, one dummy word); single word reads repeated in
  separate packets are not valid for burst data.
- HRDY: the host waits for HRDY = 1 before a packet. ITE also recommends to wait after the preamble and, if
  possible, after every word; otherwise a burst should not exceed 1024 words (2048 bytes, the FIFO size) per packet.
- Reset: RESET_N low (the drivers use 10 .. 100 ms), then wait about 200 ms resp. for HRDY.

Example, write register 0004h = 0001h: `60 00 00 11`, `00 00 00 04`, `00 00 00 01` (three packets). Read register
1224h: `60 00 00 10`, `00 00 12 24`, then `10 00` + dummy word + data word.

The I2C interface uses a preamble byte (00h command, 80h write data, 80h read data) and sends the words low byte
first; the I80 / M68 buses use the HD/C line instead of a preamble.

## 4 Image memory and pixel format

The image buffer holds one byte per pixel, row by row, the gray level left aligned (a 4 bit pixel G3..G0 is stored
as G3 G2 G1 G0 0 0 0 0). 00h is black, F0h is white. Its address comes from GET_DEV_INFO (e.g. 001236E0h) and is
written to the load address register LISAR; all image loads go there.

Load argument (first parameter of LD_IMG / LD_IMG_AREA, same layout as the register MCSR 0200h):

| Bits | Field | Values |
|---|---|---|
| 8 | endian | 0 = little: the first pixel is in the lowest bits of the word; 1 = big: the first pixel is in the highest bits |
| 5:4 | bits per pixel | 00 = 2, 01 = 3, 10 = 4, 11 = 8 |
| 1:0 | rotation | 00 = 0, 01 = 90, 10 = 180, 11 = 270 degree: the image of the host is rotated into the memory |

Pixels are packed into 16 bit words: 4 bit per pixel big endian is `P0 << 12 | P1 << 8 | P2 << 4 | P3`, so on SPI
(high byte first) the first pixel is the upper nibble of the first byte. Little endian is `P3 << 12 | P2 << 8 |
P1 << 4 | P0`. A 3 bit pixel takes 4 bits (bit 0 unused), 8 bit pixels are two per word.

Rules for a load area:

- Every row is a whole number of words.
- The x start should be a multiple of 8 (2 bit), 4 (4 bit) or 2 (8 bit) pixels. For any other position the real
  x, y, width and height stay in the command, but the host sends dummy pixels: `x % 4` in front of each row and up
  to the next multiple of 4 behind it (4 bit). The controller drops them.
- Width and height of a load must be less than 2048. Larger images are split or written with a memory burst
  (8 bit per pixel only).

## 5 Command set

All parameters and data are 16 bit words. (D) = datasheet, (G) = programming guide (firmware commands).

| Code | Command | Parameters | Data | Function |
|---|---|---|---|---|
| 0001h | SYS_RUN (D) | - | - | active state |
| 0002h | STANDBY (D) | - | - | standby |
| 0003h | SLEEP (D) | - | - | sleep |
| 0010h | REG_RD (D) | address | read 1 word | read register |
| 0011h | REG_WR (D) | address | write 1 word | write register |
| 0012h | MEM_BST_RD_T (D) | address[15:0], address[25:16], count[15:0], count[25:16] (words) | - | trigger a memory burst read into the FIFO |
| 0013h | MEM_BST_RD_S (D) | - | read count words | read the FIFO, after 0012h |
| 0014h | MEM_BST_WR (D) | address low / high, count low / high (words) | write count words | memory burst write, rotation must be 0; not to be mixed with a running image load |
| 0015h | MEM_BST_END (D) | - | - | end of a burst read / write |
| 0020h | LD_IMG (D) | argument | pixel words of the full frame | load a full image |
| 0021h | LD_IMG_AREA (D) | argument, x[10:0], y[10:0], width[11:0], height[11:0] | pixel words | load an area |
| 0022h | LD_IMG_END (D) | - | - | must follow every load |
| 0034h | DPY_AREA (G) | x, y, width, height, mode | - | display an area of the image buffer with a waveform mode; does not wait for the engine |
| 0037h | DPY_BUF_AREA (G) | x, y, width, height, mode, buffer address low, high | - | display from another buffer |
| 0038h | POWER_SEQ (G) | 0 = off, 1 = on | - | panel power sequence, normally automatic |
| 0039h | VCOM (G) | 0 = get / 1 = set, value | get: read 1 word | VCOM as magnitude in mV (1530 = -1.53 V), platforms with PMIC only |
| 0040h | FORCE_SET_TEMP (G) | 0 = get / 1 = set, temperature | get: read 2 words | temperature for the waveform selection |
| 0302h | GET_DEV_INFO (G) | - | read 20 words | panel size, image buffer address, versions |

The parameters of the memory burst and load commands are only taken from the command when I80CPCR bit 0 is set
(packed mode); otherwise they have to be written to registers. Every driver sets I80CPCR = 1 at init.

GET_DEV_INFO answer: word 0 panel width, 1 panel height, 2 image buffer address [15:0], 3 address high, 4 .. 11
firmware version string (16 bytes), 12 .. 19 LUT (waveform) version string (16 bytes). The characters of the
strings are stored low byte of the word first.

## 6 Registers

| Address | Name | Function |
|---|---|---|
| 0004h | I80CPCR | bit 0 = 1: command parameters in packed mode (reset value 0) |
| 0200h | MCSR | memory converter setting, layout of the load argument |
| 0208h / 020Ah | LISAR | load image start address, low / high word |
| 1000h | LUT0EWHR | display register base: LUT0 engine width / height |
| 1040h, 1080h, 10C0h | LUT0XYR, LUT0BADDR, LUT0MFN | LUT0 position, base address, mode and frame number |
| 1114h | LUT01AF | LUT0 / 1 active flag |
| 1134h, 1138h | UP0SR, UP1SR | update parameters; UP1SR bit 18 (bit 2 of 113Ah) = 1 bit per pixel mode, bit 0 = AC VCOM |
| 113Ch, 117Ch, 1180h | LUT0ABFRV, UPBBADDR, LUT0IMXY | alpha blend / fill value, update buffer address, image offset |
| 1224h | LUTAFSR | status of all LUT engines, 0 = free |
| 1250h | BGVR | 1 bit per pixel mode: [15:8] gray level of the 0 bits, [7:0] of the 1 bits |

32 bit registers are read / written as two words (address and address + 2).

1 bit per pixel mode (fast black / white): load the bitmap as 8 bit pixels with x / 8 and width / 8 (one byte =
8 pixels), set UP1SR bit 18 and BGVR, DPY_AREA, wait for LUTAFSR = 0, clear the bit again.

## 7 Display modes

Mode numbers of the "AF" waveform (E Ink mode declaration), times at 25 C and 85 Hz:

| Mode | Name | Time | Use |
|---|---|---|---|
| 0 | INIT | 2000 ms | full clear to white, after power on or when the memory does not match the panel |
| 1 | DU | 260 ms | black / white only, no flash |
| 2 | GC16 | 450 ms | 16 gray levels, flashing, best quality |
| 3 | GL16 | 450 ms | 16 gray levels, less flash for text on white |
| 4 | GLR16 | 450 ms | as GL16, with ghost reduction |
| 5 | GLD16 | 450 ms | as GL16, with dithering of the white state |
| 6 | A2 | 120 ms | black / white only, fast animation; a white image before and a GC16 update after an A2 sequence are recommended |
| 7 | DU4 | 290 ms | 4 gray levels |

The numbers depend on the waveform file of the panel firmware. Waveshare selects by the LUT version string: A2 is
mode 4 with "M641" (6" 800 x 600 and one 6" HD firmware) and 6 otherwise; INIT is 0 and GC16 is 2 everywhere.
With the "M641" and "M841_TFAB512" firmware Waveshare aligns the display area to 32 pixels in x.

## 8 Sequences

Init (Waveshare, ITE example, pbert519; GregDMeyer without SYS_RUN):

1. Reset, wait for HRDY.
2. `SYS_RUN`.
3. `GET_DEV_INFO`, read 20 words.
4. `REG_WR I80CPCR = 0001h`.
5. VCOM: get, set if it differs from the value of the panel (printed on the panel cable).
6. Load a white image and display it with mode INIT.

Load and display an area:

1. Wait until LUTAFSR = 0 (when a display update may be running).
2. `REG_WR LISAR + 2 = address high`, `REG_WR LISAR = address low`.
3. `LD_IMG_AREA`, argument, x, y, width, height.
4. Pixel words.
5. `LD_IMG_END`.
6. `DPY_AREA`, x, y, width, height, mode.
7. Wait until LUTAFSR = 0.

Read back from the image buffer: `MEM_BST_RD_T` (address low / high, word count low / high), `MEM_BST_RD_S`, one
read packet with the words, `MEM_BST_END`.

Sleep: `SLEEP`; wake up with `SYS_RUN`.

## 9 The vic head `src/head/IT8951.h`

```cpp
vic::head::IT8951<Screen_Size_X = 800, Screen_Size_Y = 600,    // logical size
                  Orientation  = drv::orientation_0,            // all eight, done in software
                  Mode = 2,                                     // waveform mode of present(), GC16
                  VCOM = 0>                                     // mV magnitude, 0 = keep the value of the controller
IT8951(io::handle_type device);
```

- **No framebuffer.** The image stays in the controller. Pixels, lines, boxes and pixel blocks are loaded directly
  into the image buffer, the head only tracks the changed area (physical rect). RAM: a 258 byte packet buffer and
  the device info.
- io layer (SPI): every `io::write()` is one packet (one CS low period), the head sends the preamble; option 0 =
  command packet, 1 = data packet. `io::read()` option 1 reads data words: the io layer sends `10h 00h`, drops the
  dummy word and returns the big endian words in one CS low period. `io::read()` option 2 returns one byte with
  bit 0 = 1 while the controller is busy (HRDY low, the inverted pin level); the head polls it before every packet
  (every 1 ms, up to 3 s). An io layer without HRDY read returns false, the head then sends without waiting. The
  hardware reset is part of `io::init()`.
- init: reset, HRDY (or 200 ms), `0001h`, `0302h` + 20 words, `0011h 0004h 0001h`, LISAR = image buffer address
  (high word, then low word, once), VCOM get / set if `VCOM != 0`, clear to white, `DPY_AREA` of the screen with
  mode 0 (INIT). Without device info (io layer can't read) LISAR keeps its power on value.
- Loads: `0021h`, `0120h` (big endian, 4 bit per pixel, no rotation), x, y, width, height, data packets of up to
  128 words, `0022h`. Unaligned starts get `x % 4` dummy pixels per row, every row is padded to a whole word.
- Colors: `color::color_to_L4()`, 0 = black .. 15 = white, `color::none` = white paper.
- `pixel_set()` is a load of 1 x 1 (8 packets). `line_horz()`, `line_vert()` and `box()` are one load with a
  constant gray level, `blit()` is one load of the block, `cls()` loads the whole screen. Lines, boxes and blocks
  are the fast path; text and other pixel wise primitives are slow on this controller.
- `present()` sends `DPY_AREA` for the changed area with the selected mode and polls LUTAFSR (every 10 ms, up to
  5 s; 500 ms fixed, 2000 ms for INIT, if the io layer can't read). It does nothing when no load happened since the
  last refresh; batch primitives with `dc::present_lock()`.
- `pixel_get()` reads one word (two pixels) with a memory burst read at buffer + y * width + (x & ~1): the even
  pixel is taken from the low byte, the gray level from the upper nibble. `color::none` without device info or
  read support.
- Orientation in software: `to_phys()` as the other e-paper heads, the rotation bits of the load argument stay 0.
- `refresh_mode(mode)` selects the waveform of `present()`, `refresh(mode)` displays the whole screen (e.g. INIT
  or GC16 against ghosting), `device_info()` returns panel size, buffer address and the version strings.
  `shutdown()` sends SLEEP, `init()` wakes the controller up.
- `static_assert`: physical width and height <= 2047.
- Not covered: 1 bit per pixel mode, DPY_BUF_AREA, hardware rotation, the 32 pixel alignment of the 6" firmware,
  temperature and power sequence commands, standby, the I80 / M68 / I2C / USB hosts.

## 11 Open points

The head is written from the documents and the reference drivers and has not been run on a panel. To verify on
hardware:

- **Pixel read back.** No driver uses the memory burst read. The address calculation (1 byte per pixel, row
  length = panel width), the position of the even pixel in the word and the gray level nibble are derived from the
  documents.
- **LISAR once.** The head relies on the load address staying valid after init.
- **A2 mode number** (4 or 6) and the availability of the modes 3 .. 7 depend on the waveform of the panel
  firmware; check `device_info().lut`.
- **Alignment of the display area** on the 6" firmware ("M641": multiples of 32 in x in the Waveshare examples).
- **SPI mode 3**, listed in the datasheet only.
- **HRDY inside a packet.** The head waits before the packet; at 12 MHz or more the io layer may have to wait for
  HRDY after the preamble as well.
- **Version string byte order** (low byte first as in the Waveshare code; GregDMeyer decodes high byte first).
