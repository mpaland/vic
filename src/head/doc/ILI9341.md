# ILI9341 programming summary

Source: ILI Technology, *ILI9341 a-Si TFT LCD Single Chip Driver, 240RGBx320 Resolution and 262K color,
Specification*, Version V1.11 on the cover (document ILI9341_DS_V1.11.pdf), revision history up to V1.13,
2011-07-20 (`ILI9341.pdf`, 245 pages). The ILI9341 is driven by the generic head `src/head/MIPI_DCS.h`
(`MIPI_DCS_ILI9341`); the shared head description is in `MIPI_DCS.md`, this file holds everything specific to the
ILI9341. Page numbers are PDF pages (they equal the printed page numbers). The datasheet writes the two 8080 bus
variants as "8080-I" and "8080-II" (Roman numerals that are lost in the text layer): 8080-I = IM3 low, 8080-II = IM3
high. Many defaults differ between the command list (8.1) and the command descriptions; both are given where they
disagree.

## 1 Overview

| Item | Value |
|---|---|
| Panel | 240 RGB x 320, 720 source outputs S1 .. S720, 320 gate outputs G1 .. G320, VCOM output (1, 2) |

| Supplies | VDDI 1.65 .. 3.3 V (I/O), VCI 2.5 .. 3.3 V (analog), VDDI must not exceed VCI (18.2 note 2); Vcore is regulated internally (capacitor only), VDDI_LED supplies the LED control pins; DDVDH 4.5 .. 5.8 V, VGH 10 .. 18 V, VGL -5 .. -10 V, VCL -1.5 .. -2.5 V from on-chip charge pumps (2, p. 8) |
| Interfaces (IM[3:0]) | 8080-I / 8080-II parallel 8 / 9 / 16 / 18 bit, 3 line 9 bit SPI, 4 line 8 bit SPI (each as interface I with bidirectional SDA or II with SDI / SDO), RGB 6 / 16 / 18 bit (DE or SYNC mode, needs a serial IM setting for the registers), VSYNC interface |
| Colour depths | MCU interface 16 bit (65K, DBI = 101) and 18 bit (262K, DBI = 110); RGB interface 16 / 18 bit; idle mode 8 colours |

## 2 Interfaces

### 2.1 Interface selection (4, p. 10; 7.1.1, p. 26)

| IM3 IM2 IM1 IM0 | Interface | Command / parameter pins | GRAM pins |
|---|---|---|---|
| 0 0 0 0 | 8080-I 8 bit | D[7:0] | D[7:0] |
| 0 0 0 1 | 8080-I 16 bit | D[7:0] | D[15:0] |
| 0 0 1 0 | 8080-I 9 bit | D[7:0] | D[8:0] |
| 0 0 1 1 | 8080-I 18 bit | D[7:0] | D[17:0] |
| 0 1 0 1 | 3 line 9 bit SPI, interface I | SDA in / out | SDA |
| 0 1 1 0 | 4 line 8 bit SPI, interface I | SDA in / out, D/CX | SDA |
| 1 0 0 0 | 8080-II 16 bit | D[8:1] | D[17:10], D[8:1] |
| 1 0 0 1 | 8080-II 8 bit | D[17:10] | D[17:10] |
| 1 0 1 0 | 8080-II 18 bit | D[8:1] | D[17:0] |
| 1 0 1 1 | 8080-II 9 bit | D[17:10] | D[17:9] |
| 1 1 0 1 | 3 line 9 bit SPI, interface II | SDI in, SDO out | SDI |
| 1 1 1 0 | 4 line 8 bit SPI, interface II | SDI in, SDO out, D/CX | SDI |

Control pins: `CSX` (low active, may be tied low on the parallel bus), `D/CX` (0 command, 1 parameter / GRAM data; the
SCL pin in serial mode), `WRX` (write strobe; D/CX in 4 line mode), `RDX`, `RESX` (low active), `TE`, `EXTC` (high =
extended commands B0h .. CFh and E0h .. FFh accepted, low = they are discarded; most modules tie it high). Unused
data pins go to VSS. When the RGB interface is used the IM pins must select a serial interface for the registers.

### 2.2 8080 parallel bus (7.1.2 .. 7.1.7, p. 27 .. 32)

Data is latched on the rising edge of WRX and read on the rising edge of RDX; D/CX = 0 marks a command byte, D/CX = 1
parameters and GRAM data. Read data is only driven while D/CX is high (Hi-Z otherwise). Every read command returns a
dummy parameter first (04h, 09h, 0Ah .. 0Fh, 2Eh, 3Eh, 45h, 52h, 54h, 56h, 5Fh, D2h, D3h, DAh .. DCh), then the
data. CSX high between bytes is a pause (7.1.14); the transfer continues where it stopped.

### 2.3 Serial interface (7.1.8 .. 7.1.13, p. 33 .. 43)

- 3 line: 9 bit frames, D/CX bit first, then D7 .. D0, MSB first; SDA is sampled on the rising SCL edge, the host
  changes it on the falling edge. 4 line: 8 bit frames, the D/CX pin gives the byte type (the timing figures draw it
  valid at the last bit, D0; tas / tah 10 ns). A falling CSX edge starts a transfer, CSX high resets the serial state
  machine; CSX may go high between bytes (pause) without losing the position in a parameter or pixel stream.
- Reads: the ILI9341 shifts read data out on the falling SCL edge (SDA in interface I, SDO in interface II); the host
  must release SDA after the last command bit. 8 bit register reads (DAh .. DCh, 0Ah .. 0Fh) have no dummy, 24 bit
  (04h) and 32 bit (09h) reads have one dummy clock cycle. RAMRD (2Eh): 8 dummy clocks in 4 line mode, 9 dummy clocks
  in 3 line mode, then 24 bits per pixel, R5..R0 in D23..D18, G5..G0 in D15..D10, B5..B0 in D7..D2 (always 18 bit,
  independent of COLMOD; Figures p. 62, 64).
- Break: a RESX pulse in the middle of a byte discards it, the next byte is a command (wait more than 10 us after
  RESX). A CSX break in the middle of a byte discards the partial byte, the same byte must be resent. Parameters of a
  multi parameter command that were completely sent are stored; the rest keep their previous value (7.1.11).

### 2.4 Pixel data on each bus (7.6, p. 60 .. 82)

| Bus | 16 bit/pixel (DBI = 101) | 18 bit/pixel (DBI = 110) |
|---|---|---|
| 8 bit (D[7:0] or D[17:10]) | 2 transfers: R4..R0 G5..G3, then G2..G0 B4..B0 | 3 transfers, 6 bits left aligned in D7..D2: R5..R0, G5..G0, B5..B0 |
| 9 bit (D[8:0] or D[17:9]) | 2 transfers as on the 8 bit bus (D8 unused) | MDT = 00: 2 transfers of 9 bit: R5..R0 G5..G3, then G2..G0 B5..B0; MDT = 01: 3 transfers on D7..D2 as on the 8 bit bus |
| 16 bit (D[15:0] or D[17:10] + D[8:1]) | 1 transfer, R4..R0 G5..G0 B4..B0 on D15..D0 | MDT = 00: 3 transfers per 2 pixels: (R1 on D15..D10, G1 on D7..D2), (B1, R2), (G2, B2); MDT = 01: 2 transfers per pixel: (R on D15..D10, G on D7..D2), (B on D15..D10); MDT = 10: R5..R0 G5..G0 B5..B2 on D15..D0, then B1 B0 on D15 D14; MDT = 11: R5 R4 on D1 D0, then R3..R0 G5..G0 B5..B0 on D15..D0 |
| 18 bit (D[17:0]) | 1 transfer, RGB565 on D15..D0 (D17, D16 unused) | 1 transfer, R5..R0 G5..G0 B5..B0 on D17..D0 |
| 3 line SPI | 2 frames: 1 R4..R0 G5..G3, 1 G2..G0 B4..B0 | 3 frames: 1 R5..R0 x x, 1 G5..G0 x x, 1 B5..B0 x x |
| 4 line SPI | 2 bytes as on the 8 bit bus | 3 bytes as on the 8 bit bus |

MDT[1:0] is in F6h. On the 8080-II buses "D15..D0" maps to D17..D10, D8..D1. ENDIAN (F6h) = 1 sends the low byte
first, valid only for 65K colour on the 8 and 9 bit buses. Only complete pixels are stored (7.1.17).

### 2.5 RGB and VSYNC interfaces (7.2, 7.3, p. 45 .. 54)

RCM[1:0] in B0h selects DE mode (10: VSYNC, HSYNC, DOTCLK, DE, data) or SYNC mode (11: DE ignored, porches from
B5h); DPI in 3Ah and RIM in F6h select 18 bit (D[17:0]), 16 bit (D[17:13] and D[11:1], D12 and D0 to GND) or 6 bit
(D[5:0], three DOTCLKs per pixel, cycle counts must be multiples of 3). F6h RM = 1 routes the RGB data into the
GRAM, DM = 01 selects RGB clocking, B0h ByPass_MODE selects GRAM or direct path. Signals are sampled on the rising
DOTCLK edge, VSYNC / HSYNC low active, DE high active (polarities in B0h). Typical QVGA timing: HSYNC 10, HBP 20,
HFP 10 DOTCLK (minimum 2 each), VSYNC 2, VBP 2, VFP 4 lines, 6.35 MHz DOTCLK for 70 Hz; internal clock PCLKD =
DOTCLK / (2 x (PCDIV + 1)) should be close to the 615 kHz oscillator (example PCDIV = 4). The VSYNC interface (F6h
DM = 10, RM = 0) writes through the MCU bus and synchronises the frame to an external VSYNC pulse.

## 3 Frame memory and pixel formats

- Address counter: CASET (2Ah) sets the column window SC .. EC, PASET (2Bh) the page (row) window SP .. EP, both
  inclusive, SC <= EC and SP <= EP; values beyond 00EFh / 013Fh (013Fh / 00EFh with MV = 1) are ignored. RAMWR (2Ch)
  resets the pointer to (SC, SP), each complete pixel increments the column; after EC the column returns to SC and
  the page increments; after EP the pointer returns to (SC, SP) (9.3, p. 208; "data transfer method 1", 7.1.16). Any
  other command ends the stream.
- RAMWRC (3Ch) continues after the last written pixel; WEMODE (F6h) = 0 ignores pixels beyond the window size,
  WEMODE = 1 (default) wraps and keeps writing (8.2.34, which wrongly names the register "B3h"). RAMRD (2Eh) / RAMRDC
  (3Eh) read with the same pointer rules, the first returned parameter is a dummy.
- MADCTL MY / MX / MV translate the host coordinates before they reach the physical counters (section 5); the host
  always sees "column first" order. The RAMWR / RAMRD texts describe the MV = 1 case as "page register incremented
  first" in terms of the physical counters, which reads like a contradiction to 9.3; the translation table of 9.3 is
  the consistent description.
- COLMOD (3Ah) `0 DPI[2:0] 0 DBI[2:0]`: DBI 101 = 16 bit, 110 = 18 bit, the others reserved; DPI the same for the RGB
  interface. Reset 66h; RDDCOLMOD (0Ch) and the reset table quote 06h, i.e. DPI = 000 (inconsistent with 66h).
- 16 -> 18 bit expansion: 7.4 (p. 55) says the 16 bit modes go through the 128 byte LUT loaded by RGBSET (2Dh, random
  after power on); F6h EPF[1:0] defines a fixed expansion instead: 00 MSB copied to the LSB (default), 01 LSB = 0
  (except 1Fh -> 3Fh), 10 LSB = 1 (except 00h -> 00h), 11 conditional copy of G0 (p. 194). The datasheet does not say
  which mechanism wins; the reference init sequences (and the head) never load 2Dh.
- Idle mode (39h) shows 8 colours from the MSBs R5, G5, B5. The display shows column pointer 0 .. 00EFh and page
  pointer 0 .. 013Fh; vertical scrolling (33h, 37h) maps frame memory lines to the scroll area, TFA + VSA + BFA must be
  320 (smaller sums are "prohibited", 9.2.4).

## 4 Commands

All commands are bytes with D/CX = 0, parameters follow with D/CX = 1. Undefined codes act as NOP. Codes B0h .. D9h
and DEh .. FFh are reserved for the display supplier, who may leave them enabled or turn them into NOPs (8.1 note 2).
10h, 12h, 13h, 26h, 28h, 29h, 30h, 36h (ML only), 38h and 39h take effect at the next VSYNC in sleep out, immediately
in sleep in.

Frame rate (B1h .. B3h): `f = fosc / (clocks per line x division ratio x (lines + VBP + VFP))` with fosc = 615 kHz
(1 clock = 1.625 us), RTN 10000 .. 11111 = 16 .. 31 clocks (smaller values prohibited), DIV 00 .. 11 = fosc / 1, 2,
4, 8. With 320 lines and 2 + 2 porch lines: RTN 10h = 119 Hz, 11h 112, 12h 106, 13h 100, 14h 95, 15h 90, 16h 86,
17h 83, 18h 79, 19h 76, 1Ah 73, 1Bh 70 (default), 1Ch 68, 1Dh 65, 1Eh 63, 1Fh 61 Hz (p. 155; the table lists 11101
twice, the second one is 11110).

Gamma (E0h / E1h): the command list (p. 87) gives the 15 bytes as VP0[3:0], VP1[5:0], VP2[5:0], VP4[3:0],
VP6[4:0], VP13[3:0], VP20[6:0], VP36[3:0]:VP27[3:0], VP43[6:0], VP50[3:0], VP57[4:0], VP59[3:0], VP61[5:0],
VP62[5:0], VP63[3:0] (VN.. for E1h); 8.3.24 / 8.3.25 (p. 188) list the same fields in reverse order (VP63 first,
VP27 in the high nibble). The field widths are symmetric, so any 15 byte table fits both readings; the ILI9488
datasheet uses the command list order (VP0 first). 14.1 lists the 64 grey levels of the 2.2 curve (V0P 4.084 V ..
V63P 0.279 V).

## 5 Orientation

MADCTL (36h, 8.2.29, p. 127; 9.3, p. 208):

| Bit | Name | Meaning |
|---|---|---|
| D7 | MY | row address order: PASET addresses page 319 - n (vertical mirror) |
| D6 | MX | column address order: CASET addresses column 239 - n (horizontal mirror) |
| D5 | MV | row / column exchange: CASET drives the physical page counter, PASET the column counter; the window limits become 013Fh / 00EFh |
| D4 | ML | vertical refresh order (panel scan direction only) |
| D3 | BGR | 0 RGB, 1 BGR colour filter; effective immediately without rewriting the GRAM |
| D2 | MH | horizontal refresh order (panel scan direction only) |

Reset 00h; SWRESET leaves MADCTL unchanged. F6h MY_EOR / MX_EOR / MV_EOR / BGR_EOR invert the bits on top, B6h SS / GS
mirror the panel outputs (both 0 by default; the head leaves them alone). The head maps its orientations as below
(MADCTL values with the head's default BGR = 1); "GRAM" is the physical (column, page) address that a logical pixel
(x, y) ends up in.

| vic orientation | MADCTL bits | Value | Logical size | Logical (x, y) -> GRAM (column, page) |
|---|---|---|---|---|
| `orientation_0` | - | 08h | 240 x 320 | (x, y) |
| `orientation_0m` | MY | 88h | 240 x 320 | (x, 319 - y) |
| `orientation_180` | MX, MY | C8h | 240 x 320 | (239 - x, 319 - y) |
| `orientation_180m` | MX | 48h | 240 x 320 | (239 - x, y) |
| `orientation_90` | MX, MV | 68h | 320 x 240 | (239 - y, x) |
| `orientation_90m` | MX, MY, MV | E8h | 320 x 240 | (239 - y, 319 - x) |
| `orientation_270` | MY, MV | A8h | 320 x 240 | (y, 319 - x) |
| `orientation_270m` | MV | 28h | 320 x 240 | (y, x) |

`orientation_0` is the datasheet default (MADCTL 00h); the reference drivers use MX | BGR (48h) as their "rotation
0", which is `orientation_180m` here. The panel covers the whole GRAM, so no offsets are needed. Whether a module
needs BGR = 1 is a panel property the datasheet does not state; the head defaults to BGR = 1.

## 6 Power, reset and sequences

- Supplies (12, p. 214; 13.2, p. 219): VDDI and VCI in any order, rise time 100 us or more; a hardware reset is
  required after both are up unless RESX was held low during power up (case 2: RESX low for at least 10 us after both
  supplies). Power off in any order; in sleep out mode VCI and VDDI may be removed only 120 ms after RESX was
  released, in sleep in mode after 0 ms. An uncontrolled power off blanks the display within 1 s without damage.
- Reset (15.4, p. 230): RESX low tRW >= 10 us; pulses shorter than 5 us are rejected, 5 .. 10 us may start a reset.
  Reset cancel tRT 5 ms (reset in sleep in) or 120 ms (reset in sleep out, the display runs a blanking sequence);
  wait 5 ms after RESX high before any command and 120 ms before SLPOUT. The ID bytes and the VCOM setting are loaded
  from the MTP within these 5 ms.
- Recommended power on sequence (p. 219): supplies on, at least 1 ms, hardware reset, power and display settings,
  SLPOUT (11h) at least 120 ms after the reset, at least 60 ms, display on sequence: wait 80 ms (at least 2 frames =
  34 ms), DISPON (29h). Display off sequence (p. 220): DISPOFF (28h), wait 50 ms (at least 2 frames). Power off: sleep in, at least
  120 ms, supplies off.
- Sleep (p. 221): SLPIN blanks the display, drains the panel charge, stops the DC/DC converter and the oscillator
  (120 ms); SLPOUT enables the DC/DC converter, starts the oscillator and the scan (120 ms). SLPIN and SLPOUT must be
  at least 120 ms apart; 5 ms before any other command. The ILI9341 has no deep standby mode (the standby flow chart
  on p. 222 with "R10 0190h" is a leftover from an older ILI chip).
- Power levels (13.1): normal, partial, normal + idle, partial + idle, sleep in (interface and GRAM on VDDI),
  power off. Transitions between the first five are by command without visible artefacts.
- MTP programming (17, p. 234): reset, SLPOUT, wait 100 ms, check D2h (counter not 111), wait 10 ms, D0h address and
  data, D1h key 55h AAh 66h, wait 10 ms, reset.

## 8 The vic head

```cpp
// 2.2" .. 3.2" 240 x 320 module, defaults: BGR, no inversion, RGB565, no offsets
vic::head::MIPI_DCS<vic::head::MIPI_DCS_ILI9341, 240, 320> tft(handle);
vic::head::MIPI_DCS<vic::head::MIPI_DCS_ILI9341, 320, 240, vic::drv::orientation_90> tft90(handle);
```

- io layer: `io::write()` option 0 = command byte (D/CX low), 1 = parameters / pixels (D/CX high); `io::read()`
  option 1 reads three bytes per GRAM pixel after RAMRD, the io layer has to produce the dummy (8 dummy clocks on
  4 line SPI, 9 on 3 line SPI, one dummy read on the parallel bus); see `MIPI_DCS.md`.
- init: the `MIPI_DCS_init::ILI9341` table (below, from the reference drivers), then MADCTL from the orientation
  table (08h for `orientation_0`), COLMOD 55h (66h with `Color_18bit`), INVOFF (`Invert` is false for the ILI9341)
  and a clear screen. No SWRESET in the table; the head relies on the RESX reset done by the application or io
  layer.
- Drawing: window 2Ah / 2Bh / 2Ch in logical coordinates plus `Offset_X` / `Offset_Y` (0 for this chip), RGB565 big
  endian (2 bytes, 2.4) or 3 bytes 6 bit left aligned, streams of 32 pixels; the tracked write pointer follows the
  counter rules of 9.3, so consecutive pixels along x need no new window.
- `pixel_get()`: 2Eh, then R, G, B bytes masked with FCh, matching the 24 bit SPI read format (2.3).
- `display_enable()` 29h / 28h, `display_brightness()` 53h 24h (BCTRL | BL) and 51h level, `display_inverse()`
  relative to the `Invert` default, `shutdown()` 28h, 10h, 5 ms.

Discrepancies and open points found in the crosscheck:

1. EFh 03h 80h 02h is not documented; it lies in the supplier range that "may be treated as NOP" (8.1 note 2).
2. VSCRSADD (37h) is sent with one parameter, the datasheet defines two (VSP[15:8], VSP[7:0]). Harmless after a
   reset (VSP = 0, no scroll area defined), but incomplete; the entry could be dropped or written with two bytes.
3. C1h 10h and F2h 00h touch bits that the bit diagrams show as fixed (D4 = 0 in C1h, D1 = 1 in F2h); the
   datasheet itself is inconsistent here (C1h HEX default 10h).
4. EDh 81h enables DDVDH_ENH, which the datasheet restricts to designs with 8 external capacitors; the default is
   off. Module dependent, cannot be verified from the datasheet. CFh, E8h, EAh and EDh deviate from the reset values
   (vendor tuning); the meaning of CFh power control[1:0] = 00 is undocumented.
5. No reset in the ILI9341 table (ST7735 / ST7789 / ST7796 / JD9853 tables start with SWRESET). After power on the
   datasheet requires a RESX pulse (12.1) followed by 5 ms before any command and 120 ms before SLPOUT; the table
   sends SLPOUT a few bytes after the start, so these waits must come from the io layer / application. Without a
   RESX line a SWRESET (01h) with the same waits is the documented alternative for a warm start.
6. `shutdown()` waits 5 ms after SLPIN; enough for the next command, but sleep is reached after 120 ms, the supplies
   must not be cut earlier (power off sequence p. 219) and a following `init()` (SLPOUT) must not come within
   120 ms. The display off sequence also asks for 50 ms after DISPOFF.
7. `pixel_get()` reads three bytes: correct for SPI and the 8 bit bus. On the 16 / 18 bit parallel buses a pixel read
   returns bus words, the 3 byte assumption does not hold there; the read format on the parallel buses is not
   described in detail. In 3 line SPI mode the dummy is 9 clocks, not a byte.
8. `display_brightness()` uses the documented bits (53h 24h = BCTRL | BL, DD off; 51h), but it only drives the LEDPWM
   pin (frequency BEh, polarity BFh), which most modules leave unconnected.
9. Head defaults `RGB_to_BGR = true`, `Invert = false` versus the datasheet reset state MADCTL 00h, inversion off:
   BGR is a module property, inversion matches the reset state.
10. Datasheet inconsistencies a driver author should not trust: defaults of B0h, B7h, B8h, B9h, BBh, C0h, CFh, F7h
    differ between the command list and the descriptions; COLMOD 66h vs RDDCOLMOD 06h; the E0h / E1h parameter order;
    "B3h" in the 3Ch description (the WEMODE register is F6h); the E9h table titled E8h; the sleep / standby flow
    chart with "R10 0190h".
