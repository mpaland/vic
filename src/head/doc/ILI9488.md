# ILI9488 programming summary

Source: ILI Technology, *ILI9488 a-Si TFT LCD Single Chip Driver, 320(RGB) x 480 Resolution, 16.7M-color, With
Internal GRAM*, Preliminary Version V090, 2012-10-19 (document ILI9488_IDT_V090_20121019.pdf, page footers
"Version: 001"; `ILI9488.pdf`, 339 pages). The ILI9488 is driven by the generic head `src/head/MIPI_DCS.h`
(`MIPI_DCS_ILI9488`); the shared head description is in `MIPI_DCS.md`, the closely related ILI9341 is described in
`ILI9341.md`; this file holds everything specific to the ILI9488. Page numbers are PDF pages. Being a preliminary
document, several default tables are copied from the 240 x 320 ILI9341 or are missing (the extended command pages
have no default table; their reset values are taken from the command list 5.1.2); contradictions are pointed out
where they matter.

## 2 Interfaces

### 2.1 Interface selection (3.2.1, p. 20; 3.3, p. 23)

| IM2 IM1 IM0 | Interface | Command / parameter pins | GRAM pins |
|---|---|---|---|
| 0 0 0 | DBI type B 24 bit (E9h DB_EN = 1) | DB[7:0] | DB[23:0] |
| 0 0 0 | DBI type B 18 bit (DB_EN = 0, reset) | DB[7:0] | DB[17:0] |
| 0 0 1 | DBI type B 9 bit | DB[7:0] | DB[8:0] |
| 0 1 0 | DBI type B 16 bit | DB[7:0] | DB[15:0] |
| 0 1 1 | DBI type B 8 bit | DB[7:0] | DB[7:0] |
| 1 0 1 | DBI type C option 1, 3 line SPI | SDA (SDO) | SDA |
| 1 1 0 | MIPI DSI | MIPI_DATA_P / N, MIPI_CLOCK_P / N | |
| 1 1 1 | DBI type C option 3, 4 line SPI | SDA (SDO), D/CX | SDA |

Control pins: `CSX` (low active), `D/CX` (0 command, 1 parameter / GRAM data), `WRX/SCL` (write strobe, serial clock in
SPI mode), `RDX`, `RESX` (low active), `SDA` (serial data in / out), `SDO` (serial data out), `TE`, `CABC_PWM`
(backlight PWM output), `DB[23:0]`, `VSYNC`, `HSYNC`, `ENABLE`, `DOTCLK`. Unused inputs go to IOVCC or DGND, unused
outputs stay open.

### 2.2 DBI type B (8080) parallel bus (4.1, p. 39 .. 42)

Data is latched on the rising WRX edge and read on the rising RDX edge; D/CX = 0 command, 1 parameter / GRAM data.
Read data is only valid with D/CX high (Hi-Z otherwise). GRAM reads go through the read data register, so the first
read after RAMRD returns invalid data and valid pixels follow from the second read (3.2.1); register reads return a
dummy parameter first. CSX high between bytes is a pause (4.3.2).

### 2.3 DBI type C serial interface (4.2, 4.3, p. 43 .. 50)

- 3 line: 9 bit frames, D/CX bit first, then D7 .. D0, MSB first; 4 line: 8 bit frames with the D/CX pin. Data in
  is sampled on the rising SCL edge, read data is shifted out on the falling edge. A falling CSX edge starts a
  transfer, CSX high resets the serial interface; CSX may go high between bytes (pause).
- B0h SDA_EN selects the pins: SDA_EN = 0 (reset) uses DIN / SDA for input and SDO for output, SDA_EN = 1 uses the
  bidirectional SDA pin and leaves SDO unused.
- Reads: 8 bit register reads (DBh, DCh, 0Ah .. 0Fh) without dummy, 24 bit (04h) and 32 bit (09h) reads with one
  dummy clock cycle. RAMRD (2Eh): 8 dummy clocks (4 line) or 9 dummy clocks (3 line), then 24 bits D23 .. D0 per pixel
  (Figures 104, 108, p. 120, 122). The figures do not show how R, G, B are placed in the 24 bits.
- Extended (EXTC) registers can only be read over SPI through FBh: write FBh with SPI_READ_EN = 1 and SPI_CNT = the
  index of the wanted parameter, then the register command, read the value, and write FBh with SPI_READ_EN = 0 again;
  one FBh setting serves one parameter read (5.3.41, p. 277).
- Break: a CSX pulse inside a byte discards it, the byte must be resent; completely sent parameters of a multi
  parameter command are stored, the rest keep their previous value (4.2.3).

| 18 bit (IM 000, DB_EN = 0) | 18 bit (110) | 1 transfer, R5..R0 G5..G0 B5..B0 on DB17..DB0 |

| 8 bit (IM 011) | 16 bit (101) | 2 transfers: R4..R0 G5..G3, then G2..G0 B4..B0 |

| 3 line SPI | 3 bit (001) | 9 bit frames 1, x x R1 G1 B1 R2 G2 B2 (2 pixels per frame) |
| | 18 bit (110) | 3 frames: 1 R5..R0 x x, 1 G5..G0 x x, 1 B5..B0 x x |
| 4 line SPI | 3 bit (001) | bytes x x R1 G1 B1 R2 G2 B2 |

The serial interface is documented with 3 bit and 18 bit pixels only; RGB565 is merely listed for 4 line SPI, 24 bit
pixels are documented for the 24 bit parallel bus, DPI and DSI, not for SPI. For a driver this means 3Ah = 66h on SPI.
Only complete pixels are stored (4.4).

### 2.5 DPI (RGB) interface (4.5, 4.8, p. 53 .. 56, 133 .. 136)

B6h RCM selects DE mode (0: VSYNC, HSYNC, ENABLE, DOTCLK, data) or SYNC mode (1: ENABLE ignored, porches from B5h);
3Ah DPI selects 16 bit (DB[15:0], 101), 18 bit (DB[17:0], 110) or 24 bit (DB[23:0], 111). B6h RM = 1 writes the GRAM
from the RGB interface, DM = 1 clocks the display from DOTCLK (DOTCLK may then only stop in sleep in), BYPASS = 1
sends the data directly to the shift register (needs H_Low 3, HBP 3, HFP 10). Signals are sampled on the rising
DOTCLK edge, VSYNC / HSYNC low active, ENABLE high active (polarities in B0h). Timing minimums: H_Low, HBP, HFP 3
DOTCLK, V_Low 1, VBP 2, VFP 2 lines, horizontal frequency up to 33 kHz, DOTCLK up to 20 MHz; example 20 MHz, 70 Hz,
V_Low + VBP = 2, VFP = 2, H_Low + HBP = 100, HFP = 170 (p. 55).

### 2.6 MIPI DSI (4.6, 4.9, p. 57 .. 118, 137 .. 139)

One clock lane and one data lane, low power (LP), ultra low power and high speed (HS) modes, escape mode functions
LPDT, ULPS, remote application reset, TE trigger (TEE) and acknowledge, bus turnaround (BTA) for reads. Commands are
DCS short writes (0 or 1 parameter), DCS long writes and DCS reads answered with long / short read responses or an
acknowledge with error report. Command mode pixels are written with 2Ch / 3Ch in 16 or 24 bit/pixel (the second
packet of a split pixel must use 3Ch); video packets use data types 0Eh (16 bit), 1Eh (18 bit packed) and 2Eh
(18 bit loosely packed). F7h DSI_18_option selects packed or loose RGB666 for DCS writes, BEh swaps data / clock lanes
and P / N, MIPI_LDO needs a capacitor in DSI mode. RDNUMED (05h) counts DSI errors. The vic head does not use DSI.

## 3 Frame memory and pixel formats

- Address counter: CASET (2Ah) sets SC .. EC (0 .. 013Fh, 0 .. 01DFh with MV = 1), PASET (2Bh) SP .. EP (0 .. 01DFh,
  0 .. 013Fh with MV = 1), inclusive, start <= end, out of range values are ignored. RAMWR (2Ch) starts at (SC, SP),
  each pixel increments the column, after EC the column returns to SC and the page increments, after EP the pointer
  returns to (SC, SP); pixels beyond (EC - SC + 1) x (EP - SP + 1) are ignored (5.2.24, 6.3). RAMWRC (3Ch) and RAMRDC
  (3Eh) continue without resetting the pointer; any other command ends a stream; no GRAM access in sleep in.
- MADCTL MY / MX / MV translate the host coordinates (section 5). As in the ILI9341 datasheet the RAMWR / RAMRD texts
  describe the MV = 1 case in terms of the physical counters ("page register incremented first"); the translation
  table of 6.3 shows that the host still sees column first order.
- COLMOD (3Ah) `x DPI[2:0] x DBI[2:0]`: DBI 001 = 3 bit (8 colours), 101 = 16 bit, 110 = 18 bit, 111 = 24 bit; DPI
  101 / 110 / 111 = 16 / 18 / 24 bit; others reserved. Reset 06h (the 3Ah description table is shifted by one row in
  the text; RDDCOLMOD 0Ch shows the correct assignment).
- 16 -> 18 bit expansion (B7h EPF[1:0], Figure p. 232): 00 R0 / B0 = 0, 01 R0 / B0 = 1, 10 MSB copied to the LSB, 11
  G0 copied to R0 / B0 under conditions. The encoding differs from the ILI9341 (F6h EPF).
- Idle mode (39h) shows 8 colours from R5, G5, B5. Vertical scrolling (33h / 37h) needs TFA + VSA + BFA = 480; with
  scrolling active MADCTL MV should be 0 for frame memory writes (33h restriction); VSP must not point into a fixed
  area.

## 4 Commands

All commands are bytes with D/CX = 0, parameters with D/CX = 1. On the DBI interfaces read commands return a dummy
parameter first; on DSI only the data is sent ("only the 2nd parameter is sent on DSI").

## 5 Orientation

MADCTL (36h, 5.2.30, p. 191; 6.3, p. 284):

| Bit | Name | Meaning |
|---|---|---|
| D7 | MY | row address order: PASET addresses page 479 - n (vertical mirror) |
| D6 | MX | column address order: CASET addresses column 319 - n (horizontal mirror) |
| D5 | MV | row / column exchange: CASET drives the physical page counter, PASET the column counter (limits 01DFh / 013Fh) |
| D4 | ML | vertical refresh order (panel scan only) |
| D3 | BGR | 0 RGB, 1 BGR colour filter |
| D2 | MH | horizontal refresh order (panel scan only) |

Reset 00h. MADCTL bits (BGR, REV, MX, MY) can be stored in the OTP (D0h address 19h), so a programmed module may start
with another value; B6h SS / GS mirror the panel outputs in addition. The head writes 36h completely:

| vic orientation | MADCTL bits | Value (BGR = 1) | Logical size | Logical (x, y) -> GRAM (column, page) |
|---|---|---|---|---|
| `orientation_0` | - | 08h | 320 x 480 | (x, y) |
| `orientation_0m` | MY | 88h | 320 x 480 | (x, 479 - y) |
| `orientation_180` | MX, MY | C8h | 320 x 480 | (319 - x, 479 - y) |
| `orientation_180m` | MX | 48h | 320 x 480 | (319 - x, y) |
| `orientation_90` | MX, MV | 68h | 480 x 320 | (319 - y, x) |
| `orientation_90m` | MX, MY, MV | E8h | 480 x 320 | (319 - y, 479 - x) |

| `orientation_270m` | MV | 28h | 480 x 320 | (y, x) |

`orientation_0` is the datasheet default; the reference drivers' "rotation 0" with MX is `orientation_180m`. The panel
covers the whole GRAM, no offsets. BGR = 1 (head default) is a module property not stated in the datasheet.

## 6 Power, reset and sequences

- Supplies (11, p. 297): IOVCC and VCI in any order, rise time (Trise) above 10 us. A hardware reset is required after
  both supplies are up unless RESX was held low during power up (then RESX low for at least 10 us after both
  supplies). Power off in any order; when RESX goes low in sleep out mode the supplies must stay at least 120 ms
  (trPWRESX1), in sleep in mode 0 ns. An uncontrolled power off blanks the display within 1 s without damage.
- Reset (13.4, p. 305): RESX low tRW >= 10 us; pulses shorter than 5 us are rejected, 5 .. 9 us may start a reset,
  longer than 9 us reset. Reset cancel tRT 5 ms (reset in sleep in) or 120 ms (in sleep out, blanking sequence); wait
  5 ms after RESX high before any command and 120 ms before SLPOUT. IDs, VCOM and the OTP settings are loaded within
  these 5 ms.
- Sleep: SLPIN / SLPOUT need 5 ms before the next command and must be 120 ms apart. The datasheet contains no
  recommended initialisation sequence and no display on / off timing chart.
- Deep standby (16, p. 317): display off sequence, B7h DSTB = 1, wait more than 150 ms. Exit by six CSX low / high
  pulses (each phase > 100 ns) followed by more than 80 ms, or by a RESX pulse; all registers return to their defaults
  and must be set again together with the GRAM (5.3.8 claims the frame memory is kept but also asks to rewrite it).
  Deep standby current about 1 uA.
- Power levels (12.1): normal, partial, normal + idle, partial + idle, sleep in, power off; transitions between the
  first five by command without visible artefacts.
- OTP programming (14.3, p. 309): reset, wait > 120 ms, SLPOUT, wait > 120 ms, external 7 V on DDVDH, wait 10 ms, D0h
  address and data, D1h key 55h AAh 66h, wait 10 ms, remove the 7 V, SLPIN, wait > 120 ms.

## 8 The vic head

```cpp
// 3.5" 320 x 480 SPI module, defaults: BGR, no inversion, 18 bit pixels (3Ah = 66h)
vic::head::MIPI_DCS<vic::head::MIPI_DCS_ILI9488, 320, 480> tft(handle);
vic::head::MIPI_DCS<vic::head::MIPI_DCS_ILI9488, 480, 320, vic::drv::orientation_90> tft90(handle);
```

- io layer: `io::write()` option 0 = command byte (D/CX low), 1 = parameters / pixels (D/CX high); `io::read()`
  option 1 reads three bytes per GRAM pixel after RAMRD, the io layer produces the dummy (8 dummy clocks on 4 line SPI,
  9 on 3 line SPI, one invalid read on the parallel bus); see `MIPI_DCS.md`.
- init: the `MIPI_DCS_init::ILI9488` table (below), then MADCTL from the orientation table (08h for `orientation_0`),
  COLMOD 66h (`Color_18bit` defaults to true for the ILI9488; false would send 55h, for which the serial interface
  has no documented data format), INVOFF and a clear screen. No SWRESET in the table.
- Drawing: window 2Ah / 2Bh / 2Ch in logical coordinates (no offsets), 3 bytes per pixel with the colour in bits 7:2
  (R5..R0 x x, G5..G0 x x, B5..B0 x x as in 2.4), streams of 32 pixels; the tracked write pointer follows 6.3.
- `pixel_get()`: 2Eh, three bytes masked with FCh.
- `display_enable()` 29h / 28h, `display_brightness()` 53h 24h (BCTRL | BL) and 51h level, `display_inverse()`
  relative to the `Invert` default, `shutdown()` 28h, 10h, 120 ms.

Discrepancies and open points found in the crosscheck:

1. `MIPI_DCS.md` calls the source "V100"; the PDF in the repository is the preliminary V090 of 2012-10-19.
2. Serial pixel formats: the datasheet documents 3 bit and 18 bit pixels on SPI and lists RGB565 for 4 line SPI only
   in a sentence without a data format; 24 bit pixels (77h) are documented for the 24 bit parallel bus, DPI and DSI
   only. The head's mandatory 18 bit on SPI is consistent with the datasheet; the COLMOD table of `MIPI_DCS.md`
   (77h "ILI9488") and the remark "18 / 24 bit pixels on SPI" go beyond what the datasheet states for the serial
   interface.
3. B0h 00h forces SDA_EN = 0, i.e. read data on SDO. A module that only wires the bidirectional SDA line (3 or 4 line
   interface with SDA in / out) needs SDA_EN = 1 for `pixel_get()` and ID reads.
4. B0h, B4h, B6h, E9h and F7h write their reset values (redundant but harmless); only E0h, E1h, C0h, C1h, C5h and B1h
   change the chip state. C0h 17h needs VCI >= 2.75 V to keep VREG1OUT <= DDVDH - 0.5 V.
5. No reset in the table: after power on the datasheet requires a RESX pulse (11.1), then 5 ms before commands and
   120 ms before SLPOUT; these waits must come from the io layer / application (or a SWRESET with the same waits).
6. Fixed: `shutdown()` waited 5 ms after SLPIN, it now waits 120 ms, so a following `init()` (SLPOUT) is 120 ms
   apart; with RESX low in sleep out the supplies must stay 120 ms. Deep standby (B7h DSTB) is not used.
7. `pixel_get()`: the 8 / 9 dummy clocks and the 24 bit pixel are documented, the placement of R, G, B in those 24 bits
   is not; the head assumes 6 bit left aligned bytes as on the ILI9341. On the 16 / 18 / 24 bit parallel buses a
   pixel read returns bus words, the 3 byte assumption does not hold.
8. `display_brightness()` uses the documented 53h / 51h bits but drives the CABC_PWM pin (frequency CFh, polarity
   C8h), which the common modules leave unconnected.
9. Datasheet inconsistencies a driver author should not trust: CASET power on default "00EFh", PASET hardware reset
   default "01EFh" and the partial area limit "01EFh" (all copied from a 240 x 320 chip; the reset table 13.1 gives
   013Fh / 01DFh); the default columns of SLPOUT ("Sleep Out"), PTLON ("Partial Mode On") and 22h / 23h ("Display
   OFF"); B7h refers to G1 .. G320; B9h / BAh defaults 04h vs 40h; the shifted 3Ah table; BPGRAM (4.5) vs BYPASS (B6h);
   absolute maximum VCI / IOVCC equal to the operating maximum and -30 .. 70 °C vs -40 .. 85 °C.
