# ST7796 programming summary

Source: Sitronix, *ST7796S 320RGB x 480 dot 262K Color with Frame Memory Single-Chip TFT Controller/Driver*,
Datasheet Version V1.0, 2014/11 (`ST7796.pdf`, 279 pages). The ST7796S is the controller of the 3.5" / 4"
320 x 480 modules. It implements the MIPI DCS user commands ("command table 1") and is driven by the generic head
`src/head/MIPI_DCS.h` (`MIPI_DCS_ST7796`); the shared head description is in `MIPI_DCS.md`, this file holds
everything that is specific to the ST7796S. The vendor registers ("command table 2") are locked behind CSCON
(F0h). Page numbers are PDF pages (identical to the printed page numbers); section numbers are the datasheet's.

## 1 Overview

| Item | Value |
|---|---|

## 2 Interfaces

### 2.1 Interface selection (6.2, p. 42; 8.1, p. 59)

| IM2 IM1 IM0 | Interface | Data pins |
|---|---|---|
| 000 | 8080 18 bit | DB[17:0] |
| 001 | 8080 9 bit | DB[8:0] |
| 010 | 8080 16 bit | DB[15:0] |
| 011 | 8080 8 bit | DB[7:0] |
| 100 | reserved | - |
| 101 | 3 line SPI | SDA (in / out), SDO (out) |
| 110 | MIPI DSI | MIPI_CLK_P/N, MIPI_DATA_P/N |
| 111 | 4 line SPI | SDA, SDO, D/CX |

The text contradicts the tables in places: 8.2.4 (p. 67) selects the 9 bit bus with IM = 011 on DB[17:9], 8.2.5
selects the 8 bit bus with 011 as well; the two IM tables (p. 42, 59) agree on 001 / DB[8:0]. The SPI text
(p. 85, 89) mentions an ID pin and a start byte, both copied from another controller; the ST7796S has neither.
The RGB interface takes its commands over SPI ("only serial interface can be selected", 8.3.1).

Pins: `CSX` (low active, may be tied low permanently, 11.2), `RESX` (low active, "must be applied to properly
initialize the chip"), `DCX` (0 command, 1 parameter / data), `WRX/SCL` (8080 write strobe, SPI clock), `RDX`,
`SDA` (input latched on the rising SCL edge), `SDO` (output changes on the falling SCL edge), `DB[17:0]`, `TE`,
`CABC_PWM`, `CABC_ON`, `EXTC` (open in normal operation, high only for NVM programming). Unused inputs go to VDDI
or DGND, unused DB pins to GND in SPI mode.

### 2.2 8080 parallel (8.2, p. 60 .. 77)

A write is latched by the rising WRX edge with D/CX = 0 for a command and 1 for a parameter or pixel data. On a
read the driver puts the data out at the falling RDX edge, the host samples at the rising edge. Every read starts
with one dummy read (command table 1 lists "Dummy read" for all read commands; RDDCOLMOD p. 153: "one dummy
parameter when using parallel interface").

| Bus | 16 bpp (3Ah = 05h) | 18 bpp (06h) | 24 bpp (07h) |
|---|---|---|---|
| 18 bit | not accepted ("only 262k colors", 8.2.2) | 1 transfer, R5..R0 G5..G0 B5..B0 on DB17..DB0 | - |
| 16 bit | 1 transfer RGB565 on DB15..DB0 | 3 transfers per 2 pixels (note 2 of the figure says 3 transfers per pixel) | 3 transfers per 2 pixels, 8 bit per colour |
| 9 bit | - | 2 transfers, upper 9 bits first | - |
| 8 bit | 2 transfers: R4..R0 G5..G3, G2..G0 B4..B0 | 3 transfers, 6 bits left aligned per byte | 3 transfers R, G, B with 8 bit each |

Read formats (8.2.7 .. 8.2.10, p. 74 .. 77), all after the dummy read: 18 bit bus 1 transfer per pixel; 16 bit bus
3 transfers per 2 pixels with 3Ah = 06h, 1 RGB565 transfer with 05h; 9 bit bus 2 transfers; 8 bit bus 3 bytes
(6 bits left aligned) with 06h, 2 bytes RGB565 with 05h. This contradicts the RDMEMC restriction (p. 194) that
memory reads are always 18 bit.

### 2.3 Serial interface (8.4, p. 85 .. 93)

- 3 line SPI (IM = 101): `CSX`, `SCL`, `SDA`, `SDO`; 9 bit frames, the D/CX bit first, then D7 .. D0, MSB first.
- 4 line SPI (IM = 111): adds the `D/CX` pin, 8 bit frames; the timing figures sample D/CX together with bit D0.
- A falling CSX starts a transfer, CSX high resets the serial state machine. SDA is latched on the rising SCL
  edge, output data are shifted on the falling edge, so SPI mode 0 (or 3) works.
- Register reads (figures p. 86, 87, 91): 8 bit reads (DAh .. DCh, 0Ah .. 0Fh) return the data byte directly
  after the command; the 24 bit RDDID (04h) and the 32 bit RDDST (09h) insert one dummy clock cycle before the
  data. CSX has to go high after a read before the next command. A GRAM read (RAMRD) is not shown for SPI.
- Read pin: IFMODE (B0h) SPI_EN = 0 (default) uses SDA as input and SDO as output, SPI_EN = 1 makes SDA
  bidirectional and leaves SDO unused (p. 213); the read figures draw the output on SDA regardless.
- FBh (SPI read control, p. 240): SPI_REN (bit 4) "SPI read enable", SPI_CNT[3:0] "SPI read parameter number",
  default 00h; the datasheet gives no usage procedure.
- Break and pause (10.3, 10.4, p. 245, 246): CSX high before bit D0 discards the partial byte (the same byte is
  expected again); RESX discards the byte and resets the interface; parameters received before a break are kept,
  the interrupted one is rejected when a new command follows. CSX may go high after any complete byte, the transfer
  resumes where it stopped.

Pixel layouts on the serial bus (4 line shown, the 3 line frames carry the same bytes with D/CX = 1 in front):

| COLMOD | Bytes per pixel | Layout |
|---|---|---|
| 05h / 55h, 16 bit | 2 | R4..R0 G5..G3, G2..G0 B4..B0; expanded to 18 bit (EPF, B7h) |
| 06h / 66h, 18 bit | 3 | R5..R0 x x, G5..G0 x x, B5..B0 x x (6 bits left aligned) |

No 24 bit format is documented for the serial interfaces.

### 2.4 RGB and MIPI DSI (8.3, p. 78 .. 84; 8.5, p. 94 .. 130)

RGB: DE mode (VSYNC, HSYNC, DOTCLK, ENABLE, DB) or SYNC / HV mode (without ENABLE), B6h RCM = 0 / 1; 16 bit on
DB[15:0] (R DB15..DB11, G DB10..DB5, B DB4..DB0) or 18 bit on DB[17:0]; B6h RM = 1 routes GRAM writes from the RGB
port, BYPASS selects memory or direct to the shift register; polarities DEP, PKP, HSCP, VSCP in B0h. Porch limits
(p. 81): HSYNC width >= 2 clocks, HBP >= 4 (hpw + hbp max 75 as printed), HFP >= 2 (typ. 38), VSYNC width, VBP and
VFP >= 2 lines (typ. 4, 4, 8).

DSI: one clock lane and one data lane (DSI-1M), low power and high speed modes, UI 2 .. 12.5 ns (80 .. 500 Mbit/s);
the packet level protocol of 8.5.2 is not used by vic and not summarised here.

## 3 Frame memory and pixel formats

Address ranges X = 0 .. 319, Y = 0 .. 479 with MV = 0 (10.2, p. 243). CASET (2Ah) and RASET (2Bh) define the
window, RAMWR (2Ch) and RAMRD (2Eh) reset the pointer to the start column / row as transformed by MADCTL. Every
pixel increments the column; past XE the column returns to XS and the row increments; past YE both return to the
start. With MV = 1 the row counter runs first. WRMEMC (3Ch) / RDMEMC (3Eh) continue after the last pixel; with 3Ch
pixels beyond (XE - XS + 1) x (YE - YS + 1) are ignored. Any command ends a memory write or read. XS <= XE and
YS <= YE are required; values beyond the maximum (columns 013Fh with MV = 0 / 01DFh with MV = 1, rows 01DFh /
013Fh) are ignored, and the reset values of XE / YE follow MV as well. MX / MY mirror the counters, MV exchanges
them, so the window is always given in the rotated coordinate system. Column 0 is on S1 .. S3 with MX = 0, row 0 at
the top with MY = 0 (10.1.2, p. 242). Simultaneous panel refresh and interface access cause no visible artefacts.

COLMOD (3Ah, 9.2.32, p. 190): `0 D6 D5 D4 0 D2 D1 D0`.

| Field | Codes |
|---|---|
| D6:D4, RGB interface format | 101 = 16 bit, 110 = 18 bit |
| D2:D0, control (MCU) interface format | 101 = 16 bit, 110 = 18 bit, 111 = 24 bit |

Reset 06h after power on and HW reset (RDDCOLMOD p. 153), a software reset leaves COLMOD unchanged. The
interface chapters write the codes as 05h / 06h / 07h; 55h / 66h set the RGB field as well and are equally
valid. 24 bit (07h / 77h) is documented for the 8080 8 and 16 bit buses only.

16 to 18 bit expansion, EPF[1:0] in B7h (p. 222): 00 r0 = b0 = 0 (default, B7h = 06h), 01 r0 = b0 = 1, 10 the MSB
is copied to the LSB, 11 r0 = b0 = g0.

Partial mode (12h, 30h): rows PSL .. PEL are shown, the rest is non display area (B6h PT / PTG); PEL < PSL wraps
around, the direction follows ML. Vertical scrolling (33h, 37h): TFA + VSA + BFA must be 480, otherwise the
scroll mode is undefined; MV should be 0 while scrolling (affects the memory writes only); VSP is a frame memory
line and must not point into a fixed area.

### 4.3 Read ID values

| Command | Bytes after the dummy | Meaning |
|---|---|---|
| 04h RDDID | ID1, ID2, ID3 (00h each unless programmed) | module manufacturer, version, driver ID from the NVM |
| DAh / DBh / DCh | ID1 / ID2 / ID3, 00h | same bytes one at a time, NVM programmable (D0h) |
| D3h RDID4 | 00h, 77h, 96h | fixed IC device code, the reliable way to detect an ST7796S |

The command bit pattern printed for D3h (p. 233) is that of B7h, the hex value D3h is consistent with the
command list. On SPI the 8 bit reads need no dummy clock, the 24 / 32 bit reads one (section 2.3); a multi byte
read of D3h over SPI is not described (FBh may be meant for it).

## 5 Orientation

MADCTL (36h, 9.2.28, p. 183; 10.2, p. 244):

| Bit | Name | Meaning |
|---|---|---|
| D7 | MY | row address order, 1: rows bottom to top (vertical mirror) |
| D6 | MX | column address order, 1: columns right to left (horizontal mirror) |
| D5 | MV | row / column exchange, 1: CASET addresses the physical rows, RASET the physical columns |
| D4 | ML | vertical refresh order, panel scan only (partial / scroll direction), image unchanged |
| D3 | RGB | colour order, 0 RGB, 1 BGR colour filter panel |
| D2 | MH | horizontal refresh order, panel scan only |
| D1, D0 | - | 0 |

MY / MX / MV act on the MCU side address counter, all eight combinations are allowed (p. 243). Reset 00h, a
software reset leaves MADCTL unchanged. B6h GS / SS (second parameter, D6 / D5) flip the gate and source outputs
in addition; both are 0 by default and in the head's B6h write.

| vic orientation | MADCTL bits | MADCTL with BGR (head default) | Logical size |
|---|---|---|---|
| `orientation_0` | - | 08h | 320 x 480 |
| `orientation_0m` | MY | 88h | 320 x 480 |
| `orientation_180` | MX, MY | C8h | 320 x 480 |
| `orientation_180m` | MX | 48h | 320 x 480 |
| `orientation_90` | MX, MV | 68h | 480 x 320 |
| `orientation_90m` | MX, MY, MV | E8h | 480 x 320 |
| `orientation_270` | MY, MV | A8h | 480 x 320 |
| `orientation_270m` | MV | 28h | 480 x 320 |

Offsets: the panel is the full 320 x 480 GRAM, `Offset_X = Offset_Y = 0` in every orientation. The reference
drivers use MX | BGR (48h) as their rotation 0, which is `orientation_180m` in vic (see `MIPI_DCS.md`). Whether a
module needs BGR or inversion is a panel property the datasheet does not state.

## 6 Power, reset and sequences

- Power on (11.2, p. 271): VDD and VDDI in any order, no rise time limits; CSX may be at any level or grounded,
  RESX has priority over CSX. If RESX is not held stable during power on, a hardware reset is required after the
  supplies are up (note 4).
- Reset: the V1.0 datasheet has no RESX pulse width or reset complete time; the AC chapter has no reset entry.
  After power on, HW reset or SW reset the controller is in sleep in with the display off.
- SWRESET: 5 ms before the next command, 120 ms before SLPOUT when sent in sleep in mode (always the case right
  after power on), never during the sleep out sequence (p. 141).
- SLPOUT: 5 ms before the next command, 120 ms before a SLPIN; the display is blanked for 2 frames automatically
  while DC/DC and oscillator start (p. 160).
- SLPIN: 5 ms before the next command; DC/DC, oscillator and panel scan stop, the charge is drained from the panel,
  the interface and GRAM keep working (p. 159).
- DISPOFF / DISPON: no wait, GRAM unchanged.
- Deep standby (B7h DSTB = 1): logic and SRAM power off, GRAM and registers are lost; leave it with six CSX low
  pulses or a RESX pulse and initialise again (p. 222).
- Power off (11.2): VDD and VDDI in any order. In sleep out mode the supplies go down >= 120 ms after RESX falls,
  in sleep in mode 0 ms. An uncontrolled power off causes no damage, the display just goes blank (11.3).
- Power levels (11.1): normal, partial, idle, partial + idle (all sleep out), sleep in, power off; levels 1 .. 5 are
  changed by command. The list numbers the power off mode "3" instead of 6.

The datasheet has no recommended register initialisation. A sequence consistent with the rules above: supplies
on, RESX low pulse, SWRESET (optional) and 120 ms, SLPOUT, F0h C3h, F0h 96h, vendor registers, F0h 3Ch, F0h 69h,
MADCTL, COLMOD, at least 120 ms after SLPOUT if a SLPIN may follow, DISPON. Power off: DISPOFF, SLPIN, 5 ms,
supplies off.

## 8 The vic head

```cpp
// 3.5" / 4" 320 x 480 module, defaults: BGR, inversion off, RGB565, no offsets
vic::head::MIPI_DCS<vic::head::MIPI_DCS_ST7796, 320, 480> tft(handle);
// landscape
vic::head::MIPI_DCS<vic::head::MIPI_DCS_ST7796, 480, 320, vic::drv::orientation_90> tft2(handle);
```

- io layer: `io::write()` option 0 = command byte (D/CX low), 1 = parameters / pixels (D/CX high); `io::read()`
  option 1 for GRAM pixels, see `MIPI_DCS.md`. The datasheet limits SCL to 15 MHz for writes and 6.6 MHz for reads.
- Template defaults for `MIPI_DCS_ST7796`: `RGB_to_BGR = true`, `Invert = false`, `Color_18bit = false`, offsets 0.
- init: the ST7796 table below, then MADCTL from the orientation table (08h for `orientation_0`), COLMOD 55h (66h
  with `Color_18bit`), INVOFF (INVON with `Invert`) and a clear screen (153,600 pixels).
- Drawing: CASET / RASET / RAMWR in logical coordinates (MV transposes them in the controller), RGB565 big endian
  or 3 bytes with 6 bits left aligned, streamed in blocks of 32 pixels; the tracked write pointer follows the
  counter rules of 10.2.
- `pixel_get()`: one pixel window, RAMRD (2Eh), three bytes with 6 bits left aligned, the io layer handles the
  dummy; `color::none` without read support.
- `display_enable()` = 29h / 28h, `display_brightness()` = 53h 24h (BCTRL | BL) and 51h level,
  `display_inverse()` = 21h / 20h relative to `Invert`, `shutdown()` = 28h, 10h, 120 ms.
- Not covered: RGB and DSI interfaces, 24 bit pixels, partial / scroll / idle modes, TE, CABC, NVM, deep standby.

Discrepancies and open points:

1. `pixel_get()` assumes a dummy byte and three 6 bit bytes per pixel. The datasheet describes the GRAM read only
   for the 8080 bus, and there the 8 and 16 bit buses return RGB565 (2 bytes / 1 word) when COLMOD is 05h, which
   contradicts the RDMEMC note "always 18 bit"; with COLMOD 55h an 8080 io layer may therefore get 2 bytes per
   pixel. The SPI pixel read format and its dummy cycle are not documented (the serial chapter shows register
   reads only), and SCL must drop to 6.6 MHz for reads.
2. Read data come out on SDO by default (B0h SPI_EN = 0). Modules that wire only SDA need B0h SPI_EN = 1, a
   command 2 register the head never writes, so `pixel_get()` cannot work on them.
3. The 120 ms delays after C5h, E1h and F0h 69h are not required by the datasheet (about 360 ms of the init time);
   B4h and B6h only rewrite their defaults. Harmless.
4. `display_brightness()` matches the documented 53h / 51h bits, but DBV is reset in sleep in (52h restriction), so
   a level set before `shutdown()` is lost after the next `init()`; it drives CABC_PWM / CABC_ON, which most modules
   leave unconnected (backlight on a separate pin).
5. The head defaults `RGB_to_BGR = true` and INVOFF; the datasheet reset state is RGB order and inversion off, the
   BGR need is a module property not stated in the datasheet.
6. The datasheet gives no RESX pulse width or reset recovery time; the head relies on the io layer for the hardware
   reset (required by note 4 of 11.2 if RESX was not stable during power on) and on SWRESET with 120 ms.
7. Datasheet errors to keep in mind: D3h printed with the B7h bit pattern, C2h with the D0h bit pattern, the 9 bit
   bus IM code and pins, ID pin / start byte text in the SPI chapter, the 16 bit bus 18 bpp transfer count,
   B6h headed "Blanking Porch Control", VSCRDEF BFA written as "[6:0]", the power level numbering, the absolute
   maximum input range without sign.
8. Outside this file: `MIPI_DCS.md` lists 77h (24 bit) as supported by the ST7796, which the ST7796S documents for the
   8080 8 / 16 bit buses only (not for SPI), and gives "2.8 .. 3.3 V logic" for all controllers while the ST7796S
   accepts VDDI 1.65 .. 3.3 V.
