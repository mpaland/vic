# ST7066 programming summary

Source: Sitronix, *ST7066 Dot Matrix LCD Controller/Driver*, V1.0, 1999/12/09, 30 pages (`ST7066.pdf`). The
ST7066 is an HD44780 compatible character LCD controller ("pin function compatibility with HD44780, KS0066 and
SED1278", p. 1) and the controller of many 16 x 2 / 20 x 4 modules. The PDF covers the ST7066 only (not the later
ST7066U revision) and describes the 4 and 8 bit parallel bus; there is no serial interface. This is the
programming view of the datasheet: interface, RAM and ROM layout, instruction set, timing and sequences. The chip
is driven by the vic head `src/head/HD44780.h`, described in `HD44780.md` (section 7, with a short ST7066
crosscheck in section 8); section 8 here checks the head against this datasheet in detail.

## 1 Overview

| Item | Value |
|---|---|
| Drivers | 16 commons (COM1..COM16) x 40 segments (SEG1..SEG40): one line of 8 characters or two lines of 8 characters per chip; cascaded ST7065 / ST7063 segment drivers extend it to 80 characters x 1 line or 40 characters x 2 lines |
| Font | 5 x 8 dots (plus cursor line) or 5 x 10 dots |
| DDRAM | 80 x 8 bit character codes, addresses not shown on the display are general purpose RAM |
| CGROM | 9,920 bit: 208 characters of 5 x 8 dots and 32 of 5 x 10 dots; standard ROM codes 0A (Japanese) and 0B (European), customer fonts by mask ROM |
| CGRAM | 64 x 8 bit: 8 user characters of 5 x 8 dots or 4 of 5 x 10 dots |
| Duty | 1/8 (1 line 5 x 8 + cursor), 1/11 (1 line 5 x 10 + cursor), 1/16 (2 lines 5 x 8 + cursor) |
| Supplies | VCC 2.7 .. 5.5 V; LCD drive voltage VLCD = VCC - V5 = 3.0 .. 11 V, levels V1..V5 from an external resistor divider |
| Interface | 6800 style parallel bus RS, R/W, E, DB7..DB0, 8 bit or 4 bit (DL bit of function set), up to 2 MHz at VCC = 5 V |
| Oscillator | internal RC with an external resistor on OSC1/OSC2 (R = 91 kOhm at 5 V: 190 .. 350 kHz, typ. 270 kHz) or external clock 125 .. 350 kHz on OSC1 |
| Execution time | 37 us per instruction, 43 us per data write / read, 1.52 ms for clear and home (fOSC = 270 kHz) |
| Package | QFP80 or bare chip (2300 x 3000 um, 90 x 90 um pads) |

State after the internal power on reset (p. 19): display cleared, function set 8 bit / 1 line / 5 x 8, display,
cursor and blink off, entry mode increment without shift. BF stays 1 for 10 ms after VCC reaches 4.5 V.

## 2 MPU interface

Pins (p. 5, pad configuration p. 27):

| Pin | Type | Function |
|---|---|---|
| RS | input, pull-up | 0 = instruction register (write) / busy flag and address counter (read), 1 = data register |
| R/W | input, pull-up | 0 = write, 1 = read |
| E | input, no pull-up | enable, starts the read / write cycle |
| DB7..DB4 | I/O, pull-up | upper data nibble, the only data lines of the 4 bit bus; DB7 is the busy flag on a status read |
| DB3..DB0 | I/O, pull-up | lower data nibble, not used in 4 bit mode |
| CL1, CL2, M, D | output | extension driver interface: latch clock, shift clock, AC inversion signal, serial pattern data |
| OSC1, OSC2 | | resistor between OSC1 and OSC2 (91 kOhm at VCC = 5 V, 75 kOhm is also printed without its condition), or external clock into OSC1 |
| V1..V5 | supply | LCD drive levels, VCC >= V1 >= V2 >= V3 >= V4 >= V5 must be kept |

The pull-ups are PMOS devices with IPUP = 10 .. 120 uA (typ. 50 uA) at 5 V; DB3..DB0 can stay open in 4 bit
mode.

| RS | R/W | Operation (Table 1) |
|---|---|---|
| 0 | 0 | Write an instruction code into the IR |
| 0 | 1 | Read the busy flag (DB7) and the address counter (DB6..DB0) |
| 1 | 0 | Write data into the DR, transferred to DDRAM or CGRAM |
| 1 | 1 | Read data from the DR, loaded from DDRAM or CGRAM |

- 8 bit bus: one E cycle per byte on DB7..DB0.
- 4 bit bus (DL = 0): DB7..DB4 only, two transfers per byte, high order nibble first. Check the busy flag only
  after both nibbles of an instruction have been transferred; the BF / AC read itself is two more transfers
  (BF AC6..AC4, then AC3..AC0) (p. 22).
- Busy flag: BF = 1 while an internal operation runs; no instruction is accepted until BF = 0. The BF / AC read
  takes 0 us. Without polling, the host has to wait the execution time of the previous instruction (note p. 14).
- Address counter: holds the DDRAM or CGRAM address of the last address instruction and moves by +1 / -1 after
  every data write or read (entry mode I/D). The datasheet gives no delay between BF = 0 and the AC update (tADD
  on the HD44780).
- Data read (p. 18): the DR is filled from the RAM by an address set instruction (for the DDRAM also by a cursor
  shift). Without a preceding address set the first read returns invalid data, the following reads are correct.
  After a data write the AC already points to the next address, a read without a new address set returns stale
  data. After a CGRAM read the display shift may not work correctly.

Bus timing (p. 23 / 25), TA = 25 C, VCC = 5 V. The datasheet has no AC table for lower supply voltages; for
2.7 .. 4.5 V the slower HD44780 values (`HD44780.md` section 2) are a conservative choice.

| Parameter | Symbol | Write | Read |
|---|---|---|---|
| E cycle time | TC | >= 400 ns | >= 400 ns |
| E pulse width (high) | TPW | >= 150 ns | >= 150 ns |
| E rise / fall time | TR, TF | <= 25 ns | <= 25 ns |
| RS, R/W setup before E rises | TAS | >= 30 ns | >= 30 ns |
| RS, R/W hold after E falls | TAH | >= 10 ns | >= 10 ns |
| Data setup before E falls | TDSW | >= 40 ns | - |
| Data output delay after E rises | TDDR | - | <= 100 ns (the table calls it "data setup time") |
| Data hold after E falls | TH | >= 10 ns | >= 10 ns |

Write data is latched on the falling edge of E. Extension driver interface (CL1, CL2, D, M to the ST7065): clock
high and low width >= 800 ns, clock setup >= 500 ns, data setup >= 300 ns, data hold >= 300 ns, M delay
-1000 .. 1000 ns.

## 3 RAM and ROM

### 3.1 DDRAM

The 7 bit DDRAM address (AC6..AC0) is set with `80h | address`:

| Mode (function set N) | Line | DDRAM addresses |
|---|---|---|
| 1 line (N = 0) | 1 | 00h .. 4Fh, display positions 1 .. 80 |
| 2 lines (N = 1) | 1 | 00h .. 27h, positions 1 .. 40 |
| 2 lines (N = 1) | 2 | 40h .. 67h, positions 1 .. 40 |

The end of line 1 (27h) and the start of line 2 (40h) are not consecutive; the cursor moves to line 2 after the
40th digit of line 1. A single ST7066 shows positions 1 .. 8 (00h .. 07h, and 40h .. 47h on line 2, Figures 3 and
5), a 16 x 2 display adds one 40 output extension driver for positions 9 .. 16 (08h .. 0Fh / 48h .. 4Fh, Figure 6).

A display shift moves the visible window over the DDRAM; both lines move together, each within its own 40 bytes
(line 2 never moves into line 1), and the AC is not changed. Example 8 x 2 (Figure 5):

| State | Line 1, positions 1 .. 8 | Line 2, positions 1 .. 8 |
|---|---|---|
| no shift | 00h .. 07h | 40h .. 47h |
| one shift left | 01h .. 08h | 41h .. 48h |
| one shift right | 27h, 00h .. 06h | 67h, 40h .. 46h |

In 1 line mode the window wraps at 4Fh (shift right shows 4Fh, 00h .. 06h, Figure 3). 4 line modules are not
described in the datasheet; they are 2 line configurations whose lines 3 and 4 continue lines 1 and 2 in the
DDRAM (see `HD44780.md` section 3).

### 3.2 CGROM

Codes 00h .. 0Fh show the CGRAM characters (3.3). The two standard ROMs (Table 4, p. 11 / 12, read from the font
images; check the table of the actual module):

| Codes | ROM code 0A (Japanese) | ROM code 0B (European) |
|---|---|---|
| 10h .. 1Fh | empty | symbols: ±, ≡, multi row bracket and integral pieces, ... |
| 20h .. 7Fh | ASCII, except 5Ch = yen sign, 7Eh = right arrow, 7Fh = left arrow | ASCII (5Ch backslash, 7Eh tilde), 7Fh house symbol |
| 80h .. 9Fh | empty | accented Latin letters in IBM code page 437 order: 80h Ç, 81h ü, 82h é, 83h â, 84h ä ... 8Eh Ä, 8Fh Å, 90h É, 91h æ ... 99h Ö, 9Ah Ü, 9Bh ñ, 9Ch Ñ |
| A0h .. AFh | A0h empty, A1h .. AFh Katakana punctuation and small kana | á í ó ú, ¢ £ ¥, ¡, Ã ã Õ õ Ø ø |
| B0h .. DFh | half width Katakana ー, ア .. ン and the voiced marks (the small circle at DFh serves as degree sign) | diacritics, ½ ¼ × ÷ ≤ ≥ « » ≠ √, arrows, box corners, ® ©, ™ † § ¶, Greek capitals |
| E0h .. FFh | Greek and math symbols, ä (E1h), ß (E2h), ö (EFh), ü (F5h), ÷ (FDh), letters with descenders in 5 x 10 | Greek small letters, triangles and other symbols |

ROM 0A has the layout of the HD44780 ROM A00; A1h .. DFh follow the Unicode half width Katakana order U+FF61 ..
U+FF9F. ROM 0B is not the HD44780 A02 (ISO 8859-1) layout.

### 3.3 CGRAM

| Bits | Meaning (Table 5, p. 13) |
|---|---|
| character code bits 2 .. 0 | CGRAM address bits 5 .. 3, character 0 .. 7; code bits 7 .. 4 = 0, bit 3 is ignored (00h and 08h show the same character) |
| CGRAM address bits 2 .. 0 | pattern row 0 (top) .. 7 |
| CGRAM data bits 4 .. 0 | dots of the row, bit 4 is the left dot, 1 = on; bits 7 .. 5 are not displayed |

Row 7 is the cursor line and is ORed with the cursor: keep it 0, set dots are lit regardless of the cursor. For
the 5 x 10 font the datasheet only states "4 character fonts", the address layout is not shown (the HD44780
layout is in `HD44780.md` section 4). To define a character write `40h | (code << 3)`, then 8 data bytes (the AC
increments per entry mode); set a DDRAM address afterwards to continue with text. Unused CGRAM is general RAM.

## 4 Instruction set

Execution times are the datasheet values at fOSC = 270 kHz (instruction table p. 14). The datasheet gives no
times for other frequencies; the internal operations run on the oscillator clock (3.7 us per clock at 270 kHz,
p. 26), so they scale with 270 kHz / fOSC: at the minimum 190 kHz clear takes 2.16 ms and a data write 61 us.

| Instruction | RS R/W | DB7 .. DB0 | Hex | Time | Function |
|---|---|---|---|---|---|
| Clear display | 0 0 | `0000 0001` | 01h | 1.52 ms | write 20h to all DDRAM, AC = 00h (DDRAM), cursor home, shift undone, I/D = 1 |
| Return home | 0 0 | `0000 001x` | 02h | 1.52 ms | AC = 00h, display shift undone, DDRAM unchanged |
| Entry mode set | 0 0 | `0000 01 I/D S` | 04h .. 07h | 37 us | I/D = 1: AC +1, cursor right; 0: AC -1 (CGRAM likewise); S = 1: shift the display on DDRAM writes |
| Display on/off | 0 0 | `0000 1 D C B` | 08h .. 0Fh | 37 us | D = 1 display on (DDRAM kept when off), C = 1 cursor, B = 1 blink the character at the cursor |
| Cursor / display shift | 0 0 | `0001 S/C R/L x x` | 10h .. 1Fh | 37 us | move the cursor or shift the display without touching the DDRAM |
| Function set | 0 0 | `001 DL N F x x` | 20h .. 3Fh | 37 us | DL = 1 8 bit / 0 4 bit bus, N = 1 2 lines, F = 1 5 x 10 font |
| Set CGRAM address | 0 0 | `01 AC5 .. AC0` | 40h .. 7Fh | 37 us | AC = CGRAM address, data accesses go to the CGRAM |
| Set DDRAM address | 0 0 | `1 AC6 .. AC0` | 80h .. FFh | 37 us | AC = DDRAM address, data accesses go to the DDRAM |
| Read BF and address | 0 1 | `BF AC6 .. AC0` | - | 0 us | busy flag and address counter |
| Write data | 1 0 | `D7 .. D0` | - | 43 us | write to DDRAM / CGRAM (selected by the last address instruction), AC +/- 1 |
| Read data | 1 1 | `D7 .. D0` | - | 43 us | read from DDRAM / CGRAM, AC +/- 1 |

Entry mode, S = 1: with I/D = 1 the display shifts left, with I/D = 0 right, on every DDRAM write; DDRAM reads and
CGRAM accesses never shift (p. 15).

| S/C | R/L | Cursor / display shift (p. 16) | AC |
|---|---|---|---|
| 0 | 0 | cursor left | AC - 1 |
| 0 | 1 | cursor right | AC + 1 |
| 1 | 0 | display left, the cursor follows the display | unchanged |
| 1 | 1 | display right, the cursor follows the display | unchanged |

| N | F | Lines | Font | Duty |
|---|---|---|---|---|
| 0 | 0 | 1 | 5 x 8 | 1/8 |
| 0 | 1 | 1 | 5 x 10 | 1/11 |
| 1 | x | 2 | 5 x 8 | 1/16 |

Datasheet inconsistencies: the instruction table and the connection examples (p. 28) call the F = 1 font
"5x11", the function set description "5 x 10" (5 x 10 dots plus the cursor line = 11 rows at 1/11 duty). The
function set description starts with the text of display on/off (p. 16), and the write data description is
headed "Read Busy Flag and Address" (p. 18); there is no separate BF read description.

## 5 Orientation

There is no orientation control: the ST7066 is a character controller, the segment and common order is fixed by
the module wiring (only the ST7065 extension drivers have shift direction pins SHL1 / SHL2, tied in the
application circuit p. 30). No mirror, rotation or start line instruction exists. The head constructs the driver
with `orientation_0` only and maps the logical character position (column, line) to a DDRAM address.

## 6 Reset, initialisation and LCD power

### 6.1 Internal reset

The power on reset executes clear, function set (DL = 1, N = 0, F = 0), display off (D = C = B = 0) and entry
mode (I/D = 1, S = 0); BF = 1 for 10 ms after VCC rises to 4.5 V. It only works if the "Power Supply Conditions
Using Internal Reset Circuit" are met (supply rise time); that table is referenced on p. 19 but not contained in
this datasheet, so initialisation by instruction is the safe choice.

### 6.2 Initialisation by instruction (p. 20 / 21)

| Step | 8 bit bus | 4 bit bus (DB7..DB4) | Wait after |
|---|---|---|---|
| Power on | | | > 15 ms after VCC > 4.5 V |
| 1 | 30h (`0011 xxxx`) | 3h (one transfer) | > 4.1 ms, BF can't be checked |
| 2 | 30h | 3h (one transfer) | > 100 us, BF can't be checked |
| 3 | 30h | 3h (one transfer) | none given, BF can't be checked |
| 4 | - | 2h (one transfer, selects 4 bit; figure: 3h) | |
| 5 | function set `0011 N F x x` | 2h, `N F x x` (figure: 3h, `0 0 N F`) | BF can be checked from here on |
| 6 | display off 08h (figure: 38h) | 0h, 8h | |
| 7 | clear 01h | 0h, 1h | 1.52 ms |
| 8 | entry mode `0000 01 I/D S` | 0h, `01 I/D S` | |

Both figures contain misprints. The 8 bit figure shows display off as `0011 1000` (38h, a function set) instead
of 08h. The 4 bit figure repeats the 8 bit flow: a fourth single nibble 3h instead of 2h, then the function set as
3h and `0 0 N F` instead of 2h and `N F x x`. Taken literally the controller would stay in 8 bit mode. The
correct sequence is the HD44780 one in the table above: 3h, 3h, 3h, 2h, then every byte as two nibbles. The
datasheet gives no power on wait for supplies below 4.5 V (the HD44780 asks for > 40 ms after 2.7 V).

### 6.3 LCD drive voltages

The drive levels are supplied externally on V1..V5 (p. 22):

| Level | 1/8, 1/11 duty: 1/4 bias | 1/16 duty: 1/5 bias |
|---|---|---|
| V1 | VCC - 1/4 VLCD | VCC - 1/5 VLCD |
| V2 | VCC - 1/2 VLCD | VCC - 2/5 VLCD |
| V3 | VCC - 1/2 VLCD | VCC - 3/5 VLCD |
| V4 | VCC - 3/4 VLCD | VCC - 4/5 VLCD |
| V5 | VCC - VLCD | VCC - VLCD |

The divider is a chain of equal resistors R from VCC to V5 (4 resistors with V2 and V3 connected for 1/4 bias, 5
for 1/5 bias) and a variable resistor VR from V5 to GND or a negative supply (-5 V in the figure) that sets VLCD,
i.e. the contrast. The application circuit (p. 30) uses R = 2.2 .. 10 kOhm and VR = 10 .. 30 kOhm.

Frame timing at fOSC = 270 kHz (p. 26): 1/8 duty 400 clocks per common, frame 3.7 us x 400 x 8 = 11.85 ms
(84 Hz); 1/11 duty 3.7 us x 400 x 11 = 16.3 ms (61 Hz); 1/16 duty 200 clocks per common, 3.7 us x 200 x 16 =
11.85 ms (84 Hz). Unused commons carry the non-selection waveform: COM9..COM16 at 1/8 duty, COM12..COM16 at 1/11.

Connection examples (p. 28 / 29): 8 x 1 with 5 x 8 dots (1/4 bias, 1/8 duty), 8 x 1 with 5 x 11 dots (1/4 bias,
1/11 duty), 8 x 2 with 5 x 8 dots (1/5 bias, 1/16 duty), 16 x 1 with 5 x 8 dots (1/5 bias, 1/16 duty: the 16 x 1
panel is driven in 2 line mode, N = 1).

### 6.4 Segment extension

The ST7066 shifts the pattern data serially on D with CL2 and latches it with CL1 into cascaded ST7065 (or ST7063)
drivers of 40 outputs each; M switches the drive waveform polarity. In the application circuit (p. 30) DR2 of one
ST7065 feeds DL1 of the next, all share the drive levels, CL1, CL2 and M with the ST7066. With extension drivers the
DDRAM limit applies: 80 characters in 1 line or 40 per line in 2 lines.

## 8 The vic head `src/head/HD44780.h`

The head is documented in `HD44780.md` section 7:

```cpp
vic::head::HD44780<Columns = 16, Lines = 2,            // 1, 2 or 4 lines, max 40 columns, max 80 characters
                   Bus  = HD44780_BUS8,                // HD44780_BUS8, HD44780_BUS4
                   Wait = HD44780_WAIT_DELAY,          // HD44780_WAIT_DELAY, HD44780_WAIT_BUSY, HD44780_WAIT_IO
                   Rom  = HD44780_ROM_A00,             // HD44780_ROM_A00, HD44780_ROM_A02
                   Font_5x10 = false,                  // 1 line only
                   Exec_Us = 43>                       // execution time per byte in us: HD44780 37, ST7066 43
HD44780(io::handle_type device);
```

In short: every byte is one `io::write()` (option 0 instruction, 1 data, 2 single high nibble of the 4 bit init;
bits 8..23 carry `Exec_Us` for a `WAIT_IO` io layer). init waits 50 ms, sends 30h (5 ms), 30h (1 ms), 30h (1 ms),
on the 4 bit bus 2h (1 ms), then function set, 08h, 01h, 06h, 0Ch. Waiting is a 1 ms delay per byte (2 ms after
clear / home), a busy flag poll, or the io layer. Text goes to the DDRAM at `00h / 40h + column` (lines 3 / 4 at
`+ Columns`), user characters with `char_define()` into the CGRAM.

Crosscheck against this datasheet:

| Item | ST7066 datasheet | Head | Result |
|---|---|---|---|
| Instruction codes and bits | section 4 | same codes and bit positions | ok |
| Data write / read time | 43 us at 270 kHz | `Exec_Us` default 43, 1 ms delay, or BF poll | ok at nominal fOSC |
| Clear / home | 1.52 ms at 270 kHz | 2 ms delay (`WAIT_DELAY`, `WAIT_IO`) | ok for fOSC >= 205 kHz, see 2. |
| Power on wait | > 15 ms after VCC > 4.5 V | 50 ms | ok |
| 8 bit init | 30h, > 4.1 ms, 30h, > 100 us, 30h, function set, display off, clear, entry mode | 30h, 5 ms, 30h, 1 ms, 30h, 1 ms, function set, 08h, 01h, 06h, then 0Ch | ok (figure misprints 08h as 38h) |
| 4 bit init | figure misprinted (3h x 4, 3h + `00NF`) | 3h, 3h, 3h, 2h, then two nibbles | head is correct, see 3. |
| Busy flag | DB7, 0 us, two nibbles on the 4 bit bus | `WAIT_BUSY` reads option 0, io layer assembles the nibbles | ok |
| DDRAM map | 00h..4Fh / 00h..27h + 40h..67h | `ddram_address()`, `Columns <= 40`, `Lines x Columns <= 80` | ok, 4 line mapping not in the datasheet |
| Function set N / F | N = 1 forces 5 x 8 | `Font_5x10` only with 1 line | ok |
| CGRAM 5 x 8 | Table 5, codes 00h..07h, row 7 cursor line | `char_define()` writes `40h + (index << 3)` and 8 rows | ok, 5 x 10 not supported (layout not in the datasheet either) |
| ROM 0A | A00 layout | `HD44780_ROM_A00` mapping (¥ 5Ch, → 7Eh, ← 7Fh, Katakana A1h..DFh, ä E1h, ß E2h, ° DFh, ö EFh, ü F5h, ÷ FDh, · A5h) | ok, codes checked in Table 4 |
| ROM 0B | code page 437 like, section 3.2 | `HD44780_ROM_0B`: UNICODE table of the codes 80h..FFh | ok (fixed, see 1.) |
| Bus timing | 5 V values only | io layer | - |

Discrepancies found:

1. Fixed: ROM code 0B is not the HD44780 A02 (ISO 8859-1) font. The head comment ("ROM code 0B the European font
   (HD44780_ROM_A02)") and the ROM row of `HD44780.md` section 8 equated them, but with ROM 0B every character
   above 7Fh came out wrong: e.g. ä (U+00E4) was sent as E4h, which is a Greek letter on 0B, ä is 84h there. The
   0B symbols at 10h..1Fh are unreachable as well (the head drops 08h..1Fh as control characters). The head now has
   `HD44780_ROM_0B` with the table of 80h..FFh (glyphs without a UNICODE equivalent stay unused, the 10h..1Fh
   symbols are still unreachable). ASCII 20h..7Eh is correct on both ROMs.
2. Clear / home: the fixed 2 ms delay covers 1.52 ms only down to fOSC = 205 kHz; the datasheet allows fOSC =
   190 kHz with R = 91 kOhm, where clear / home take 2.16 ms. Same for `Exec_Us = 43` with `WAIT_IO`, which is the
   270 kHz value (61 us at 190 kHz); the parameter comment already says to scale it. `WAIT_BUSY` and the 1 ms
   per byte delay are safe in all cases.
3. The head's 4 bit init (3h, 3h, 3h, 2h) is correct, but it is not what the ST7066 figure on p. 21 shows; the
   `HD44780.md` section 8 row "Init by instruction, 4 bit: identical" holds for the intended flow, not for the
   printed figure, which is a misprint (section 6.2). The 8 bit figure misprints display off as 38h.
4. Comment only: the head's 50 ms power on wait is annotated "> 40 ms after VCC rises to 2.7 V", the HD44780
   value; the ST7066 datasheet only specifies > 15 ms after 4.5 V.
